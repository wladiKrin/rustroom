# M5.1c — Parametric curve: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** Lightroom's parametric curve (4 region amounts, 3 splits) as its own edit, folded into
`ToneCurveStage`'s composite table, with a Parametric mode in the curve panel and an on-curve drag
behind a Settings binding. Spec: `docs/superpowers/specs/2026-09-26-m5.1c-parametric-curve-design.md`.

**Gate:** fmt · `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings` · `cargo test --workspace`.

### Task 1 — `edit-model`: `ParametricCurve`
- [ ] Test: defaults (amounts 0, splits 0.25/0.5/0.75), `is_active` only on amounts, an old sidecar
  without the field loads neutral, round-trip through JSON.
- [ ] `ParametricCurve` + `Edits.tone_curve_parametric`; its group in `EditGroups` (Tone Curve),
  `merge_from`'s destructure, the three exhaustive fixtures (the compiler lists them).

### Task 2 — `pipeline::parametric::eval`
- [ ] Tests: zero is the identity exactly; each amount moves its own region most and the far
  regions by < 1%; monotone for all ±100 combinations; a split move shifts the peak; output in
  [0, 1].
- [ ] Raised-cosine bumps in display space, `MAX_LIFT = 0.15`, clamped. The table is made monotone
  in the stage (task 3).

### Task 3 — `ToneCurveStage` from the edits (one constructor, one predicate)
- [ ] Tests: `ToneCurveStage::from_edits` on an inactive parametric curve equals today's
  `new(points).with_channels(..)` bit for bit; an active one changes the composite table only; the
  table is monotone. `pipeline::tone_curve_active(&Edits)` is true for any of the five.
- [ ] Composite table = `spline(points)(srgb_to_linear(eval(p, linear_to_srgb(x))))`, then a
  running max. Both call sites (`build_pipeline_split_*` and `accelerate`'s `REPLACEABLE`) go
  through `from_edits` / `GpuToneCurveStage::from_edits`, and the insertion condition through
  `tone_curve_active`, so a sixth curve field cannot be missed at one of them.
- [ ] Golden `parametric_curve` (shadows +40, highlights −40), generated alone; the 78 others must
  regenerate byte-identically. The GPU whole-chain parity test's fixture gains a parametric curve.

### Task 4 — `tone_curve_tool`: the pure widget rules
- [ ] `combined_points(points, param, n)` (sampled through the real stage), `region_at(splits, u)`,
  `drag_split(splits, i, u)` (no crossing, min gap 0.05, within [0.05, 0.95]),
  `drag_amount(amount, dy_px, height_px)` (full height = 200 units, clamped to ±100). Tests for each.

### Task 5 — `settings::ParametricDrag { Left, Off }`
- [ ] The `EraseDrag` shape (ALL, label, serde default), round-trip test, and a dropdown in the
  Settings dialog beside the other drag bindings.

### Task 6 — The panel (bin, `develop/panel/tone_curve.rs`)
- [ ] `CurveChannel::Parametric` first in the selector. Parametric view: the combined curve, shaded
  regions, split handles on the bottom strip, four sliders; the on-curve drag when the binding is
  `Left`. The point modes' ghost is the combined curve.
- [ ] App test: a vertical drag in the Parametric widget changes the region under the pointer, and
  nothing with `Off`.

### Task 7 — Docs, GUI
- [ ] Journal, CLAUDE.md State/Next, the Obsidian plan's M5.1c marker (✅ once used) and its amended
  "done when". Launch the GUI.
