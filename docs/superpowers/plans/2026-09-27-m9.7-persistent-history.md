# M9.7 — Persistent history: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans.

**Goal:** a photo's undo/redo steps survive a restart, stored in the catalog. Spec:
`docs/superpowers/specs/2026-09-27-m9.7-persistent-history-design.md`.

**Gate:** fmt · `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings` · `cargo test --workspace`.

### Task 1 — Catalog
- [ ] Migration 9 `photo_history`; `save_history(path, copy, body)`, `load_history(path, copy)`,
  `delete_history(path, copy)`. Tests: round-trip, overwrite, delete, copies separate, a folder
  forgotten takes its rows, a path with no folder row is a quiet no-op.

### Task 2 — `History` parts and `history_store`
- [ ] `History::into_parts`/`from_parts`; `history_store::{encode, decode, CAP}`. Tests: round
  trip; the cap keeps the newest steps and the current; garbage decodes to `None`.

### Task 3 — `ActionLog::seed`
- [ ] `seed(id, undo, redo)` inserts at the front. Tests: seeded steps are reached only after this
  session's; redo reaches the seeded redo steps; a new edit clears the seeded redo.

### Task 4 — The app
- [ ] Persist on stash (`finalize_session`) and in `on_exit`; restore on a stash miss through
  `take_matching`'s rule, then seed. Test: the whole cycle across two app instances on one catalog;
  a sidecar changed between them discards the history.

### Task 5 — Measure, docs, GUI
- [ ] Encoded size for DSCF7218 at 100 steps; journal (with the decision), CLAUDE.md, Obsidian.
