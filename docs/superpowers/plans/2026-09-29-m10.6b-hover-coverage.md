> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.
> **Commits carry no `Co-Authored-By` trailer. Never push.**

**Goal:** every clickable control carries one hover sentence, exposed as its AccessKit description and
checked by a walk over every surface a harness can draw.

**Spec:** `docs/superpowers/specs/2026-09-29-m10.6b-hover-coverage-design.md`.

**Gate:** fmt · `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`
· `cargo test --workspace` (filter by name, never `-p`).

## Task 1: `test_ui::nodes`

`crates/app/src/test_ui.rs` — one frame of `body`, every AccessKit node as a plain struct:

```rust
/// One AccessKit node, as the coverage walk reads it.
#[derive(Debug, Clone)]
pub struct Node {
    pub label: String,
    pub role: egui::accesskit::Role,
    pub description: Option<String>,
    /// Offers a click — a control rather than a label.
    pub clickable: bool,
    /// Carries an open/closed state — a section header.
    pub expandable: bool,
}

/// Every node one frame of `body` produces.
pub fn nodes(ctx: &egui::Context, body: impl FnMut(&mut egui::Ui)) -> Vec<Node> { /* run_ui on
screen(); read platform_output.accesskit_update's nodes: label (or value), role(), description(),
supports_action(Action::Click), is_expanded().is_some() */ }
```

## Task 2: the helper, the exemptions

- `theme.rs`: the `Hover` trait for `egui::Response` — `hover(self, sentence: impl AsRef<str>)`,
  `hover_titled(self, title: &str, sentence: &str)` — and `pub fn describe(r: &egui::Response,
  sentence: &str)`, all setting the description through
  `r.ctx.accesskit_node_builder(r.id, |n| n.set_description(..))`. Plus
  `#[cfg(test)] pub(crate) fn sentence_fault(t: &str) -> Option<&'static str>` — the sweep's rule
  (over 110 characters, a second sentence, a newline, a semicolon clause, a trailing full stop, ⚠, the
  reset phrase), which `every_hover_is_one_short_sentence` then calls.
- `develop/panel/section.rs`: both `CollapsingHeader` widget-info sites also
  `set_expanded(open)` on their node.
- `menu_bar.rs`: each `menu_button`'s response node `set_role(Role::MenuItem)`.
- Tests: a `hover` sets the description (read through `test_ui::nodes`) and shows a tooltip; a header
  node is expandable. Commit.

## Task 3: route every hover through it

- Replace `.on_hover_text(` with `.hover(` in every non-test bin source; `use crate::theme::Hover` where
  needed. The slider row's elided case → `hover_titled(label, h)`; its rail → `theme::describe`.
- Guard test in `theme.rs`: `no_bare_on_hover_text_outside_theme` (non-test code, a positive control
  first: the sweep must find `theme.rs`'s own call). The literal sweep's pattern list gains `.hover(`.
- Build; the existing suite passes. Commit.

## Task 4: the walk

`crates/app/src/hover_coverage.rs`, `#[cfg(test)] mod hover_coverage;` in `main.rs`. One test,
`every_clickable_control_says_what_it_does`, over the surface states the spec lists, each a closure
built on the existing fixtures (`test_app::for_test`, `open_test_photo`, `library_of`, the rail's Immich
settings, `panel::show` per `Tool`, `modals::{settings, export, info}`, `shell` top bar, `status_bar`,
`menu_bar::show`). Collect `(surface, label, fault)`; assert the sample (> 150 clickable nodes) first,
then that the list is empty, printing it whole. Run → the list is the fix pass's worklist.

## Task 5: the fix pass

Write each missing sentence in the house style (verb first, one sentence, no full stop, what it does
here), and fix each fault — the mask row's Disable hover among them. Re-run until green. Commit.
