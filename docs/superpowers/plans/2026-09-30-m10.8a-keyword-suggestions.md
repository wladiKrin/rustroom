# M10.8a — keyword suggestions, type-to-tag, undoable tagging: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.
> **Commits carry no `Co-Authored-By` trailer. Never push.**

**Goal:** suggested keywords (same capture day + companions) in the rail and the right-click menu, a
type-to-tag field with autocomplete, and every tagging route an undo step.

**Spec:** `docs/superpowers/specs/2026-09-30-m10.8a-keyword-suggestions-design.md`.

**Architecture:** the catalog answers two counting queries and reports what a write changed; the lib's
`keyword_suggest` ranks, completes and caches (no egui); the bin draws the field, the rows and the menu
group, and records undo. **Gate:** `cargo fmt --all --check` · `CARGO_TARGET_DIR=target/clippy cargo
clippy --workspace --all-targets -- -D warnings` · `cargo test --workspace` (filter by name, never `-p`).

⚠ `collections_panel.rs` is already 788 lines of code: it gains only the wiring; the field lives in a new
`keyword_field.rs`, the rows in `keyword_rows.rs`.

## Task 1: the catalog — what a write changed, and two counts

`crates/catalog/src/db/keywords.rs`, `crates/catalog/src/db.rs`.

- `assign_keyword` / `unassign_keyword` → `Result<bool, CatalogError>`: `execute(..)? > 0`.
- `create_keyword_reporting(name, parent) -> Result<(i64, bool)>` — the `INSERT … ON CONFLICT DO NOTHING`'s
  row count is the bool; `create_keyword` keeps its signature and delegates.
- `recreate_keyword(id, name, parent) -> Result<()>` — `INSERT INTO keywords (id, name, parent_id)`.
- `pub struct DayCounts { pub neighbours: usize, pub counts: HashMap<i64, usize> }` and
  `day_keyword_counts(photos: &[PathBuf]) -> Result<DayCounts>`: the selection's days
  (`date(taken,'unixepoch')` of each photo with a time), then every other photo taken on one of them —
  `neighbours` is how many, `counts` how many of them carry each keyword.
- `companion_counts(keywords: &[i64]) -> Result<HashMap<(i64, i64), usize>>` — per `j`, a self-join of
  `photo_keywords` on `(folder_id, file_name)` grouped by the other keyword.
- `Catalog::change_count(&self) -> u64` = `self.conn.total_changes()` (`db.rs`).
- Tests (`db/keywords.rs`): assign twice → `true` then `false`; unassign an absent tag → `false`;
  create twice → `(id, true)` then `(id, false)`; recreate after delete keeps the id; day counts on a
  fixture of two days (the other day's photo not counted, the selection itself excluded, a photo with no
  time ignored); companion counts on three files; `change_count` grows on a write and not on a read.
- Callers compile unchanged (`.is_ok()`, `?`, `let _`). Commit.

## Task 2: the lib — rank, complete, cache

`crates/app/src/keyword_suggest.rs`, `pub mod keyword_suggest;` in `lib.rs`.

```rust
pub const LIMIT: usize = 5;
pub const COMPLETE_LIMIT: usize = 8;

pub struct Evidence<'a> {
    pub keywords: &'a [KeywordRow],
    pub on_selection: &'a HashMap<i64, usize>, // keyword_counts(files)
    pub files: usize,
    pub day: &'a DayCounts,
    pub companions: &'a HashMap<(i64, i64), usize>,
}
/// Scored, excluded (on every file; ancestors of those; zero), sorted (score, usage, name), capped.
pub fn rank(e: &Evidence, limit: usize) -> Vec<i64>;
/// The four queries, then `rank`.
pub fn suggest(cat: &Catalog, files: &[PathBuf], limit: usize) -> Vec<KeywordRow>;

pub struct Match { pub id: i64, pub name: String, pub path: String }
/// Exact, then prefix, then substring, case-insensitive; each group by path.
pub fn complete(typed: &str, kws: &[KeywordRow], limit: usize) -> Vec<Match>;
/// `Places › Europe` — the parent chain of `id`, root first ("" for a root).
pub fn parent_path(id: i64, kws: &[KeywordRow]) -> String;

#[derive(Default)]
pub struct Cache { key: Option<(Vec<PathBuf>, u64)>, list: Vec<KeywordRow> }
impl Cache {
    /// `suggest` for `files`, recomputed only when the files or `cat.change_count()` move.
    pub fn get(&mut self, cat: &Catalog, files: &[PathBuf]) -> &[KeywordRow];
}
```

Score of `k`: `day.counts[k] / day.neighbours` (0 without neighbours) + max over `j` in `on_selection` of
`companions[(j,k)] / usage(j)`. Tests: positive control (the fixture yields ≥ 1); same-day beats
unrelated; companion suggested; on-every-file and its ancestors excluded; on-some kept; tie order; cap;
completion order, paths, case; the cache recomputes on a write and not on a redraw (a counting closure or
the change count). Commit.

## Task 3: undo for tagging and creating

`crates/app/src/action_log.rs` (lib): `KeywordTag { keyword: i64, on: bool, files: Vec<PathBuf> }`,
`KeywordCreate { id: i64, name: String, parent: Option<i64> }` — every exhaustive match the compiler
names gets them.

`crates/app/src/catalog_ops.rs` (bin): one `fn tag_files(&mut self, keyword, on, files) -> Vec<PathBuf>`
applies, collects the files that **changed**, writes their XMP, and pushes `KeywordTag` when any did —
`assign_keyword_to_selection`, `unassign_keyword_from_selection` and `set_keyword_on_targets` all call it.
`fn create_and_tag(&mut self, name) ` creates (reporting), tags the selection, and pushes a `Batch` of
`KeywordCreate` (only when created) and `KeywordTag` as **one** step; `Action::CreateKeyword` records a
bare `KeywordCreate` the same way.

`keyword_ops.rs::replay_keyword_action` + `undo.rs`: `KeywordTag` forward re-applies, backward inverts,
both on `files`, then `write_xmp_for(files)`; `KeywordCreate` backward `delete_keyword`, forward
`recreate_keyword`.

Tests (`keyword_ops.rs`, the `tagged` fixture): undoing a tag leaves a pre-existing tag; undo and redo
rewrite the XMP; one undo removes a created-and-tagged keyword and its tags; each route pushes exactly one
step; nothing changed → nothing pushed. Commit.

## Task 4: the field — type to tag

`crates/app/src/keyword_field.rs` (bin, new): `pub(crate) struct FieldState { highlight: usize }` on the
app; `pub(crate) fn field(ui, text: &mut String, state, kws, picked, parent_name) -> Option<FieldOut>`
with `enum FieldOut { Tag(i64), Create(String), Open(i64) }`. The hint: "Tag with a keyword" when
`picked > 0`, else "New keyword" / "New keyword under X". Typing shows `complete(..)` in a list under the
field (rows: name, path in Caption `text3`); ↑/↓ move `highlight`, Enter picks it (or `Create` when there
is no match), a click picks, Escape clears. With `picked == 0` a pick is `Open`.

`collections_panel.rs`: the Keywords section uses `keyword_field::field` in place of `new_item_row`, and
maps `Tag` → `assign_keyword_to_selection`, `Create` → `create_and_tag` (or the bare create when nothing is
selected), `Open` → the existing open.

Tests (`keyword_field.rs`, a harness like `keyword_rows`'): typing "par" lists Paris; Enter yields
`Tag(paris)`; ↓ then Enter the second match; a new name + Enter yields `Create`; Escape closes; the hint
follows `picked`. Commit.

## Task 5: the Suggested rows and the menu group

`keyword_rows.rs`: `pub(crate) fn suggested(ui, rows: &[KeywordRow], kws, picked) -> Option<Out>` — a
`Suggested` label and §7.6 rows (name, `parent_path` as meta, the `+` Tag action; a row click is
`Out::Open`). `collections_panel.rs` draws it between the field and the tree when `picked > 0`, from
`app.keyword_suggest.get(cat, &selected_files)`.

`library/cell_menu.rs`: `Suggested` at the top of the Keywords submenu — `keyword_suggest::suggest(cat,
&files, LIMIT)` (the menu runs only while open, the file's own rule for its queries), the same tri-state
marks, then a separator and the full list.

Tests: the rail shows the Suggested rows for a selection and not without one (nodes); a suggested row's
`+` tags and the XMP carries it; the menu lists `Suggested` first; the hover walk passes (new controls
have sentences). Commit.
