# M10.8d — batch rename: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.
> **Commits carry no `Co-Authored-By` trailer. Never push.**

**Goal:** Photo → Rename… ⌘R (and the right-click) renames the selection's files from a template, in
grid order from a start number, as one undo step — and the single rename stops losing the XMP and four
catalog tables.

**Architecture:** One move path for every rename and move: `photo_move::move_all` (direct, or two
passes through temporary names when targets chain) and `Catalog::move_photos` (one transaction, the
same two passes). A pure `batch_rename::plan` decides names; the bin's `rename_flow` gathers facts and
applies; `after_move` re-keys the selection and reloads hand stacks.

**Spec:** `docs/superpowers/specs/2026-10-02-m10.8d-batch-rename-design.md`.

**Gate:** `cargo fmt --all --check` · `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace
--all-targets -- -D warnings` · `cargo test --workspace` — several filters go **after `--`** as a zsh
array, with a control count. **Commit only after reading every exit code. Sabotage only a committed
tree** (a `git checkout` restore on an uncommitted one throws the feature away — 2026-10-02).

## Task 5: `batch_rename` — the plan

**Files:** create `crates/app/src/batch_rename.rs` (`pub mod` in `lib.rs`).

- [ ] Types: `pub struct Photo { pub files: Vec<PathBuf>, pub taken: Option<i64>, pub camera:
  Option<String> }`. `pub fn photos_of(files: &[PathBuf]) -> Vec<Vec<PathBuf>>` — grouped by
  (folder, stem), in first-appearance order.
- [ ] `pub fn plan(photos: &[Photo], template: &Template, start: usize, taken: impl Fn(&Path) -> bool)
  -> Vec<Planned>`: seq = `start + k`; base = `template.render(NameFacts { file_stem: stem, copy: 0,
  seq, taken, camera })`; `named(n)` = base or `base-{n}` + each file's own extension, in its folder.
  Pass 1: a photo whose `named(0)` equals its current names for every file is **staying** — its names
  reserved. Pass 2, in order, for the others: the least `n` where every name is free — free = not
  reserved by a staying photo, not already planned, and (`!taken(p)` or `p` is a moving source).
  Identity entries are dropped.
- [ ] Tests: order and start (`{seq:3}` from 7 → 007, 008); a RAW+JPEG pair takes one number and
  keeps both extensions; an outside name taken → `-1` for both files of the pair; a swap (A named
  what B is called, B what A is) plans with no suffix; a shift (001→002, 002→003) plans with no
  suffix; a staying photo is left out and its name is not given away; `{date}` empty drops its
  separator.
- [ ] Gate, commit `feat(app): batch_rename plans names from a template (M10.8d)`.

- [ ] Tests (`rename_flow` tests, `test_app` + a temp folder of `a.RAF a.JPG b.JPG c.JPG`):
