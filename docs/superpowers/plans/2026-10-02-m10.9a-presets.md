# M10.9a — preset folders, rename, import and export: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.
> **Commits carry no `Co-Authored-By` trailer. Never push.**

**Goal:** User presets live in one level of folders and can be renamed, moved, updated, imported and
exported — every change one undo step, nothing ever overwritten.

**Architecture:** The store (lib, new `preset_store.rs`) knows folders as subdirectories and keeps the
file format; `preset_ops.rs` (bin) performs each operation and records `ActionKind::PresetEdit
{ before, after }` snapshots; `develop/panel/preset_rows.rs` draws *Yours* with folder headers, menus,
in-place rename and drag.

**Spec:** `docs/superpowers/specs/2026-10-02-m10.9a-presets-design.md`.

**Gate:** `$SCRATCH/gate.sh` (fmt, clippy in `target/clippy`, tests; exits non-zero unless all three
pass) — `gate.sh && git commit`. Filters go after `--` as a zsh array, with a control count. **Sabotage
only a committed tree.**

## Task 1: the store, with folders

**Files:** create `crates/app/src/preset_store.rs`; modify `crates/app/src/presets.rs`, `lib.rs`.

- [ ] Move `PresetStore`, `PresetError`, `TRASH_CAP` and the trash code from `presets.rs` into
  `preset_store.rs`; `presets.rs` re-exports them (`pub use crate::preset_store::{…}`), so callers keep
  compiling. `Preset` gains `#[serde(skip)] pub folder: Option<String>` and `pub fn key(&self) ->
  String` (name, or `folder/name`).
- [ ] `list()` reads the top level (folder `None`) and each subdirectory (folder `Some(dir name)`);
  sorted by folder (none first) then name. `folders() -> Vec<String>` — every subdirectory, sorted,
  empty ones included. `path_of(folder, name)`.
- [ ] `save(&Preset)` writes into its folder (creating it). `delete(folder, name)` — the trash entry is
  `{"folder": …, "preset": …}`; `latest_trashed` reads both shapes; `restore(folder, name)` writes back
  into the remembered folder. `latest_trashed_name` unchanged.
- [ ] `rename(folder, name, new) -> Result<(), PresetError>` and `move_to(folder, name, to)` — refuse
  `PresetError::Taken(String)` when the target name exists in the target folder (compared by sanitized
  file name). `create_folder(name) -> Result<String>` (refuses a taken one, returns the sanitized name),
  `rename_folder(old, new)`, `remove_folder(name)` (trashes each preset, then removes the directory).
- [ ] `pub fn unique_name(taken: &[String], wanted: &str) -> String` — `wanted`, else `wanted 2`, `3`…
  (compared sanitized). `pub fn export_path(dir, stem, ext) -> PathBuf` — `stem.ext`, else `stem-1.ext`…
  never an existing file.
- [ ] Tests (temp dirs): list with folders and an empty folder; save/delete/restore in a folder; an old
  trash entry reads as no folder; rename/move refuse a taken name and keep the file; `unique_name`;
  `export_path`; folder create (taken refused) / rename / remove (presets in the trash, restorable);
  `key`. Existing store tests keep passing.
- [ ] Gate, commit `feat(app): the preset store knows folders, renames, moves; the trash remembers the
  folder (M10.9a)`.

## Task 2: the operations and their undo

**Files:** create `crates/app/src/preset_ops.rs` (bin `mod`); modify `action_log.rs`, `undo.rs`,
`transfer.rs` (`delete_preset` by folder+name), `import_flow.rs` (names → keys), `modals/import.rs`,
`modals/presets.rs` (Folder choice; confirm-delete carries the folder; `Modal::ConfirmDeletePresetFolder
  { name, count }` — Delete folder asks first, its presets go to the trash), `modals/mod.rs`.

- [ ] `ActionKind::PresetEdit { before: PresetState, after: PresetState }` with `pub struct PresetState
  { pub presets: Vec<Preset>, pub folders: Vec<String> }` (presets keep their `folder`). Global in
  `reachable` like `PresetDelete`. `PresetDelete { folder: Option<String>, name: String }`.
- [ ] `preset_ops` (`impl RustroomApp`), each building `before`/`after`, applying, pushing one step:
  `rename_preset(folder, name, typed)`, `move_preset(folder, name, to)`, `update_preset(folder, name)`
  (open photo's edits, groups kept), `import_presets(paths, into)` (`unique_name`, non-presets counted),
  `new_preset_folder(typed)`, `rename_preset_folder(old, typed)`, `delete_preset_folder(name)`;
  `export_preset(folder, name, dir)`, `export_preset_folder(name, dir)` (no undo — nothing in the store
  changes); `replay_preset_edit(kind, forward)`: delete every preset of the side being left, remove its
  folders that the other side lacks (only if empty), create the other side's folders, save its presets.
  Pickers (`rfd`) in thin wrappers, the work in functions taking paths — tests call those.
- [ ] Tests: each operation then Ctrl+Z restores and Ctrl+Shift+Z redoes (folder and file state);
  rename onto a taken name is refused with a status and no undo step; update keeps the groups; import
  of two files where one is junk and one collides; folder delete then undo brings presets back.
- [ ] Gate, commit `feat(app): rename, move, update, import and export presets, and their folders — one
  undo step each (M10.9a)`.

## Task 3: the panel

**Files:** create `crates/app/src/develop/panel/preset_rows.rs`; modify `develop/panel/presets.rs`,
`develop/panel/mask_components.rs` (`RowOut::response`, `RowSpec::delete_hover`), `develop/panel/mod.rs`.

- [ ] `mask_components`: `RowOut` gains `pub response: egui::Response`; `RowSpec` gains `delete_hover:
  &str` (masks say *"Deletes this mask"*, presets *"Deletes this preset"*).
- [ ] `preset_rows::yours(app, ui) -> Option<RowAction>`: the no-folder presets, then per folder a
  `section::header` (trailing count) with its presets indented. A preset row: click applies,
  double-click → `app.preset_rename = Some((folder, name, text))` (drawn as a field; Enter commits,
  Escape cancels), right-click menu (Rename, Update with current settings, Move to ▸, Export…, Show in
  Finder, Delete), drag payload `PresetDrag(folder, name)`. A folder header: right-click (Rename,
  Import presets here…, Export folder…, Delete folder…), double-click rename, accepts a drop; the
  *Yours* caption accepts a drop for no folder.
- [ ] `presets.rs`: the ⋯ menu (Import presets…, New folder…, Show presets folder); *Yours* via
  `preset_rows`; actions dispatched to `preset_ops`.
- [ ] Tests (drawn, `test_ui`): a folder header and its preset are drawn; the six right-click entries;
  a double-click opens the field and Enter renames; a drag from a preset onto a folder header moves it;
  the ⋯ entries; the hover sweep still green.
- [ ] Gate, commit `feat(app): preset folders in the Presets tool — menus, in-place rename, drag
  (M10.9a)`.
