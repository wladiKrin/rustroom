# M10.10b — export sizing in cm/in with a PPI, and a file-size target: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use `- [ ]`.
> **Commits carry no `Co-Authored-By` trailer. Never push.**

**Goal:** The Size section offers Lightroom's modes in px/cm/in with a PPI and Don't enlarge, applied to
the final cropped picture; every file carries its PPI; a JPEG can be limited to a file size.

**Architecture:** The export crate owns the size rules (`sizing`), the PPI writers (`density`), in-memory
encoding (`encode`, `metadata::with_xmp`) and the quality search (`size_limit`). The app predicts the
final size from the prefix's `output_dims`, chooses the decode size, trims or enlarges the render, and
finishes the file (`batch_export::{sizing, finish}`); the bin draws the controls.

**Tech Stack:** Rust, `image` 0.25 (JPEG density, Lanczos3), `crc32fast` (PNG chunk), serde.

**Spec:** `docs/superpowers/specs/2026-10-11-m10.10b-export-sizing-design.md`.

## Global Constraints

- No egui in `export`, `pipeline`, `core-image` or any app lib module.
- No new crates.
- Old options files and presets load: `"max_edge": N` → Long edge N px; `null`/absent → Original.
- **KB = 1000 bytes.** Quality floor **40**. Default PPI **300**, Don't enlarge **on**, limit off at 500 KB.
- The size is the final cropped picture's, exact in pixels.
- Hover text: one short sentence, no full stop.
- Gate: `$SP/gate.sh > $SP/gate.out 2>&1; rc=$?`, commit only on `rc == 0`; filters after `--`; sabotage
  only a committed tree; never `git checkout` uncommitted work.

## Review Focus

1. **A rotated (90°) and cropped photo with Width & height** — the box is matched against the photo as it
   will be seen, after orientation. (Task 3 test with a quarter turn.)
2. **A file-size limit smaller than the metadata alone** — fails that photo with a reason, never loops or
   writes an over-limit file silently. (Task 4 test.)
3. **Switching units back and forth** — the numbers return to what they were (within rounding), never
   drift. (Task 1 test.)
4. **A DNG export with a size** — sized like any other; no PPI written, no limit offered. (Task 3 test.)
5. **An export preset saved before M10.10b with `max_edge`** — still sizes the same. (Task 3 test on the
   real preset shape.)

## Task 1: the size rules (export crate)

**Files:** create `crates/export/src/sizing.rs`; `lib.rs` (`pub mod sizing;`, re-exports).

**Interfaces — produces:**
- `FitMode { #[default] Original, WidthHeight, Dimensions, LongEdge, ShortEdge, Megapixels, Percentage }`
  with `ALL`, `label()` ("Original size", "Width & height", "Dimensions", "Long edge", "Short edge",
  "Megapixels", "Percentage"), `uses_length()`.
- `LengthUnit { #[default] Px, Cm, In }` with `ALL`, `label()` ("px", "cm", "in"), `to_px(v, ppi)`,
  `from_px(px, ppi)`.
- `#[serde(default)] OutputSize { fit, unit, long_edge: f32, short_edge: f32, width: f32, height: f32,
  megapixels: f32, percent: f32, ppi: u16, dont_enlarge: bool }`, hand-written `Default` (2048, 1536,
  1920 × 1080, 12, 50, 300, true), `impl Eq` (values finite by construction), `long_edge_px(n)`,
  `set_unit(unit)`, `plan(final_w, final_h) -> SizePlan`.
- `SizePlan { width: usize, height: usize, ppi: f32, below_ppi: bool }`.
- `pub fn size_or_max_edge<'de, D: Deserializer<'de>>(d) -> Result<OutputSize, D::Error>` — an untagged
  `Old(Option<usize>) | New(OutputSize)`.

- [ ] Tests first (`sizing.rs`): on 6000 × 4000 and 4000 × 6000 — Long edge 2048 px → 2048 × 1365 /
  1365 × 2048; Short edge 1000 → 1500 × 1000; Width & height 30 × 20 cm at 300 PPI → 3543 × 2362, and on the
  portrait → 1575 × 2362 (fits 30 wide, 20 high); Dimensions 30 × 20 cm on the portrait → 2362 × 3543;
  Megapixels 6 → within 1 % of 6 MP at the photo's aspect; Percentage 25 → 1500 × 1000; Original → the
  photo's own size with 300 PPI. Don't enlarge: Long edge 70 cm at 300 PPI on 6240 × 4160 → 6240 × 4160,
  `ppi` ≈ 226.4, `below_ppi`; the same in px (9000 px) → own size, `ppi` 300, not below; enlarge allowed
  → 8268 × 5512. Units: px → cm → in → px returns each length within 0.01 px. Serde: `{"max_edge":2048}`
  through a wrapper struct using `size_or_max_edge` → Long edge 2048 px; `null` → Original; a new
  `OutputSize` round-trips; a default is inert (`fit == Original`) with its other fields non-zero.
- [ ] Run: `cargo test --workspace --offline -- sizing` → FAIL (no module).
- [ ] Implement: `k` per mode on the final size (Dimensions compares long with long and short with short);
  `k > 1 && dont_enlarge` → `k = 1`, and for a length mode in cm/in the PPI written is `ppi / k_asked`,
  `below_ppi = true`; target `round(w·k).max(1)` × `round(h·k).max(1)`. `set_unit` converts the four
  lengths through the PPI.
- [ ] Run → PASS. Gate, commit `feat(export): the size rules — Lightroom's modes in px/cm/in with a PPI,
  Don't enlarge lowering the PPI (M10.10b)`.

## Task 2: writing the PPI, encoding in memory, the size limit (export crate)

**Files:** create `crates/export/src/density.rs`, `crates/export/src/size_limit.rs`; `lib.rs`
(`encode`, `save` through it); `metadata.rs` (`with_xmp`); `sizing.rs` (`resample_encoded`).

**Interfaces — produces:**
- `pub fn encode(image: &ImageBuf, format: ExportFormat, quality: u8, space: OutputSpace, ppi:
  Option<f32>) -> Result<Vec<u8>, ExportError>` — raster formats; DNG is `Err` (written by `save`).
- `density::{png_with_ppi(bytes, ppi), tiff_with_ppi(bytes, ppi)} -> Result<Vec<u8>, ExportError>`;
  JPEG through `JpegEncoder::set_pixel_density`.
- `metadata::with_xmp(bytes: Vec<u8>, format, meta) -> Result<Vec<u8>, ExportError>`; `embed` uses it.
- `size_limit::{QUALITY_FLOOR = 40, FileSizeLimit { on: bool, kb: u32 } (default off, 500),
  enum Within { Fits { bytes, quality }, TooBig { at_floor: usize } },
  encode_within(limit_bytes, encode: impl Fn(u8) -> Result<Vec<u8>, ExportError>) -> Result<Within, _>}`.
- `sizing::resample_encoded(image: &ImageBuf, space: OutputSpace, w: usize, h: usize) -> ImageBuf`.

- [ ] Tests first: JPEG at 300 PPI → its APP0 JFIF has units 1 and density 300 × 300; PNG → a `pHYs`
  chunk of 11811 px/m (unit 1) before `IDAT`, and `image` still decodes it; TIFF 8 and 16 → IFD0's 282/283
  read 300/1 and 296 reads 2, and `image` still decodes it; `ppi: None` → bytes identical to `save`'s
  file. `with_xmp` equals what `embed` writes. Limit: a closure whose size falls with quality
  (`(q as usize) * 1000`) → `limit 60_000` gives quality 60; `limit 39_999` → `TooBig { at_floor:
  40_000 }`; on a real noisy JPEG a 30 KB limit is met and quality + 1 is over it (or the quality is 100).
  `resample_encoded` of a 2 × 1 black-white sRGB image to 1 × 1 → `encode(0.5)` ≈ 0.735, not 0.5.
- [ ] Run: `cargo test --workspace --offline -- density size_limit encode resample` → FAIL.
- [ ] Implement. `png_with_ppi`: drop any `pHYs`, insert after `IHDR`, `round(ppi / 0.0254)`, CRC over type
  and data. `tiff_with_ppi`: walk IFD0, write `round(ppi·100)/100` at 282 and 283's value offsets and 2 into
  296's inline value — `Err` if any of the three is missing. `encode_within`: if `encode(40)` is over →
  `TooBig`; else binary search 40..=100 for the highest that fits, keeping the best seen.
  `resample_encoded`: `space.decode` per sample → `image::imageops::resize` (Lanczos3) on an
  `Rgb32FImage` → `space.encode`.
- [ ] Run → PASS. Gate, commit `feat(export): the PPI in JPEG, PNG and TIFF; encoding in memory; a
  quality search under a file-size limit (M10.10b)`.

## Task 3: the size reaches the export (pipeline, core-image, app)

**Files:** `crates/pipeline/src/prefix.rs` (`prefix_output_dims`); `crates/core-image/src/…`

(`export_one` → `Result<Written, String>`, `scale_for` removed); `fixtures.rs`; `worker.rs`;
`export_summary.rs` (`size`); `modals/export.rs` (the interim long-edge control on `size`);
`preview_build.rs`, `export_presets.rs`, `settings/compat_tests.rs`, examples.

**Interfaces:**
- Consumes: `OutputSize::plan`, `encode`, `with_xmp`, `resample_encoded`.
- Produces: `pipeline::prefix_output_dims(edits: &Edits, w: usize, h: usize) -> (usize, usize)`;
  `ImageBuf::downscaled_dims(w, h, max_dim) -> (usize, usize)`; `pub struct Written { pub below_ppi:
  bool, pub shrunk: bool }`; `sizing::Sizing { decode_long, plan, enlarge }`, `sizing::for_photo(edits,
  (w, h), &OutputSize) -> Sizing`, `sizing::fit(rendered, &plan, space) -> ImageBuf`;
  `finish::write(base, dest, opts, logo, meta, &plan, space) -> Result<Written, String>`.

- [ ] Tests first: `prefix_output_dims` — identity, a half crop, a quarter turn; `downscaled_dims` equals
  `downscale_to`'s output for five sizes. Render (`render.rs` tests): a 400 × 200 source cropped to its
  left half at Long edge 100 px → exactly 100 × 100 (**today 50 × 50**); Dimensions 10 × 5 cm at 50 PPI on
  a 600 × 300 source → 197 × 98 and JFIF 50; a quarter-turned 300 × 600 source at Width & height 200 × 100
  px → 200 × 100; enlarge allowed, Long edge 300 px on 100 × 50 → 300 × 150; Don't enlarge, 10 cm at 50 PPI
  on 100 × 50 → 100 × 50, `below_ppi`, JFIF 25; a DNG with Long edge 64 px → 64 wide, no density written.
  Options: the real pre-M10.10b preset JSON (`export_presets.rs`' shape with `"max_edge":2048`) → Long edge
  2048 px.
- [ ] Run: `cargo test --workspace --offline -- prefix_output_dims downscaled_dims batch_export
  export_presets compat` → FAIL (does not compile).
- [ ] Implement. `prefix_output_dims` folds `build_prefix_steps(edits, FULL, None, default, None)`'s
  `output_dims`. `for_photo`: final = predicted at full size; plan; shrink → the smallest decode long edge
  from `ceil(source_long · max(tw/fw, th/fh))` upward whose predicted output covers the target; else the
  source's own. `export_one`: decode `downscale_to(decode_long)`, `RenderScale::new(decode_long /
  source_long)`, render, `fit` (centred trim, or `resample_encoded` up), then `finish::write`: sharpen,
  watermark, and DNG → `save` + `embed` as before; else `encode(…, Some(plan.ppi))` → `with_xmp` → write.
  `ExportOptions`: `#[serde(alias = "max_edge", deserialize_with = "export::sizing::size_or_max_edge")]
  pub size: OutputSize`, `pub limit: FileSizeLimit`; `opts(dir, long_edge)` maps onto `size`.
  `export_summary::size` reads `size` (Original → "original"; Long edge px → "2048 px long edge").
- [ ] Run → PASS. Gate, commit `feat(app): the size applies to the final cropped picture — predicted, the
  decode chosen, trimmed exact or enlarged in linear light; the PPI in every file (M10.10b)`.

## Task 4: the file-size limit and the report's notes

**Files:** `batch_export/finish.rs`, `batch_export/worker.rs` (`ExportReport::{below_ppi, shrunk}`, notes),
`fixtures.rs` (`noisy(w, h)`).

- [ ] Tests first (worker): a JPEG run with a 30 KB limit on a noisy 600 × 400 → the file ≤ 30 000 bytes
  and no note; a 3 KB limit → the file ≤ 3000 bytes, smaller than 600 × 400, note *"1 photo made smaller
  to fit 3 KB"*; a 1 KB limit with a 2 KB copyright caption → that photo fails, its reason names the limit;
  a Don't enlarge run below the PPI → note *"1 photo below 50 PPI"*; `summary` places the notes after the
  counts.
- [ ] Run: `cargo test --workspace --offline -- batch_export` → FAIL.
- [ ] Implement. `finish::write` with `limit.on && format == Jpeg`: `encode_within(kb·1000, |q| with_xmp(
  encode(finished, Jpeg, q, …)))`; `TooBig { at_floor }` → resize the **base** (before sharpening and the
  watermark) by `sqrt(limit / at_floor) · 0.95` with `resample_encoded`, redo sharpening and watermark,
  search again — at most 8 rounds and never below 16 px, else `Err("could not be made smaller than N KB")`.
  The run counts `Written` flags and pushes *"N photo(s) below P PPI"* and *"N photo(s) made smaller to fit
  K KB"* into `notes` before `Finished`.
- [ ] Run → PASS. Gate, commit `feat(app): a file-size limit — the quality searched to 40, then the pixels;
  the report names photos below the PPI or made smaller (M10.10b)`.
