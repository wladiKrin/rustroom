# M10.19c — Folder marks and Forget N folders — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mark several folders in the Library's Folders rail (⌘/⇧-click) and forget them all, after one confirmation, from a right-click menu — one undo step.

**Architecture:** A no-egui lib type `FolderMarks` keyed by path holds the marks and their gesture rules; `folder_tree::subtrees` gives the deduplicated rows a forget covers. The app's single-folder forget becomes `forget_folders(paths)` behind one generalised confirmation modal; the rail reads click modifiers and adds a context menu.

**Tech Stack:** Rust, egui 0.35 (bin), `catalog` (SQLite).

**Spec:** `docs/superpowers/specs/2026-10-12-m10.19c-folder-marks-design.md`

## Global Constraints

- Env for every cargo command: `export PKG_CONFIG_PATH="/opt/homebrew/lib/pkgconfig:/opt/homebrew/opt/libraw/lib/pkgconfig:/opt/homebrew/opt/little-cms2/lib/pkgconfig:$PKG_CONFIG_PATH"`.
- Tests: `cargo test --workspace <filter>` only (never `-p`); a filtered run must report `N passed`, N > 0.
  Clippy: `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`.
- "Delete" means **Forget from the catalog**; files on disk are never touched.
- Gestures: ⌘-click toggles a mark, ⇧-click extends from the anchor in the rail's visible order, a plain

- Lib modules have no egui. Commits carry no `Co-Authored-By`. Sabotage from a `cp` backup, restore with `cp`.

## Review Focus

1. **A right-click on an UNMARKED row while others are marked** acts on that row alone — pinned in Task 3
   (`a_right_click_on_an_unmarked_row_forgets_only_it`).
2. **⇧-click after the anchor folder disappeared** (forgotten, or hidden by a collapse) behaves as a plain
   mark, never a range from nowhere — pinned in Task 1 (`a_range_from_a_vanished_anchor_is_a_click`).
3. **A marked folder nested under another marked one** is forgotten once and restored once — pinned in

4. **Marks for folders that no longer exist** do not inflate the menu's count — pinned in Task 1

5. **A plain click on one of several marked folders** opens it and leaves only it marked — pinned in

```rust
use std::collections::BTreeSet;
use std::path::{Path, PathBuf};

#[derive(Debug, Default, Clone)]
pub struct FolderMarks {
    marks: BTreeSet<PathBuf>,
    anchor: Option<PathBuf>,
    /// The open folder the marks were last reset for — `None` until the first `follow`.
    followed: Option<Option<PathBuf>>,
}

impl FolderMarks {
    pub fn click(&mut self, path: &Path) {
        self.marks = [path.to_path_buf()].into();
        self.anchor = Some(path.to_path_buf());
    }
    pub fn toggle(&mut self, path: &Path) {
        if !self.marks.remove(path) { self.marks.insert(path.to_path_buf()); }
        self.anchor = Some(path.to_path_buf());
    }
    pub fn extend_to(&mut self, path: &Path, order: &[PathBuf]) {
        let at = |q: &Path| order.iter().position(|o| o == q);
        match (self.anchor.as_deref().and_then(at), at(path)) {
            (Some(a), Some(b)) => self.marks = order[a.min(b)..=a.max(b)].iter().cloned().collect(),
            _ => self.click(path),
        }
    }
    pub fn follow(&mut self, open: Option<&Path>) {
        let open = open.map(Path::to_path_buf);
        if self.followed.as_ref() != Some(&open) {
            self.marks = open.iter().cloned().collect();
            self.anchor = open.clone();
            self.followed = Some(open);
        }
    }
    pub fn retain(&mut self, keep: impl Fn(&Path) -> bool) { self.marks.retain(|p| keep(p)); }
    pub fn contains(&self, path: &Path) -> bool { self.marks.contains(path) }
    pub fn len(&self) -> usize { self.marks.len() }
    pub fn is_empty(&self) -> bool { self.marks.is_empty() }
    pub fn targets(&self, row: &Path) -> Vec<PathBuf> {
        if self.marks.len() > 1 && self.marks.contains(row) {
            self.marks.iter().cloned().collect()
        } else {
            vec![row.to_path_buf()]
        }
    }
}
```

```rust
/// Every row in any of `paths`' subtrees, each ONCE, in `rows` order — what forgetting `paths`
/// removes. ⚠ A marked folder beneath another marked one is in both subtrees; counting or forgetting
/// it twice would inflate the dialog and fail the second delete.
pub fn subtrees<'a>(rows: &'a [FolderRow], paths: &[PathBuf]) -> Vec<&'a FolderRow> {
    rows.iter()
        .filter(|r| paths.iter().any(|p| r.path == *p || is_under(&r.path, p)))
        .collect()
}

#[test]
fn subtrees_counts_a_nested_path_once() {
    let ps = [PathBuf::from("/Users/w/Pictures/fuji"), PathBuf::from("/Users/w/Pictures/fuji/2026/09-27")];
    let ids: Vec<i64> = subtrees(&rows(), &ps).iter().map(|r| r.id).collect();
    assert_eq!(ids, vec![1, 2, 5]);
}
```
