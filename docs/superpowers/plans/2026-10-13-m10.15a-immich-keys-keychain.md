# M10.15a — The Immich API keys in the OS keychain — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep both Immich API keys in the OS credential store instead of plaintext `settings.json`, migrating existing keys and falling back to the file only where no keychain works.

**Architecture:** A lib module `rustroom_app::secrets` (a `SecretStore` trait, the real `Keychain` over the `keyring` crate, an in-memory `Memory` for tests). `SettingsStore` gains an optional store: `user_default()` (the app) uses the keychain, `new(path)` (every test) uses none. `Settings` keeps the keys as in-memory fields, so `immich_source::connection`, `immich_upload::config` and the Settings window's editing are unchanged.

**Tech Stack:** Rust, `keyring` 4.2 (default `v1` feature: macOS Keychain, Windows Credential Manager, pure-Rust zbus Secret Service), serde_json.

**Spec:** `docs/superpowers/specs/2026-10-13-m10.15a-immich-keys-keychain-design.md`

## Global Constraints

- One keychain item: service `Rustroom`, account `immich`, the two keys as JSON `{"browse": …, "upload": …}`.
- **The one rule:** plaintext keys in `settings.json` are always the newest — on load they win and are moved into the keychain; the file loses them only after a keychain write succeeded. No path deletes a key before another copy exists.
- **No test touches the real keychain** except one `#[ignore]`d round trip on a throwaway account.
- The keychain is written **only when a key changed**, never on an ordinary settings save.
- Lib modules have no egui. Hover text: one sentence, ≤ 110 characters, no full stop (`slider_help::sentence_fault`).
- Gate: `cargo fmt --all --check`, `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (filter by test name, never `-p`). Commit messages carry no `Co-Authored-By`. Never push.

## Review Focus

1. **A denied or failed keychain read** (the user clicks Deny) — the keys are empty this session, and neither the file nor the item is written or deleted. → `a_failed_read_writes_and_deletes_nothing` (Task 2).
2. **Clearing a key to disconnect** — the cleared value persists; the keychain never resurrects the old key on the next launch. → `a_cleared_key_stays_cleared` (Task 2).
3. **A settings-save storm** (panel toggles save the file constantly) — the keychain is not touched once. → `ordinary_saves_do_not_touch_the_keychain` (Task 2).
4. **A keychain write failing mid-migration** — the file keeps its keys; nothing is lost. → `a_failed_write_keeps_the_keys_in_the_file` (Task 2).
5. **A malformed item** (someone edited it in Keychain Access) — read as a failure, never a panic, never written over. → `a_malformed_item_is_a_read_failure` (Task 1).

  - `the_files_keys_win_over_an_older_item` — item `old`, file `new` → load gives `new`, the item becomes `new`, the file loses them.
  - `ordinary_saves_do_not_touch_the_keychain` — load, then ten saves with only `panel_sections` changing: `writes()` unchanged.
  - `a_cleared_key_stays_cleared` — load (keys in the item), clear `immich_key`, save, reload: `immich_key` empty.

- [ ] **Step 2:** run → compile errors / failures.
- [ ] **Step 3: implement.** Fields: `secrets: Option<Arc<dyn SecretStore>>`, `written: Mutex<Option<Keys>>`, `home: Mutex<KeyHome>`. A private `write_file(&self, s: &Settings, blank_keys: bool)`.
  - `load`: parse the file (default on error). No store → return. File keys non-empty → `store.write`; on `Ok` remember them as written, home `Keychain`, `write_file(s, true)`; on `Err` home `File`. Return `s` (with its keys). File keys empty → `store.read()`: `Ok(Some(k))` → fill `s`, written `Some(k)`, home `Keychain`; `Ok(None)` → home `Keychain`; `Err` → home `File`, nothing written.
  - `save`: no store → `write_file(s, false)`. Keys from `s`; unchanged when equal to `written`, or empty with `written == None`. Changed → `store.write`: `Ok` → written, home `Keychain`; `Err` → home `File`. Then `write_file(s, home == Keychain)`.
