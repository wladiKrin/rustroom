# M10.15c — Read Immich's own rating and favourite — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fill a photo's Rustroom rating and flag once from Immich's own rating and favourite, where Rustroom has none, never writing to the server.

**Architecture:** The `immich` DTO learns `isFavorite` and `exifInfo.rating`, and every search asks for EXIF. The catalog gets two "filled" columns and one method holding the whole fill rule in SQL. The app maps an asset to marks (`immich_catalog::server_marks`) and fills right after `record_assets` when an album or month opens; the list cache's format version moves so every list is fetched once with the new fields.

**Tech Stack:** Rust, serde, rusqlite.

**Spec:** `docs/superpowers/specs/2026-10-13-m10.15c-immich-rating-and-favourite-design.md`

## Global Constraints

- Never write to Immich. Fill only copy 0, only where Rustroom's mark is empty (rating 0 / flag `None`), each mark at most once per photo (`filled_rating` / `filled_flag`).
- Mapping: rating 1–5 → stars; `isFavorite` → `Flag::Pick`; rating −1 → `Flag::Reject` and no stars; favourite + −1 → `Pick`; anything else (`null`, 0, 6, −2…) → nothing.
- `Asset::is_favorite` and `Asset::exif_info` default when absent (old cached lists lack them); `ExifInfo::rating` defaults when absent.
- Schema 12 → 13 is a **new gate**, never an edit to an old one. `immich_list_cache::VERSION` 1 → 2.
- Fixtures say whether they were captured or constructed.
- Lib modules have no egui. Gate: `cargo fmt --all --check`, `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (filter by test name, never `-p`). No `Co-Authored-By`. Never push.

## Review Focus

1. **An old cached list (format 1) on the first launch** — a miss, fetched again with the new fields; never a parse failure that empties an album. → `a_version_one_list_is_a_miss` (Task 3) and `an_old_cached_asset_without_the_new_fields_parses` (Task 1).
2. **A mark the user set in Rustroom, then Immich's arrives** — untouched. → `a_set_mark_is_never_overridden` (Task 2).
3. **A filled mark the user clears** — stays cleared on every later open. → `a_filled_then_cleared_mark_stays_cleared` (Task 2).
4. **A virtual copy of an Immich photo** — keeps its own marks. → `only_the_original_is_filled` (Task 2).
5. **An open that fills nothing** — no catalog change, so no view refresh. → `a_fill_that_changes_nothing_moves_no_counter` (Task 2).

```rust
//! Filling a photo's marks from the server it came from — once, and only where it has none (M10.15c).
//!
//! ⚠⚠ **The whole rule is in the SQL**: each update names the empty value and the unfilled column
//! in its `WHERE`, so a mark the user set, or one filled before, is never touched — no read-then-write
//! to race, and a fill that changes nothing changes no row (`change_count` stays).

use super::{split, Catalog, CatalogError, Flag};  // `split` as `photo_id` uses it — adjust the path
use std::path::PathBuf;

/// What the server says about one photo: stars 1–5, and a flag.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct ServerFill {
    pub photo: PathBuf,
    pub rating: Option<u8>,
    pub flag: Option<Flag>,
}

impl Catalog {
    /// Fill each photo's rating and flag from `fills` where the original (copy 0) has none and never
    /// had one filled. Returns how many marks were filled. ⚠ An unknown photo is skipped.
    pub fn fill_from_server(&self, fills: &[ServerFill]) -> Result<usize, CatalogError> {
        let tx = self.conn.unchecked_transaction()?;
        let mut n = 0;
        for f in fills {
            let Some((folder, name)) = split(&f.photo) else { continue };
            let row = "folder_id = (SELECT id FROM folders WHERE path = ?1) AND file_name = ?2 AND copy = 0";
            if let Some(r) = f.rating.filter(|r| (1..=5).contains(r)) {
                n += tx.execute(
                    &format!("UPDATE photos SET rating = ?3, filled_rating = 1
                              WHERE {row} AND rating = 0 AND filled_rating = 0"),
                    rusqlite::params![folder, name, r as i64],
                )?;
            }
            if let Some(flag) = f.flag.filter(|f| *f != Flag::None) {
                n += tx.execute(
                    &format!("UPDATE photos SET flag = ?3, filled_flag = 1
                              WHERE {row} AND flag = 0 AND filled_flag = 0"),
                    rusqlite::params![folder, name, flag.to_i64()],
                )?;
            }
        }
        tx.commit()?;
        Ok(n)
    }
}
```

```rust
/// What Immich's own marks become in Rustroom (M10.15c): 1–5 stars; a favourite → pick; −1
/// (rejected) → reject and no stars; a favourite rejected → pick. Anything else is nothing.
///
/// ⚠ −1 is handled although the reply schema says 1–5: writing allows −1, and no real reply could
/// settle what the server sends back.
pub fn server_marks(a: &immich::Asset) -> (Option<u8>, Option<catalog::db::Flag>) {
    use catalog::db::Flag;
    let rating = a.exif_info.as_ref().and_then(|e| e.rating);
    let stars = rating.filter(|r| (1..=5).contains(r)).map(|r| r as u8);
    let flag = if a.is_favorite {
        Some(Flag::Pick)
    } else if rating == Some(-1) {
        Some(Flag::Reject)
    } else {
        None
    };
    (stars, flag)
}

/// Fill the catalog's marks of `assets` (cached under `root`) from Immich's — once each, never over
/// the user's (`Catalog::fill_from_server`). Only assets carrying a mark are passed on.
pub fn fill_marks(
    cat: &catalog::db::Catalog,
    root: &Path,
    assets: &[immich::Asset],
) -> Result<usize, catalog::db::CatalogError> {
    let fills: Vec<catalog::db::ServerFill> = assets
        .iter()
        .filter_map(|a| {
            let (rating, flag) = server_marks(a);
            (rating.is_some() || flag.is_some()).then(|| catalog::db::ServerFill {
                photo: crate::immich_source::cache_path(root, a),
                rating,
                flag,
            })
        })
        .collect();
    if fills.is_empty() {
        return Ok(0);
    }
    cat.fill_from_server(&fills)
}
```
