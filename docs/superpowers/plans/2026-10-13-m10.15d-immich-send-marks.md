# M10.15d — Send marks to Immich — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A deliberate, confirmed **Send marks** that writes the selected photos' Rustroom marks to their Immich assets — never removing a mark there — and an **Undo last send** that restores what it replaced.

**Architecture:** Every decision is pure and lives in a new lib module `immich_send` (mapping, plan, groups, undo, words). The `immich` client gains one `PUT /assets`. The catalog keeps the last send's prior values (v14). The worker gains a check job (fresh list, read-only key) and a send job (its own Write-key connection). The bin gets `send_flow.rs`, `modals/send_marks.rs`, and `status_immich.rs` (the Immich buttons moved out of the over-long `status_bar.rs`, with Send marks added).

**Tech Stack:** Rust, egui 0.35 (bin), ureq, rusqlite.

**Spec:** `docs/superpowers/specs/2026-10-13-m10.15d-immich-send-marks-design.md`

## Global Constraints

- Mapping: ★1–5 → `rating`; pick → `isFavorite: true`; reject → `rating: -1` (stars + reject → −1). **Never remove:** no rating / no flag in Rustroom leaves Immich's as it is.
- Nothing reaches the server except from the confirmation's button. Only `rating` and `isFavorite` are ever sent.
- The send uses the **Write key** (`Settings::immich_upload_key`, through `immich_upload::config`), never the browse key.
- Record only what landed; undo restores both fields to the prior values (`rating: null` included).
- Lib modules have no egui. Hover text: one sentence, ≤ 110 characters, no full stop. No file over 1,000 lines of code and doc.
- A new schema gate never edits an old one; older upgrade-test fixtures drop what the new gate adds.
- Gate: `cargo fmt --all --check`, `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`. Narrow runs may use `--lib --bins` (still `--workspace`). No `Co-Authored-By`. Never push.
- ⚠ **Stop before the first real send** — it changes the author's server: ask him to add `asset.update` to the Write key and to pick one photo, then send and undo it with his OK.

## Review Focus

1. **A photo whose mark in Immich was set on the phone after the list was cached** — the check refetches, so the confirmation and the recorded prior value are the server's real ones. → `the_check_uses_the_fresh_list_not_the_cache` (Task 5).
2. **A selection including a virtual copy and its original** — one asset, one line, the original's marks. → `a_copy_counts_as_its_original_once` (Task 5).
3. **Undo after a half-landed send** — restores exactly what landed. → `a_half_landed_send_records_only_what_landed` (Task 5).
4. **Undo of a photo that had no stars** — `rating: null` sent, not left as is. → `undo_groups_restore_both_fields_null_included` (Task 2).
5. **A key without `asset.update`** — nothing recorded, the message names the permission. → `a_refused_send_records_nothing_and_names_the_permission` (Task 5).

pub fn wanted(mine: Marks, server: ServerMarks) -> ServerMarks {
    let rating = if mine.flag == Flag::Reject {
        Some(-1)

}
