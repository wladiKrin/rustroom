# M10.16d2 — Lens Blur's GPU twin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Lens Blur live while dragging — `GpuLensBlurStage`, the d1 CPU reference as compute shaders, joined to the prefix seam by name.

**Architecture:** The twin resolves its inputs on the CPU at construction — the two planes as bytes at the frame's size, the focus, the highlight level — through ONE lookup shared with `build_prefix_steps` (`pipeline::lens_blur::inputs`). One constant shader holds a source-build and a dense-gather entry point per level (≤ 8) and one full-resolution composite that samples every level bilinearly; every parameter is a uniform, so it compiles once. `SeamFacts` gains the maps (`ai`), and the app's prefix walk and export pass them.

**Tech Stack:** Rust, `wgpu` compute (WGSL), the `gpu-pipeline` crate's `GpuStage` / `GpuChain`.

**Spec:** `docs/superpowers/specs/2026-10-14-m10.16d-lens-blur-design.md` (§3 — the GPU twin; §2 — the reference it must match).

## Global Constraints

- The CPU stage defines the picture; the twin matches it — **worst < 1 eight-bit level** on every parity fixture (`crate::compare`), the bar `an_accelerated_prefix_step_renders_the_same_picture` sets for dehaze. A failure is investigated, never met by loosening (CLAUDE.md shape (d)).
- **Target: under ~50 ms a frame at the preview size**, measured with `RUSTROOM_DEBUG_GPU_TIME` (spec §3).
- No adapter, a refused buffer, or a panic → the CPU step (`guarded`, `GpuStage::cpu`); a decline is `None` from the seam.
- The step's `PrefixStepKey` is untouched — a checkpoint written by either path is a hit for the other.
- One cargo mode: `cargo test --workspace <filter>`; clippy in `target/clippy`. Commits carry **no** `Co-Authored-By`; never push.

## Review Focus

1. **A frame whose sides are not multiples of a level's scale** (an odd crop) — the edge cells hold partial blocks; must match the CPU. Pinned in Task 2 (`odd_sizes_match_the_cpu`).
2. **Subject mode where the Subject map found nobody** (an all-zero alpha) — the twin must take the subject path with zero alpha, exactly as the CPU does. Pinned in Task 2 (the `Subject, empty` parity case).
3. **Cat-eye near the frame's corners** — `pos` clamps; the shift is largest there. Pinned in Task 2 (lights in the corners of the parity scene).
4. **A frame needing two or more levels** (Amount high on a large frame) — the level offsets and the bilinear composite across levels. Pinned in Task 2 (`two_levels_match_the_cpu`).
5. **A device that cannot hold the level buffers** (a huge export) — must decline to the CPU, never hand `create_buffer` an oversized request. Pinned in Task 2 (`fits` unit test).

### Task 1: The shared inputs and a grid-sampled highlight level (`pipeline`)

**Files:** `crates/pipeline/src/stages/lens_blur/{mod.rs,gather.rs,aperture.rs}`, `crates/pipeline/src/prefix.rs`, goldens `crates/pipeline/tests/golden/lens_blur_*.png`.

**Produces:**
```rust
pub struct Inputs { pub focus: f32, pub depth: (Arc<dyn RasterSource>, u64), pub subject: Option<(Arc<dyn RasterSource>, u64)> }
pub fn inputs(lb: &LensBlur, ai: &dyn AiRasters) -> Option<Inputs>;          // stages::lens_blur
pub fn plane_bytes(src: &dyn RasterSource, w: usize, h: usize) -> Vec<u8>;   // row-major, CoverageMap::at
pub fn highlight_level(img: &ImageBuf) -> Option<f32>;                        // gather; None: no finite sample
pub const GRID: usize = 256;
pub fn level_of(c: f32) -> usize;                                             // now pub
pub fn blade_edges() -> [(f32, f32); 3]; pub fn apothem() -> f32;             // aperture, shared with weight()
```
- [ ] Tests first: `the_highlight_level_reads_a_grid` — a 600 × 400 mid-grey frame with 0.5 % of its pixels at 50× → `highlight_level` is the grey's luminance; the same frame downscaled ×2 → the same value within 2 %; a frame of NaN → `None`. `inputs` — the prefix's own tests (`prefix::lens_blur_tests`) must stay green after `lens_blur_step` is rewritten on it.
- [ ] Implement: `highlight_level` samples the pixel nearest each cell centre of a grid with step `ceil(max(w, h) / GRID)`, the 99th percentile of the finite luminances by `select_nth`, floored at `1e-6`; `boost` uses it (`None` → unboosted). `inputs` is `lens_blur_step`'s lookup moved; `LensBlurStage::apply` reads its planes through `plane_bytes`. `weight` reads `blade_edges()` / `apothem()`.
- [ ] The three lens-blur goldens move (Boost 60): re-pin with `UPDATE_GOLDEN=1` only after reading the old-vs-new worst difference, and look at them. Ruling: the reference changes — the highlight level from a fixed grid is cheap at construction AND the same at the preview and the export (dehaze's airlight's reason).
- [ ] Sabotage: the grid step forced to 1 → the downscale assertion still passes (expected — recorded) but the bright-pixels assertion must stay green; sabotage the percentile to the max → red. Commit `feat(pipeline): lens blur's inputs shared, its highlight level from a fixed grid (M10.16d2)`.

### Task 2: `GpuLensBlurStage` and its shader (`gpu-pipeline`)

**Files:** create `crates/gpu-pipeline/src/lens_blur.rs` (the stage, its buffers, its tests) and `crates/gpu-pipeline/src/lens_blur_wgsl.rs` (the shader text); `lib.rs` (`mod`, `pub use`).

**Produces:**
```rust
pub struct GpuLensBlurStage { /* params, l99, depth/alpha bytes, levels: Vec<[u32; 4]> (lw, lh, k, cell offset), cells, cpu: LensBlurStage */ }
impl GpuLensBlurStage {
    /// None: radius under half a pixel, more than MAX_LEVELS levels, or buffers past the device's limit.
    pub fn new(lb: &LensBlur, inputs: &pipeline::lens_blur::Inputs, image: &ImageBuf, ctx: &GpuContext) -> Option<Self>;
}
pub(crate) const MAX_LEVELS: usize = 8;
fn fits(cells: u64, pixels: u64, max_bytes: u64) -> bool; // 48·cells, 32·cells, the packed planes, each ≤ max_bytes
```
- [ ] Tests first (each `let Some(ctx) = ctx() else { return };`): a parity helper runs the CPU `LensBlurStage` and a `GpuChain` of the twin on one scene and asserts **`!compare(input, cpu).is_exact()` first** (shape (c)), then `compare(cpu, gpu).worst_levels < 1.0`. Cases: each of Circle · Blades · Ring · Cat-eye in Subject mode with boost 60 (`each_shape_matches_the_cpu`); Point mode, no subject (`point_focus_matches_the_cpu`); Subject mode with an all-zero alpha (`an_empty_subject_matches_the_cpu`); a 301 × 203 frame (`odd_sizes_match_the_cpu`); a 640 × 400 frame at Amount 100 so `level_of(R) ≥ 1` (`two_levels_match_the_cpu`, asserting the level count first). The scene: a depth ramp, a subject disc, point lights including two in the corners, a near strip. Plus `fits` (a pure unit test: true under, false past each of the three limits), `declines_below_half_a_pixel`, `the_stage_is_named_like_the_cpu_one`.
- [ ] Implement: `new` computes `Params::new(lb, focus, max(w, h))`, `highlight_level(image)`, the levels `0..=level_of(radius_px)` (each `lw = ceil(w / k)`, `k = 2^(l+1)`, cell offsets running), the plane bytes; `encode` packs the bytes into `u32` words, creates the uniform (176 bytes: 12 scalars then `lv: array<vec4<u32>, 8>`), the `src` (12 f32 a cell) and `got` (8 f32 a cell) buffers, one bind group, and dispatches `build_l` for each level, `gather_l` for each level, then `composite` — each over `count.div_ceil(64)` workgroups split 2-D past 65,535 and indexed with `num_workgroups`. The shader is the CPU reference line for line: `radius_at`, `level_of`, `boosted`, `weight` (Blades' edges and apothem, the Ring's area as literals from `aperture`), `area`, `cover` (2 × 2 at the edge), `pos_of` (the padded `lw·k`), the build's row-major block sum and normalisation and norm (footprint below 3 working px), the gather's dy-then-dx-then-layer loop, the composite's level-by-level bilinear taps in the CPU's tap order and its three-layer formula. `cpu_cost` 500 (the spike's 190 ms at 1.7 Mpx is ~760 per 6.8 Mpx; shipped low, the gate's direction).
- [ ] Sabotage: Ring's 0.35 floor → 0.30 in the shader only → `each_shape_matches_the_cpu` red; the composite's taps without the level's offset → `two_levels_match_the_cpu` red. Commit `feat(gpu-pipeline): GpuLensBlurStage — lens blur as compute shaders, matched to the CPU (M10.16d2)`.
