# M10.16b6 — FFDNet as the network, DRUNet in Settings, the full-photo progress line — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** AI denoise runs FFDNet colour by default (GPU engine, CPU path of our own), DRUNet stays a Settings choice, and a quiet "Full denoise" line under Amount shows the whole-photo job.

**Architecture:** A restricted reader turns `ffdnet_color.pth` (PyTorch legacy format) into the weights type the engines already take. FFDNet's pixel unshuffle/shuffle and its σ plane are packed on the CPU (`app::ffdnet`), so the GPU crate only runs a chain of 3 × 3 convolutions — the DRUNet engine's kernel, Winograd and bands, plus a per-channel bias in the store. A `DenoiseNetwork` setting reaches every place that names the network: the factory, the download offer, export, the cache key and the rendered preview's key.

**Tech Stack:** Rust, `wgpu` 29 (WGSL), `rayon`, `egui` 0.35.

**Spec:** `docs/superpowers/specs/2026-10-18-m10.16b6-ffdnet-and-progress-design.md`

## Global Constraints

- The model: `ai_mask::ModelId::FfdnetColor` — file `ffdnet_color.pth`, URL `https://github.com/cszn/KAIR/releases/download/v1.0/ffdnet_color.pth`, **3,411,551 bytes**, SHA-256 `286f04f7e3a20254c067ba95efb5d3339f4fc8a09a365a93cd469184d4cdb279`, licence line *"MIT (FFDNet weights, KAIR) — trained partly on ImageNet images, whose terms say research use only"*, licence URL `https://github.com/cszn/KAIR`.
- The reader executes nothing from the file: globals **only** `collections.OrderedDict`, `torch._utils._rebuild_tensor_v2`, `torch.FloatStorage`; anything else is an error naming it.
- FFDNet: 13 → 96, ten 96 → 96, 96 → 12, 3 × 3 with bias, ReLU after all but the last; input = the tile unshuffled 2 × 2 (channel `c · 4 + dy · 2 + dx`) + one plane of each 2 × 2 block's mean σ / 255; output shuffled back the same order; the output **is** the image.
- Both networks run the noise map × 2 (`ai_denoise::CALIBRATION`, unchanged).
- Cache key recipe: DRUNet keeps `denoise:v2` (its key string byte-identical — the pinned key stays); FFDNet `denoise:v3-ffdnet`.
- Default network: **FFDNet**, for new and existing settings files.
- The progress line: under Amount, **"Full denoise"** in Caption `text2`, a **3 px** line across the section's content width, track `line`, done part `text3`, never the accent, **no percentage**; hover *"Your view is denoised first and the rest of the photo follows in the background"*.
- `docs/DESIGN.md` §7.16 gets one exception line. Hovers: one sentence, no full stop, ≤ 110 chars.
- Repo rules: never push; no `Co-Authored-By`; one cargo mode (`cargo test --workspace <filter>`; clippy in `target/clippy`; `gpu-pipeline`'s own loop in `CARGO_TARGET_DIR=target/gpu cargo test --release -p gpu-pipeline`); no file over 1,000 lines of code; placement per `docs/PARALLEL-WORK.md` §5.

## Review Focus

1. **No usable GPU, or *Use the GPU* off** — FFDNet runs on the CPU path, never `tract` (which cannot read a `.pth`). Pinned in Task 4 (`no_gpu_runs_ffdnet_on_the_cpu`).
2. **A damaged or foreign weights file** — a truncated storage, a foreign global, a misshapen tensor: an error that names it, never a panic. Pinned in Tasks 1 and 2.
3. **The network switched while a job runs** — the old job's result never lands under the new network's key. Pinned in Task 4 (`switching_the_network_drops_the_running_job`).
4. **Tiles at the image's edge and odd sizes** — FFDNet needs even sides; the tiler's overlap (32) must cover FFDNet's ±25 px. Pinned in Task 2 (`ffdnet_tiles_match_one_pass_inside`).
5. **A preview or export asking for FFDNet's result while only DRUNet's exists** — `DenoiseUse::Cached` fails (the build runs later), never borrows the other network's file. Pinned in Task 4 (`an_export_never_borrows_the_other_networks_result`).
