# M10.17b Panorama merge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Photo → Photo merge → Panorama…: a row of 3–6 handheld raws matched, levelled, exposure-matched, cut
along seams that avoid what moved, blended, projected, auto-cropped or edge-filled, and written as a
floating-point `-Pano.dng` (long edge ≤ 16,000 px) that Rustroom opens as a raw of the same camera.

**Architecture:** all stitching lives in `photo-merge` (zero GUI) as new single-purpose modules beside HDR's,
reusing its frames, decode, dense aligner, warp kernel and DNG writer; lens correction goes through `lens-profile`
inside the one resample; the LaMa fill is handed in through a trait so `photo-merge` never depends on `ai-mask`.
The CLI and the app (lib plan/worker, bin dialog/flow) drive it; the HDR flow's queue becomes the queue of both.

**Tech Stack:** Rust workspace; rayon; `lens-profile` (LensFun); M10.17a's `photo-merge`, `export::dng_hdr`,
`raw_decode::float_dng`; LaMa via `ai-mask` (app side only); egui 0.35 for the dialog.

**Spec:** `docs/superpowers/specs/2026-10-27-m10.17b-panorama-merge-design.md` (and M10.17a's,
`docs/superpowers/specs/2026-10-26-m10.17a-hdr-merge-design.md`, which it builds on — read both).

## Review Focus

1. **A portrait row** (camera turned; libraw has already turned the frames upright) — stitches like a landscape
   one, horizon level. → Task 3 `a_portrait_row_is_levelled`.
2. **Perspective chosen by hand on a sweep too wide for it** — the dialog says so and Merge is disabled, never a
   canvas of millions of pixels. → Task 5 `perspective_past_its_limit_is_refused`, Task 13
   `a_too_wide_perspective_disables_merge`.
3. **Fill edges with the LaMa model not downloaded** — the download is offered, Merge with Fill on waits for it
   or merges without the fill and says so; never a panic. → Task 12 `fill_without_the_model_offers_the_download`.
4. **A virtual copy and its original, or a RAW+JPEG pair, in the selection** — one frame, the raw. → Task 12
   `a_virtual_copy_is_one_frame_in_a_panorama`.
5. **Cancel mid-merge, or an HDR queued behind a panorama** — no `-Pano.dng`, no visible partial, the HDR then runs.
   → Task 13 `a_cancelled_panorama_leaves_no_file_and_the_next_merge_runs`.

### Task 3: The rig — rotations, the chain, the global fit, the level

**Files:**
- Create: `crates/photo-merge/src/rotation.rs` (split `rig.rs` off if it passes ~600 lines)

**Interfaces:**
- Consumes: Task 2's `Keypoint`, `matches`.
- Produces:
  - `rotation::Rot(pub [f64; 9])` (row-major, world → camera) with `identity`, `from_axis_angle([f64; 3])`,
    `compose`, `transpose`, `apply([f64; 3]) -> [f64; 3]`.
  - `rotation::Corr { a: usize, b: usize, pa: [f64; 2], pb: [f64; 2] }` (full-size pixels of frames `a`, `b`).
  - `rotation::Sweep` — `enum { Horizontal, Vertical }`.
  - `rotation::Rig { focal_px: f64, size: (usize, usize), rotations: Vec<Rot>, order: Vec<usize> /* the chain, left→right or top→bottom */, reference: usize, sweep: Sweep }`
    with `ray(&self, frame: usize, x: f64, y: f64) -> [f64; 3]`, `pixel(&self, frame: usize, ray: [f64; 3]) -> Option<(f64, f64)>`
    (None behind the camera) and `rescaled(&self, s: f64) -> Rig` (size and focal × s; the half → full step).
  - `rotation::focal_guess(meta: &raw_decode::RawMetadata, long_px: usize) -> Option<f64>` — `focal_mm × crop / 36 × long_px`,
    crop factor from LensFun's camera, else 1.5 for an APS-C `Make` it knows, else `None`.
  - `rotation::fit_pair(a: &[Keypoint], b: &[Keypoint], m: &[(usize, usize)], focal_px: f64, size: (usize, usize)) -> Option<PairFit>`
    — RANSAC on the rotation model (2-point minimal), threshold 3 px at full size, 500 iterations, connected at ≥
    **25 inliers**; `PairFit { r_ab: Rot, inliers: Vec<Corr> }`.
  - `rotation::chain(n: usize, pairs: &[(usize, usize, usize /* inliers */)]) -> Result<Vec<usize>, Vec<usize> /* frames not connected */>`
    — maximum spanning tree on inlier counts; for one row it must be a path (a frame with three strong neighbours
    is a grid: `Err` naming nothing — `MergeError::NotARow`, Task 11); order the path from the end whose frame lies
    left (or top) in the reference's view.
  - `rotation::solve(n: usize, focal_px: f64, size: (usize, usize), corrs: &[Corr], order: Vec<usize>) -> Rig`
    — Levenberg–Marquardt over every rotation (axis-angle, the reference's fixed) and the focal length, Cauchy
    loss, residuals in pixels; the reference = `order[(n - 1) / 2]`; `sweep` from the order's spread.
  - `rotation::level(rig: &mut Rig)` — wave correction: the up vector = the smallest-eigenvalue eigenvector of
    `Σ xᵢ xᵢᵀ` over the frames' x axes (Horizontal) or y axes (Vertical), signed to agree with the reference's up;
    every rotation post-multiplied so up is the world's −y.
