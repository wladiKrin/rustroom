# M10.18a Tethered capture: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task by task.

**Goal:** Shots from a USB camera land in the catalog and on screen as they are taken, and Rustroom
can fire the shutter.

**Architecture:** A new GUI-free crate, `tether`, holds a `Camera` trait, a scripted `Fake` behind
`testing`, a libgphoto2 backend behind `gphoto2`, and a `Session` worker thread that downloads each
new file safely. The app adds `tether_options` (lib, remembered in Settings), plus a bin flow, a
dialog, a status-row slot and the menu commands.

**Tech stack:** Rust, the `gphoto2` 3.4 crate (LGPL-2.1) over the system's libgphoto2, and egui.

**Spec:** `docs/superpowers/specs/2026-10-28-m10.18a-tethering-design.md`

## Global constraints

- No egui outside the bin. No file over 1,000 lines of code and doc.
- Hover text is one sentence with no full stop. The UI follows `docs/DESIGN.md`.
- Test directories come from `test_dir`. A wait for an event has a 120 s ceiling.
- The gate:
  - `cargo test --workspace`
  - `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo fmt --check`
- The camera's card is never written to.

## Review focus

1. **A name already in the folder** (a second session the same day, or a RAW+JPEG pair). It must
   never be overwritten. The tests are `free_name` and the session's.
2. **The cable pulled mid-download.** No `.part` is left looking like a photo, and the session
   ends with the sentence. The test is a fetch error mid-session.
3. **A shot landing while a dialog is open, or in Develop.** In Develop the new shot is opened,
   and nothing is lost behind an open dialog. The test is an app e2e in Develop.
4. **A thread that panics.** It reads as Ended, and the status row is freed. The test uses
   `Session::ended`.
5. **Stop pressed while a download runs.** The file finishes or is dropped, never half-named.
   This is the session's order: rename only after the fetch.

### Task 1: The `tether` crate (core, fake, session)

**Files:**
- Create `crates/tether/{Cargo.toml, src/lib.rs, src/fake.rs, src/session.rs, src/name.rs}`.
- Workspace `Cargo.toml` (members).

**Produces:**
- The trait:

  ```rust
  pub trait Camera {
      fn name(&self) -> String;
      fn wait(&mut self, timeout: Duration) -> Result<Option<CameraFile>, String>;
      fn fetch(&mut self, f: &CameraFile, to: &Path) -> Result<(), String>;
      fn shoot(&mut self) -> Result<Vec<CameraFile>, String>;
  }
  ```

- `pub struct CameraFile { pub folder: String, pub name: String }`.
- `pub type Opener = Box<dyn FnOnce() -> Result<Box<dyn Camera + Send>, String> + Send>`.
- `pub fn free_name(dir: &Path, name: &str) -> PathBuf`.
- `pub struct Session`, with `Session::start(open: Opener, dir: PathBuf) -> Session` and
  `.shoot()`, `.stop()`, `.events() -> &Receiver<Event>` and `Session::ended()` (test).
- The events:

  ```rust
  pub enum Event {
      Connected(String),
      Landed(PathBuf),
      Failed(String),
      Ended(Option<String>),
  }
  ```

- `fake::Fake` (feature `testing`): scripted `Vec<Step>`, where `Step` is `File(name, bytes)`,
  `WaitError(String)` or `FetchError(name)`. It also has a shared `shots: Arc<AtomicUsize>`.
  `Fake::opener(self) -> Opener`.

**Tests (crate):**
- `two_shots_land_under_their_own_names`
- `a_taken_name_steps_to_dash_two_and_leaves_no_part_file`
- `free_name_keeps_a_raw_jpeg_pair_apart_from_each_other` (`A.RAF` and `A.JPG` both stay as they
  are)
- `shoot_reaches_the_camera_and_its_files_land`
- `a_fetch_error_is_failed_and_the_session_goes_on`
- `a_wait_error_ends_the_session_with_its_sentence`
- `stop_ends_the_session`
- `a_camera_that_never_opens_ends_at_once`
- `a_session_thread_gone_without_a_word_reads_as_ended`

### Task 2: The libgphoto2 backend (feature `gphoto2`)

**Files:** `crates/tether/src/gphoto.rs`, CI (`libgphoto2-dev`).

**Produces:**
- `pub fn detect() -> Result<Option<String>, String>` gives the first camera's model.
- `pub fn opener() -> Opener` opens the first camera on the session thread.
- The error sentences pass through `sentence(e)`. "Could not claim the USB device" becomes
  "Another program is using the camera".

**Tests:** `the_claim_error_reads_as_another_program`. The sentence mapping is a pure function. The
real camera is checked in the GUI.
