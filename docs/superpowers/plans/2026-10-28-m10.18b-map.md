# M10.18b GPS and a Map: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan
> task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Library gains a Map view. It shows where the photos in view were taken: the file's
GPS, Immich's location, or one set by hand by dragging onto the map or typing in the location
field, many photos at once.

**Architecture:**
- Locations live in a new per-file catalog table, `photo_location`, with one row per source:
  hand, file and server. The winning row is chosen in SQL.
- Readers fill `Capture.gps`.
- A GUI-free lib holds the projection, the clustering, the place search and the tile fetcher.
- The bin draws the map, with its own tile layer: `walkers` needs egui 0.37, and Rustroom is on
  0.35.

**Tech stack:**
- Rust, egui 0.35, rusqlite.
- libraw (`rsraw::GpsInfo`) for raw files, kamadak-exif for the others.
- ureq 3 for tiles and Nominatim.

**Spec:** `docs/superpowers/specs/2026-10-28-m10.18b-map-design.md`

## Global constraints

- **The original file and its sidecar are never written** with a location. Locations live in the
  catalog only.
- **The winning location:** hand beats file, file beats server. A hand row with NULL lat and lon
  means "removed", and shows no location.
- **(0, 0) from libraw is "no fix"**, read as none.
- Nothing per frame grows with the catalog. Derived map data is keyed on
  `(cat.instance(), cat.change_count())` and the view's identity, as `RailData` is.
- **OSM tiles:**
  - User-Agent `Rustroom/0.1 (+https://github.com/wladiKrin/rustroom)`.
  - At most 2 downloads at once, and only tiles the view shows.
  - A disk cache at `dirs::cache_dir()/rustroom/tiles/<host_slug>/z/x/y.png`.
  - The credit "© OpenStreetMap contributors" is always drawn.
- **Nominatim:** only on Enter, at most 1 request a second, with the same User-Agent.
- Hover text is one sentence with no full stop. No literal font size or `Color32` outside `theme`.
  An icon glyph must be in a bundled font's cmap (the `icons.rs` warning).
- The gate:
  - `cargo test --workspace`
  - `CARGO_TARGET_DIR=target/clippy cargo clippy --workspace --all-targets -- -D warnings`
  - `cargo fmt --check`
- No file over 1,000 lines of code and doc. Test directories come from `test_dir`.

## Review focus

1. **An Immich photo that hasn't been downloaded** (no file on disk). The startup pass must skip
   it, never write a "read, none" row for it, and never overwrite its server location. Test:
   `the_startup_pass_skips_a_file_not_on_disk` (Task 3).
2. **Remove location on a photo whose file has GPS.** It shows no pin, and Undo brings the
   file's pin back. Test: `remove_then_undo_restores_the_files_location` (Task 8).
3. **A move or relink of a photo carries its hand location** (`PER_FILE_TABLES`). Test:
   `a_moved_photo_keeps_its_hand_location` (Task 2).
4. **Clusters near the antimeridian, and zoom 0** with tile indices wrapping. Test:
   `tiles_wrap_at_the_antimeridian` (Task 5).
5. **A RAW+JPEG pair:** the pair is one grid entry, so it is one pin. The located half's position
   is used. Test: `a_pair_is_one_pin_at_its_located_half` (Task 7).

### Task 2: Catalog v15, `photo_location`

**Files:**
- `crates/catalog/src/db/schema.rs`: a v15 step, plus `DROP TABLE photo_location;` added to every
  downgrade test's list.
- `db.rs`: `SCHEMA_VERSION = 15`.
- Create `db/location.rs`.
- `db/moves.rs`: `PER_FILE_TABLES` gains `"photo_location"` (7 entries).
- `restore.rs` and `snapshot.rs`: a deleted photo's restore brings its hand row back.

**Schema:**

```sql
CREATE TABLE photo_location (
  folder_id INTEGER NOT NULL REFERENCES folders(id) ON DELETE CASCADE,
  file_name TEXT NOT NULL,
  source TEXT NOT NULL CHECK (source IN ('hand','file','server')),
  lat REAL,
  lon REAL,
  PRIMARY KEY (folder_id, file_name, source)
)
```

**Produces** (`impl Catalog`):
- `pub fn location_of(&self, photo: &Path) -> Result<Option<(f64,f64)>, CatalogError>` returns the
  winner.
- `pub fn locations_of(&self, photos: &[PathBuf]) -> Result<HashMap<PathBuf,(f64,f64)>, CatalogError>`
  answers only located photos, in one transaction, by one prepared statement.
- `pub fn hand_location(&self, photo: &Path) -> Result<Hand, CatalogError>`, with
  `pub enum Hand { Unset, Removed, At(f64,f64) }`.
- `pub fn set_hand(&self, photos: &[PathBuf], hand: Hand) -> Result<(), CatalogError>` writes
  `Unset` as a deleted row.
- `pub fn set_file_location(&self, photo: &Path, at: Option<(f64,f64)>) -> Result<(), CatalogError>`
  writes the row with NULLs for "read, none".
- `pub fn set_server_locations(&self, rows: &[(PathBuf,(f64,f64))]) -> Result<usize, CatalogError>`.
- `pub fn files_without_location_read(&self) -> Result<Vec<PathBuf>, CatalogError>` lists photos
  with a `photo_capture` row but no `file` row, across the catalog.

**Tests:**
- `hand_beats_file_beats_server`
- `removed_shows_no_location_and_unset_brings_the_file_back`
- `a_moved_photo_keeps_its_hand_location`, through `move_photo`
- `files_without_location_read_lists_each_photo_once_until_read`
- `a_version_fourteen_catalog_gains_the_location_table`
- `locations_of_answers_only_located_photos`

  thread-per-job shape.

**Produces:**
- `pub struct TileFetcher`:
  - `new(root: PathBuf, template: String, fetch: FetchTile, on_done: Arc<dyn Fn()+Send+Sync>)`
