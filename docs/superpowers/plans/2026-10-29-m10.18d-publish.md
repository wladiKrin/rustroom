# M10.18d Publish Services Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Named publish services — a folder or an Immich album — that remember what was exported where, mark a
member Modified when its edits or the service's settings change, and bring the destination in step on Publish.

**Architecture:** Catalog v18 holds services, members and what was published (keyed on `photos.id`, like
collections). A lib module derives each member's state from a fingerprint; the existing `ExportWorker` does the
exporting, now reporting what it wrote per photo; a small lib module clears removed members (folder files it
wrote, album entries), and three new `immich` calls handle albums. The bin adds a rail section, a create/edit
dialog, a `LibrarySource::Publish` view with counts and **Publish N**.

**Tech Stack:** Rust, rusqlite, egui 0.35 (bin only), `ureq` via the `immich` crate.

**Spec:** `docs/superpowers/specs/2026-10-29-m10.18d-publish-design.md`

## Global Constraints

- No egui in `crates/app/src/lib.rs` modules; widgets only in bin modules.
- No source file over 1,000 lines of code and doc (`collections_panel.rs` is 779 — add nothing there beyond a
  call; `batch_export/worker.rs` re-measure before adding).
- Hover text: one sentence, no full stop. DESIGN.md: one accent, no literal font size or `Color32` outside `theme.rs`.
- Tests wait on events under a 120 s ceiling; directories from `test_dir`; every fixture says captured or constructed.
- Nothing per frame grows with a service's members; states derive once per change.
- Immich: uploads ride the upload key (`immich_upload::config`); a staged file is never deleted on an unconfirmed
  upload; **no Immich asset is ever deleted**.
- Never delete or overwrite a file the service did not write itself.
- `PanelSection::Publish` is APPENDED to the enum, never inserted.
- Commits: no `Co-Authored-By` trailer. Tests: `cargo test --workspace <filter>`, never `-p`.

## Review Focus

1. A member published to a folder, whose file the user then edited or replaced by hand → on removal it is left,
   and said (Task 3 `a_changed_file_is_left`).
2. Two members with the same file stem in one service → each keeps its own file across re-publishes; neither
   overwrites the other's (Task 6 `two_stems_alike_keep_their_own_files`).
3. A publish cancelled or with a failed photo → only confirmed photos get a `published` row; the rest stay
   New/Modified (Task 6 `only_written_photos_are_recorded`).
4. An Immich upload that does not confirm → no `published` row, the staged file rescued as export does, the
   album untouched for that photo (Task 4 + Task 6 `an_unconfirmed_upload_is_not_recorded`).
5. A photo moved to another folder after publishing → still Published, not New (Task 1
   `a_moved_photo_keeps_its_published_row`).

### Task 1: Catalog v18 — services, members, published

**Files:**
- Create: `crates/catalog/src/db/publish.rs` (+ `mod publish;` in `db.rs`, re-exports)
- Modify: `crates/catalog/src/db/schema.rs` (v18 gate), `crates/catalog/src/db.rs` (`SCHEMA_VERSION = 18`),
  `crates/catalog/src/snapshot.rs` + `crates/catalog/src/db/restore.rs` (carry members and published rows in
  `CatalogSnapshot::Folder`, the way `memberships` are)

**Interfaces — Produces:**
```rust
pub enum PublishTarget { Folder { path: PathBuf }, Immich { album_id: Option<String>, album_name: String } }
pub struct PublishServiceRow { pub id: i64, pub name: String, pub target: PublishTarget, pub options_json: String, pub count: i64 }
pub enum Place { File { path: PathBuf, size: u64, mtime: i64 }, Asset { id: String } }
pub struct Published { pub fingerprint: u64, pub place: Place, pub at: i64 }
pub struct Member { pub path: PathBuf, pub copy: u32, pub removed: bool, pub published: Option<Published> }
impl Catalog {
  fn create_publish_service(&self, name: &str, target: &PublishTarget, options_json: &str) -> Result<i64, CatalogError>; // a taken name → CatalogError (services are made in a dialog that says so), unlike collections
  fn publish_services(&self) -> Result<Vec<PublishServiceRow>, CatalogError>; // lower(name) order; count excludes removed
  fn update_publish_service(&self, id: i64, name: &str, target: &PublishTarget, options_json: &str) -> Result<(), CatalogError>;
  fn delete_publish_service(&self, id: i64) -> Result<(), CatalogError>; // its rows only
  fn add_to_service(&self, id: i64, photo: &Path, copy: u32) -> Result<bool, CatalogError>; // re-adding a removed member clears `removed`
  fn remove_from_service(&self, id: i64, photo: &Path, copy: u32) -> Result<bool, CatalogError>; // published → removed=1; never published → row deleted
  fn publish_members(&self, id: i64) -> Result<Vec<Member>, CatalogError>;
  fn record_published(&self, id: i64, photo: &Path, copy: u32, p: &Published) -> Result<(), CatalogError>; // upsert
  fn clear_member(&self, id: i64, photo: &Path, copy: u32) -> Result<(), CatalogError>; // member + published rows gone
}
```
Tables: `publish_services(id, name UNIQUE COLLATE NOCASE, kind CHECK IN ('folder','immich'), target TEXT JSON,
options TEXT, created)`; `publish_members(service_id → CASCADE, photo_id → photos.id CASCADE, added, removed,
PK(service_id, photo_id))`; `published(service_id, photo_id, fingerprint INTEGER (u64 as i64 bits), place TEXT
JSON, at, PK(service_id, photo_id))`. Every write bumps `change_count` as the other writers do.

### Task 7: The publish flow (bin)

**Files:** Create `crates/app/src/publish_flow.rs` (bin); modify `crates/app/src/export_flow.rs` (extract
`export_jobs_for(&self, ids: &[PhotoId]) -> Vec<ExportJob>` from `export_jobs`, which then calls it with the
selection), `crates/app/src/shell/mod.rs` (`pump_publish`), the app state (`publisher: Option<PublishRun>`).

`start_publish(service)`: members → fingerprints (edits from `sidecar::load_copy`, the open photo's in-memory
edits) → `plan` → `ExportWorker::spawn` with the service's options, `dest_dir` = the folder (Folder) or

`Collision` with `collision_answer`, shows progress in the status row with Cancel (as export does), and on
`Finished`: `record`, then `clear_folder` or — on a background thread — `sync_album` (stores a new album id with
`update_publish_service`), then the summary in the status row. One run at a time; a second press says so.
