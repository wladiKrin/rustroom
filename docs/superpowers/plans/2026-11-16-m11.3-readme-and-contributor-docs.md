# M11.3 — README and contributor docs: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. ⚠ This project runs plans **inline** (executing-plans) by the author's standing choice.

**Goal:** Rewrite the README as a product page for photographers, add `ARCHITECTURE.md`, `CONTRIBUTING.md` and GitHub templates, split `CLAUDE.md` into public `AGENTS.md` + private `CLAUDE.local.md`, remove the Immich server's address from the tree, and illustrate the README with screenshots taken on a throwaway profile.

**Architecture:** Approach A. Text first (Tasks 1–6), then the author reads it, then one screenshot session on the Mac on a fresh Rustroom profile with the real one renamed aside (Tasks 7–9), then the README is finished with the chosen images and the measured test count (Task 10). Docs have no unit tests: each task's "test" is a check command whose output proves the deliverable, with a positive control wherever the check could pass by finding nothing.

**Tech Stack:** Markdown (GitHub-flavoured, Mermaid), GitHub issue/discussion forms (YAML), `screencapture`, small Swift scripts for window ids and mouse events, `ffmpeg` for the GIF.

**Spec:** `docs/superpowers/specs/2026-11-14-m11.3-readme-and-contributor-docs-design.md` — read it first; this plan does not repeat its reasoning.

## Global Constraints

- **Never push; no `Co-Authored-By` trailer; branch `m11.3-docs`.**
- **No file this plan writes may contain** the Immich server's hostname, the author's email, or a path under the author's home written out in full (use `~`). The hostname is never printed in chat or a commit message; it is found with the pattern `ts\.net`, which matches exactly its 5 lines today (sidecar.rs 1, BACKLOG.md 1, the two 2026-09-24 plans 1 + 2).
- **The README is written as of the public launch:** Windows works, `v0.1` is released. No "Linux first", no "build from source only", no "coming soon". Facts that do not exist yet are marked spots `<!-- fill at v0.1: … -->`.
- **Numbers are measured at writing time, never requoted.**
- **Photographers' words** in the README; developer material at its bottom and in `CONTRIBUTING.md` / `ARCHITECTURE.md`.
- **Only screenshots are committed, never a photo file; every image shows Rustroom's window around the photo** — never a photo cropped out on its own.
- **No screenshot shows:** the author's albums, folders outside the demo folder, a path with the username, a person, the server's address (the Settings window is never photographed).
- **The agent never reads an Immich key** and never reads `settings.json` of the real profile.
- **Anything removed is moved to `~/.Trash/`, never `rm`-ed** — the author empties it.

## Review Focus

1. **A screenshot that leaks** — a file dialog or title showing a path, a status line or error naming the server, an album or folder of the author's, a face. → Task 8 inspects every PNG at full size against a written list before it is saved into `docs/images/`, and Task 9 has the author pick only from inspected ones.
2. **The restore not bringing the real profile back** — Rustroom still running during a rename, a second `rustroom/` created behind the agent's back, the original renamed twice. → Task 7 records `shasum` of the real `catalog.db` before; Task 9 asserts the same sum after, and asserts no Rustroom process at every rename.
3. **"Your photos stay yours" overstating** — Rustroom does go online: AI model downloads (GitHub, Hugging Face), map tiles (OpenStreetMap), place lookup (Nominatim), Immich when configured. → Task 6 lists every HTTP client (`git grep -l 'ureq::' -- crates`: `ai-mask/src/download.rs`, `app/src/tile_fetch.rs`, `app/src/map_view.rs`, `immich/src/lib.rs`) and the README names each, saying none sends your photos anywhere you did not choose.
4. **The session's leftovers in the shared caches** — demo downloads, AI maps and tiles in `~/Library/Caches/rustroom/`. → Task 7 drops a marker file; Task 9 moves only files newer than the marker to the Trash, listing them first.
5. **A broken reference** — a relative link that 404s on GitHub, a code comment pointing at a `PARALLEL-WORK.md` that no longer exists, `CLAUDE.md`'s import not loading `AGENTS.md`. → Task 3's grep for `PARALLEL-WORK` in live files; Task 6's link check over every new Markdown file; Task 2's import check.
