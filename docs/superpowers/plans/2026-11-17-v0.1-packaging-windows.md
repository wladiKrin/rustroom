# v0.1 piece 3a — the icon, the Windows installer, the release workflow: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. ⚠ This project runs plans **inline** (executing-plans) by the author's standing choice.

**Goal:** `Rustroom-0.1.0-windows-x64-setup.exe` — a per-user installer of a self-contained exe with its icon, built by
one script locally and by a release workflow on a tag; the icon for every system; briefs for 3b (Mac) and 3c (Linux).

**Architecture:** One master SVG in `packaging/icons/`, every raster committed beside it. The window icon is decoded
in a lib function (no egui) and handed to eframe by `main`. ONE build script, `packaging/windows/build.ps1`, makes the
installer — the release workflow calls it, so a local build and a release cannot differ.

**Spec:** `docs/superpowers/specs/2026-11-17-v0.1-packaging-windows-design.md`

## Global Constraints

- The icon is the AUTHOR's pick among concepts; nothing derived from it is made before the pick.
- No egui in the lib (`AGENTS.md`); a Windows-only branch is a lib no-op elsewhere or a build-script check of
  `CARGO_CFG_TARGET_OS`; macOS and Linux builds unchanged except the window icon.
- The Inno Setup `AppId` is generated once and never changes.
- Never imitate another product's icon (no "Lr"-style letter tile) — Rustroom's own mark.
- One cargo mode; `CARGO_BUILD_JOBS=4` here; no commit trailer; never push; branch `v0.1-packaging-windows`.

## Review Focus

1. **The exe imports no C++ runtime** — `dumpbin /dependents` lists no `MSVCP140`/`VCRUNTIME140*` after Task 2.
2. **The exe carries its icon and version** — `dumpbin` shows a resource directory; Explorer's Properties show 0.1.0.
3. **An install needs no admin and an uninstall keeps the user's data** — checked by running both.
4. **The tag check refuses a mismatch** — `v0.1.1` against `0.1.0` fails before anything builds.
5. **The window icon is the committed PNG**, decoded once, the right size (a test).

### Task 2: The C++ runtime linked in

**Files:** `.cargo/config.toml`; `CONTRIBUTING.md` (Task 7).

- [ ] `[target.x86_64-pc-windows-msvc] rustflags = ["-C", "target-feature=+crt-static"]`, with a comment.

- [ ] Verify: `dumpbin /dependents` — no `MSVCP140`, `VCRUNTIME140*`, `api-ms-win-crt-*`; the app starts.

### Task 3: Icon files, the window icon, the exe's resources

**Files:** `packaging/icons/*` (rasters, `README.md`); `crates/app/src/app_icon.rs` (lib) + `lib.rs`;
`crates/app/src/main.rs`; `crates/app/build.rs`, `crates/app/Cargo.toml` (a Windows-only build-dependency).

- [ ] Rasterise the master (resvg) to 16–1024 px PNGs; write `rustroom.ico` (16, 24, 32, 48, 64, 128, 256); the
  `README.md` says how to regenerate. `.icns` is 3b's, from these PNGs, on the Mac (`iconutil`).
- [ ] `app_icon::rgba() -> (Vec<u8>, u32, u32)` decodes the embedded 256 px PNG; a test: 256×256, opaque pixels present.
- [ ] `main`: the viewport gets the icon in both branches (the debug-window one too).
- [ ] `build.rs`: when `CARGO_CFG_TARGET_OS == "windows"`, embed the `.ico` and VERSIONINFO (product Rustroom, the
  crate version, `GPL-3.0-or-later`) with `winresource`.
- [ ] Verify: `dumpbin /headers` shows a resource directory; the title bar and taskbar show the icon.

### Task 4: Licences

**Files:** `about.toml`, `packaging/about.hbs`, `packaging/licenses/` (native libraries' and fonts' texts).

- [ ] `cargo-about` generates `THIRD-PARTY-LICENSES.html` for the app's crate graph; `about.toml` lists the accepted

- [ ] `packaging/licenses/`: LibRaw (LGPL-2.1, CDDL), libheif and libde265 (LGPL-3.0), LittleCMS (MIT), Inter (OFL),

### Task 5: The installer

**Files:** `packaging/windows/rustroom.iss`, `packaging/windows/build.ps1`.

- [ ] `rustroom.iss`: `PrivilegesRequired=lowest`, `{autopf}\Rustroom`, x64 only, Windows 10+, Start menu, optional
  desktop shortcut (unchecked), the GPL as `InfoBeforeFile`, `LICENSE` + third-party list + `licenses\` installed,
  `CloseApplications`, launch after install; version from `/DVersion=`; a fixed `AppId`.
- [ ] `build.ps1`: read the version from `cargo metadata`; build `--release -p app`; generate the licence list;
  `iscc`; print the output path and its SHA-256. Fails loudly at each step.
- [ ] Verify: install silently into a scratch folder with no admin; it starts; uninstall; the data folders untouched.
