# v0.1 piece 2 — Windows: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. ⚠ This project runs plans **inline** (executing-plans) by the author's standing choice.

**Goal:** Rustroom builds with a plain `cargo run --release -p app`, passes the gate and runs on Windows; a CI job keeps it building.

**Architecture:** No new crate. `rsraw-sys` is vendored and patched (`vendor/rsraw-sys`, `[patch.crates-io]`); tethering's
libgphoto2 becomes `cfg(not(windows))`; ONE function (`catalog::library_dir`) says where the catalog, thumbnails and
previews live; the console handling is a lib module that is a no-op off Windows, so no reference needs a `cfg`.

**Tech Stack:** Rust, MSVC 2022, LLVM (libclang), vcpkg (libheif), GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-17-v0.1-windows-design.md`

## Global Constraints

- macOS and Linux behave exactly as before, except where a name guard gets stricter (Task 7) — the same names on
  every system, since an exFAT card refuses `?` on a Mac too.
- A Windows-only branch is `cfg(windows)` / `cfg!(windows)` in a **lib** module where it can be, so no bin reference
  needs gating (the lesson of `native_menu`, `AGENTS.md`).
- One cargo mode for the session: `cargo build --workspace`, `cargo test --workspace <filter>`, default features;
  clippy in `target/clippy`. `CARGO_BUILD_JOBS=4` on this machine (no page file); `-j` does not change fingerprints.
- Every command prepends `%USERPROFILE%\.cargo\bin` to `PATH` and sets `VCPKG_ROOT=%USERPROFILE%\vcpkg` (the app's
  shell predates the installs).
- Append, never insert; no file over 1,000 lines; no commit trailer; never push; branch `v0.1-windows`.

## Review Focus

1. **The vendored crate differs from 0.1.1 only by the patch** — Task 2 diffs `vendor/rsraw-sys` against the
   registry copy and the diff is the patch, nothing else.
2. **`cargo fmt --all` reaches local path dependencies** — the vendored crate must not make `--check` fail, nor be
   reformatted (that would bury the patch in a whitespace diff).
3. **The tethering `cfg` is exhaustive** — Windows with the `camera` feature on (the default, and CI's
   `--all-features`) must compile and say "not available on Windows", never "no camera support".
4. **The data folder moves on Windows ONLY** — a test that proves Windows' folder differs from `config_dir()`, and
   that macOS/Linux's is still `config_dir()/rustroom` (shape (c): prove they differ before asserting which).
5. **A console borrowed from the parent must not swallow a redirect** — `Rustroom.exe > log 2>&1` still fills the
   log (checked by use, Task 6).
6. **Gate fixes say where the fault was** — a test that assumed Unix, or code that is wrong on Windows.

### Task 2: `rsraw-sys` vendored and patched

- [ ] Copy `rsraw-sys-0.1.1` from `~/.cargo/registry/src/*/` to `vendor/rsraw-sys`, minus `.cargo-ok` and
  `.cargo_vcs_info.json`; commit it **unchanged** first, so the patch is its own reviewable commit.
- [ ] Patch `build.rs`: drop the `is_like_msvc` panic; `-pthread` only when not MSVC; bindgen blocklists `memcmp`,

- [ ] Root `Cargo.toml`: `[patch.crates-io] rsraw-sys = { path = "vendor/rsraw-sys" }`, `exclude = ["vendor"]`.
- [ ] `VENDORED.md`: the version, the three changes and why, how to take a new release (diff against this copy).
- [ ] Verify: `cargo build --workspace` builds rsraw-sys with **no** warnings; `cargo fmt --all -- --check` still
