# `v0.1` piece 3c — the AppImage: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `Rustroom-0.1.0-linux-x86_64.AppImage`, built on Ubuntu 22.04 by `packaging/linux/build.sh` (locally in Docker,
in the release workflow on `ubuntu-22.04`), that runs on any Linux from 2022 on, decodes HEIC, tethers, and says why
when USB permission is missing.

**Architecture:** Two app changes (lib modules, no egui): `app_bundle` recognises an AppImage, and `tether` names a
missing USB permission from the device node. One build change: an `appimage` cargo feature compiles libheif in, on
Linux only. Everything else is shell: a dependency list shared by Docker and CI, `build.sh` (build, walk, exclude
list, outside-path check, glibc floor, licences, desktop/AppStream, `appimagetool` with update info), a Docker wrapper,
and a release job.

**Tech Stack:** Rust (eframe/winit, `libheif-sys`'s `embedded-libheif`, `gphoto2` 3.4), bash, `patchelf`, `readelf`,
`appimagetool` (pinned, checksummed), `zsyncmake` (via appimagetool's `-u`), `appstreamcli`, Docker `ubuntu:22.04`.

**Spec:** `docs/superpowers/specs/2026-11-18-v0.1-appimage-design.md` (and the brief beside it). Read both.

## Global Constraints

- App id `io.github.wladikrin.Rustroom` — desktop file, AppStream id, Wayland app id. Fixed forever.
- Build base Ubuntu 22.04; release passes `--floor 2.35`; the build FAILS if any bundled ELF needs a newer `GLIBC_`.
- Artifact names: `target/linux/Rustroom-<version>-linux-x86_64.AppImage` and `…AppImage.zsync`.
- Update info string, exactly: `gh-releases-zsync|wladiKrin|rustroom|latest|Rustroom-*-linux-x86_64.AppImage.zsync`.
- Never bundle: libvulkan, libGL*, libEGL, Mesa, libdrm, libgbm, libwayland-*, libX*/libxcb*, libxkbcommon, glibc's
  libraries, ld-linux (AppImage's `excludelist` is the reference).
- libgphoto2 drivers left out: `ax203`, `st2205`, `tp6801`, `docupen`.
- A variable the user set (`CAMLIBS`, `IOLIBS`, `LIBHEIF_PLUGIN_PATH`) is never replaced.
- Status sentences: one sentence, no full stop (`tether::trouble`'s house style).
- x86_64 only. No signing. Rustroom installs nothing on the user's system.
- `AGENTS.md`'s gate on the tip; one cargo invocation mode (`cargo test --workspace <filter>`, never `-p`);
  clippy in `target/clippy`. Commits: no `Co-Authored-By` trailer (the author's rule overrides the harness's).
- Shell, from the Mac's `build.sh` review: every tool's output captured into a variable before use (`x="$(…)" ||
  fail`), never an exit status lost in `< <(…)` or a pipeline; versions compared as numbers; an empty answer never
  passes a check.

## Review Focus

1. **An AppImage run from a path with spaces, or through a symlink** (`~/Apps/My Tools/Rustroom.AppImage`) — the
   folders still resolve; pinned in Task 2's tests.
2. **The user already set `CAMLIBS` / `LIBHEIF_PLUGIN_PATH`** (a distro's own libgphoto2 user debugging) — never
   replaced; Task 2 reuses `to_set` and its test covers the AppImage dirs too.
3. **A camera plugged in with permission granted but some OTHER USB device unwritable** (a webcam, a hub) — no false
   "Linux does not allow" sentence; Task 3's test has a non-camera unwritable device beside a writable camera.
4. **No camera at all with an unwritable non-camera device** — still "No camera found", not the permission sentence;
   Task 3's test.
5. **A machine with no HEVC in libheif** — a HEIC must DECODE in the built AppImage, not just link; Task 5's step
   decodes a real `.heic` through `rustroom-cli` inside the AppImage's own environment.

### Task 3: Tethering names a missing USB permission

**Files:** Create `crates/tether/src/usb_access.rs`; modify `crates/tether/src/lib.rs` (`pub mod usb_access;`),
`crates/tether/src/trouble.rs` (variant + sentence + test), `crates/tether/src/gphoto.rs` (`detect`, `opener`, `say`).
Shape the hook by Task 1's capture — the rule below holds whichever way libgphoto2 behaves.

**Interfaces — Produces:**
- `Trouble::NoPermission`, appended after `Other` (the append rule); `sentence` gives
  exactly `"Linux does not allow Rustroom to use this camera — install libgphoto2's udev rules"`.
- `pub fn blocked_camera(sys_usb: &Path, dev_usb: &Path) -> Option<String>` in `usb_access` — scans
  `sys_usb/devices/*` (sysfs: `busnum`, `devnum`, `product` files; interfaces `*:*/bInterfaceClass`), takes devices
  with an interface of class `06` (Still Image — PTP; a Fuji's) and returns the first such device's `product` (or
  `"camera"`) whose node `dev_usb/<busnum:03>/<devnum:03>` cannot be opened read+write. `None` off Linux
  (`#[cfg(not(target_os = "linux"))]` body) and when every camera node opens.
- `pub fn blocked_camera_here() -> Option<String>` = `blocked_camera("/sys/bus/usb", "/dev/bus/usb")`.
- `gphoto::detect` / `opener`: when no camera is listed, or opening fails with an I/O-class error (per Task 1's
  capture), and `blocked_camera_here()` is `Some`, the error is `sentence(Trouble::NoPermission, "")`. If Task 1 shows
  `detect` lists nothing, `detect` returns `Err(that sentence)` instead of `Ok(None)` in that case.

- [ ] **Step 1: Failing tests** in `usb_access` (sysfs and dev trees built under `test_dir::TempDir`; a node made

  root opens anything — and assert the premise that the 0o444 node indeed fails to open rw first):
  `an_unwritable_camera_is_named` → `Some("X-T4")`;
  `a_writable_camera_is_not_blocked` → `None`;
  `an_unwritable_non_camera_beside_a_writable_camera_is_not_blocked` (class `0e` video, 0o444) → `None`;
  `no_camera_at_all_is_not_blocked` (only the unwritable non-camera) → `None`;
  `a_missing_node_is_not_blocked` (sysfs lists it, `/dev` lacks it) → `None`.
  In `trouble::tests`: `the_permission_sentence_names_the_udev_rules` — contains `udev rules`, no trailing `.`.

- [ ] **Step 1: `deps.txt` + `in-docker.sh`.** Packages: build-essential, curl, pkg-config, clang, cmake, libde265-dev,
  liblcms2-dev, libgphoto2-dev, libraw-dev (if `rsraw-sys` wants it — it is vendored; check), patchelf, file,
  desktop-file-utils, appstream, zsync, plus rustup's stable. `in-docker.sh` installs `deps.txt` and rustup in the
  image (a small Dockerfile or `docker run … bash -c`; the builder's call), then runs `build.sh "$@"`.
  Check: `packaging/linux/in-docker.sh --help` (or a dry stage) runs in the container.
- [ ] **Step 2: `build.sh` — build and AppDir.** `cargo build --release -p app --features appimage` and
  `cargo about generate …`; AppDir: `usr/bin/Rustroom`, `usr/lib/` for libraries, Task 2's three folders
  (`libheif/plugins` empty), the desktop file at the root and in `usr/share/applications/`, icons
  `usr/share/icons/hicolor/{256x256,512x512}/apps/io.github.wladikrin.Rustroom.png` + `.DirIcon`, metainfo in
  `usr/share/metainfo/`. Header comment like the Mac script's: usage, what it needs, what it writes.
- [ ] **Step 3: the walk.** For `usr/bin/Rustroom` and every camlib/iolib `.so` (copied from
  `pkg-config --variable=driverdir libgphoto2` / `libgphoto2_port`, minus the four): resolve NEEDED through `ldd`
  (captured whole), each library either in `excludelist` (skip), already copied, or copied into `usr/lib/` and walked
  in turn; a library in neither list but outside the expected bundle set → keep copying, but the licence map (Step 6)
  fails on it, so every new library is a decision. `patchelf --set-rpath` `$ORIGIN/../lib` on the binary, `$ORIGIN`
  on `usr/lib/*`, `$ORIGIN/../../..` (to `usr/lib`) on the drivers.
- [ ] **Step 4: the checks.** (a) Outside-path: for every ELF in the AppDir, `env -i LD_LIBRARY_PATH= ldd` — every
  resolved path is inside the AppDir or names an `excludelist` library; `not found` fails. (b) GPU stack: no
  `libvulkan`, `libGL`, `libEGL`, `libgbm`, `libdrm`, `libwayland`, `libX`, `libxcb`, `libxkbcommon` under `usr/lib`
  — a separate explicit check, not only the list. (c) The floor: the highest `GLIBC_x.y` over
  `readelf --version-info` (or `objdump -T`) of every ELF; print it; with `--floor`, fail if higher (compared
  numerically, `sort -V`); `--floor` itself validated as `N.N`. Sabotage each once (a fake library outside, a copied
  `libvulkan`, `--floor 2.30`) and see it fail; note the three in the journal.
- [ ] **Step 5: desktop + AppStream.** Desktop: `Name=Rustroom`, `Comment` one line, `Exec=Rustroom %F`,
  `Icon=io.github.wladikrin.Rustroom`, `Categories=Graphics;Photography;`, `MimeType` for the RAW/HEIC/JPEG types it
  opens (from `image_decode`'s and `raw_decode`'s extension lists — the builder's set), `StartupWMClass` = the app id.
  Metainfo: id, name, summary, GPL-3.0-or-later project licence, `metadata_license` CC0-1.0, description from the
  README's first paragraph, `launchable`, `url homepage` the GitHub repo, one `release` 0.1.0. Both validated in the
  script: `desktop-file-validate` and `appstreamcli validate --no-net` — failure stops the build.
- [ ] **Step 6: licences.** `usr/share/licenses/rustroom/`: `COPYING` (the GPL), `THIRD-PARTY.html` (cargo-about), and
  a `case` map from each copied library's soname to its text (from `/usr/share/doc/<pkg>/copyright` of the Ubuntu
  package that owns it — `dpkg -S` — or the libheif source in cargo's `OUT_DIR` for libheif, which is static but its
  LGPL text is still owed; libde265 likewise). Unknown soname → `fail "no licence text for …"`.
- [ ] **Step 7: AppImage.** Download `appimagetool` (a pinned release tag; `sha256sum -c` against a checksum in the
  script) into `target/linux/tools/`; run it with `--appimage-extract-and-run` (no FUSE in Docker) and
  `-u 'gh-releases-zsync|wladiKrin|rustroom|latest|Rustroom-*-linux-x86_64.AppImage.zsync'`; output to the
  artifact names above. `ARCH=x86_64`.
- [ ] **Step 8: proof in the built image.** In the container: `./Rustroom-…AppImage --appimage-extract-and-run` is
  not a GUI test; instead extract (`--appimage-extract`) and run the bundled `ldd` check again on the extracted tree
  (the check after packing), and decode a real `.heic` through the AppImage's libheif — build `rustroom-cli` with the
  same feature into `target/linux-docker` and run it with `LD_LIBRARY_PATH` at the extracted `usr/lib` on a HEIC from
  the author's library (or a public sample whose licence permits; never committed). It must produce an image. If the
  CLI has no HEIC path, give `rustroom` the same feature or, failing that, run `image-decode`'s HEIC tests in the
  container with `--features image-decode/embedded-libheif` — plus `ldd` of the bundled binary as the link proof.
- [ ] **Step 9:** `packaging/linux/in-docker.sh --floor 2.35` end to end on Arch; record sizes and the measured floor.
