# M2.1 — Folder Browser / Library Grid: Design Spec

**Milestone:** Phase 2 / M2.1 — the first "catalog" step. Adds a thin, in-memory folder browser so Rustroom can open a directory of RAWs, show thumbnails, and pick one to edit — instead of opening a single file at a time.

**Status:** Approved design (2026-07-26). Implementation to follow in one plan.

---

## Goal

Point Rustroom at a folder, see a **grid of thumbnails**, and **double-click (or Enter)** a photo to open it in the existing Develop editor. A **Library / Develop** view toggle switches between the grid and the editor.

## Non-goals (explicitly deferred)

Chosen "A" (Library grid ↔ Develop) for M2.1; the eventual target is "C" (Library grid **and** a filmstrip in Develop). Deferred to later milestones:

- Filmstrip strip inside the Develop view (the path to "C").
- On-disk thumbnail cache (reopening a folder re-extracts, in-memory only).
- Edit-accurate rendered thumbnails (M2.1 shows the camera's embedded JPEG).
- Ratings / flags / keywords / metadata columns.
- Sort options, filtering, recursive subfolders (M2.1: flat folder, sorted by filename).
- Any persistent database (M2.1 index is in-memory only).

---

## Decisions (from brainstorming)

- **Thumbnail source:** the camera's **embedded JPEG preview**, extracted via libraw (no demosaic → fast). Consequence: thumbnails show the *camera* rendering, not Rustroom edits — acceptable for browsing; edit-accurate thumbnails are a later refinement.
- **Caching:** **in-memory for the session** only. Reopening a folder re-extracts. Matches the "no DB yet" roadmap.
- **Open flow:** single click **selects**; **double-click or Enter** opens the photo in Develop. (Leaves room for future multi-select / ratings.)

---

## Architecture & crates

- **New `crates/catalog`** — the thin catalog. M2.1 responsibility: `scan_folder(dir) -> Vec<CatalogEntry>` where `CatalogEntry { path: PathBuf, file_name: String }`, filtered to known RAW extensions (case-insensitive), sorted by file name. Pure filesystem logic, unit-testable against a temp dir. This crate is where a DB-backed catalog grows later.
- **`raw-decode`** — add `extract_thumbnail(path: &Path) -> Result<Thumbnail, DecodeError>`, where `Thumbnail { width: usize, height: usize, rgba: Vec<u8> }`. Uses rsraw's `extract_thumbs` to obtain the embedded preview; a JPEG-format thumbnail is decoded to RGBA via the `image` crate; a bitmap-format thumbnail is converted directly. Returns a `DecodeError` if the file has no usable embedded thumbnail.
- **`app`** — a **Library** view and a background **thumbnail loader** thread (same shape as `render_engine`): it extracts + decodes thumbnails off the UI thread and streams `(index, Thumbnail)` results back; the grid uploads each as an egui texture on arrival and requests a repaint, so the grid fills in progressively without blocking.

**Boundaries:** `catalog` knows only files/paths (no image decoding, no egui). `raw-decode` owns thumbnail extraction (no egui). `app` owns the grid view, the loader thread, textures, and selection.

## App view modes (the `main.rs` change)

`RustroomApp` today is only the editor (`session: Option<Session>`). Add:

```
enum AppView { Library, Develop }

struct RustroomApp {
    view: AppView,
    library: Option<Library>,   // present once a folder is opened
    session: Option<Session>,   // the editor (unchanged from M1)
    status: String,
}

struct Library {
    folder: PathBuf,
    entries: Vec<CatalogEntry>,
    thumbs: Vec<Option<egui::TextureHandle>>, // parallel to entries; None = still loading
    selected: Option<usize>,
    loader: ThumbLoader,        // background thumbnail worker
}
```

- Top bar gains **Open folder…** and a **Library / Develop** toggle. The existing **Open file…** (single RAW → straight to Develop) stays.
- The develop-only controls (sliders, crop, export, undo/redo) show only in Develop view; they operate on `session` exactly as in M1.

## Data flow

```
Open folder… (rfd pick_folder)
   → catalog::scan_folder(dir) → entries; thumbs = vec![None; n]; view = Library
   → ThumbLoader::new(entries.paths) spawns a worker that, per entry, calls
     raw_decode::extract_thumbnail and sends (index, Thumbnail) back
Each frame in Library view:
   → drain loader results → upload each Thumbnail as a texture into thumbs[index] → repaint
Grid interaction:
   → click cell = set selected; Left/Right/Up/Down move selected; 
   → double-click a cell OR Enter = open_entry(index):
        raw_decode::decode_raw(path, preview()) → Session (existing open path) → view = Develop
Toggle Library/Develop switches the visible view; the loaded Library persists.
```

## UI (Library grid)

- A scrollable grid (`egui::ScrollArea`) of fixed-size cells (e.g. 160×120), thumbnails aspect-fit within the cell, filename label beneath. A cell shows a placeholder (spinner or gray) until its thumbnail arrives.
- Selected cell is outlined. Arrow keys move the selection; Enter opens it. Double-click opens.
- States: no folder open ("Open a folder to browse."), empty folder / no RAWs found ("No RAW files in this folder.").
- Thumbnails load progressively; the UI stays responsive throughout.

## Error handling

- A file whose thumbnail can't be extracted keeps a placeholder (or a small "no preview" marker); it's still openable (opening does a full decode). One bad file never aborts the folder load.
- Folder scan errors (permissions, missing dir) surface as a status message; the app stays alive.

## Testing strategy

- `catalog::scan_folder` — unit tests against a temp dir (filters extensions case-insensitively, sorts, ignores non-RAW files and subdirs).
- `raw_decode::extract_thumbnail` — a gated integration test (env `RAW_FIXTURE`, like the existing decode smoke test) asserting non-zero dimensions and a non-empty RGBA buffer.
- `ThumbLoader` — a logic test that feeds a couple of paths and confirms results stream back keyed by index (using a fixture or a tolerant skip when none is set).
- Grid view (egui) — compile + clippy + manual smoke run, consistent with M1.4.

Open a folder of RAWs → thumbnails populate progressively → select with mouse/arrows → double-click or Enter opens the photo in the Develop editor → toggle back to the Library grid and pick another. `cargo test --all` / `clippy --all-targets` / `fmt` green; window closes cleanly.
