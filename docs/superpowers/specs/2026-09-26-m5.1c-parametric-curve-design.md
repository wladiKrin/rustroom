# M5.1c — Parametric curve (Highlights / Lights / Darks / Shadows)

**Date:** 2026-09-26 · **Branch:** `m5.1c-parametric-curve` · **Status:** choices made in brainstorm

## What and why

Lightroom's parametric tone curve: four region amounts and three split points, adjusted as
**ranges** rather than points. It is the curve most photographers actually use, because a region
slider cannot kink the curve and needs no point placement.

## Decisions (the author's)

- **A separate representation, like Lightroom** — not sliders rewriting the point curve. ⚠ This
  amends the plan's "done when … without a second representation": a slider cannot be read back
  from hand-edited points, so one representation would leave the sliders unable to show an honest
  value. The plan's line is amended to match.
- **On-curve drag in Parametric mode**, with its own Settings binding.
- **Global only.** Masks keep their composite point curve (by decision since the RGB curves).

## Model (`edit-model`)

```rust
pub struct ParametricCurve {
    pub shadows: f32,     // -100..=100
    pub darks: f32,
    pub lights: f32,
    pub highlights: f32,
    pub splits: [f32; 3], // display-referred x, default [0.25, 0.5, 0.75], strictly increasing
}
```
`Edits.tone_curve_parametric`, `#[serde(default)]`, so an older sidecar loads neutral. It joins the
**Tone Curve** `EditGroups` group, `merge_from`'s destructure and the three exhaustive fixtures.
`is_active()` is true iff any amount is non-zero; the splits alone are modifiers and insert nothing.
Presets, copy/paste, Sync and `changed_parameters` follow from serialisation.

## Math (`pipeline`, one function)

`pipeline::parametric::eval(p: &ParametricCurve, u: f32) -> f32`, in **display-referred** space
(`u` = `linear_to_srgb(x)`), so the regions sit where the widget draws them:
- Region boundaries `0 < s1 < s2 < s3 < 1`. Each amount contributes a smooth bump (raised cosine)
  centred on its region, spanning the region plus half of each neighbour, peaking at
  `amount / 100 * MAX_LIFT` with `MAX_LIFT = 0.15`.
- `y = clamp(u + Σ bumps, 0, 1)`, and the table built from it is made **monotone non-decreasing**
  (a running maximum), so the curve can never fold over.

The stage composes: `out = point_curve(srgb_to_linear(eval(p, linear_to_srgb(x))))`. It is folded
into `ToneCurveStage`'s **composite table**, so there is no new stage, no new GPU code, and the GPU
twin, which uploads the CPU's table, follows by construction. The stage is inserted when the
point curves are non-empty **or** the parametric curve is active, so an untouched curve moves no
golden.

## Panel (`develop/panel/tone_curve.rs`, the bin) and its logic (`tone_curve_tool`, the lib)

- The selector becomes **Parametric | RGB | Red | Green | Blue**.
- Parametric mode: the widget draws the **combined** curve (parametric then composite points),
  with the four regions lightly shaded. Three split handles sit on the bottom edge and are
  draggable, never crossing (minimum gap 0.05). Four sliders sit below.
- **On-curve drag**: a vertical drag inside the widget adjusts the region under the pointer at
  drag start, in the direction of the drag. The rules (which region, how many units per pixel)
  live in the lib as pure functions.
- The point modes draw the combined curve as their ghost line.

## Settings

`ParametricDrag { Left (default), Off }` in `settings.rs`, the `EraseDrag` shape: `ALL`, `label`,
`#[serde(default)]`. It gets a Settings dropdown beside the other drag bindings. `Off` leaves the
sliders as the only route.

## Tests

- `eval` with zero amounts is the identity; the stage with an inactive parametric curve is
  byte-identical (the 78 goldens do not move).
- Each amount moves only its own region's neighbourhood; monotonic for every extreme combination;
  moving a split moves the region.
- A new golden `parametric_curve` (shadows +40, highlights −40).
- GPU parity: the existing whole-chain GPU test's fixture gains a parametric curve.
- Lib tests for the region under a point, the split drag (no crossing) and the drag scaling;
  settings round-trip.
- An app test: a drag in the Parametric widget changes the region under the pointer, and does
  nothing when the binding is `Off`.

## Out of scope

Parametric curves inside masks; per-channel parametric curves.
