# M6.4c — Rendering intents (perceptual / relative colorimetric)

**Date:** 2026-09-26 · **Branch:** `m6.4c-rendering-intents` · **Status:** choices made in brainstorm

## What and why

Out-of-gamut colour is **clipped per channel** today: `OutputTransform` applies one matrix and
`OutputSpace::encode` clamps each channel to `[0, 1]`. That shifts hue (a deep orange goes yellow, a
violet goes blue) and flattens saturated detail. The soft proof and the display conversion use the
same matrix + clamp.

⚠⚠ **LittleCMS cannot supply a perceptual intent here.** It is not in the render path (only in
tests, checking our ICC profiles), and all four of our profiles are **matrix-shaper** profiles,
which carry no perceptual tables — lcms's "perceptual" on them falls back to colorimetric, i.e. the
same clip. The compression has to be ours: a per-pixel function in the working space, a CPU stage
and a GPU twin.

## Decisions (the author's)

- **Canvas + export.** One intent drives the canvas (and the soft proof, and thumbnails); each export
  preset records its own.
- **Method A: hue-preserving compression in Oklab with a precomputed boundary table** (not ACES-style
  RGB compression, which keeps hue only approximately).
- **The default is chosen from crops** of the author's saturated photos (clip / relative /
  perceptual), after both intents work. Relative colorimetric is the provisional default meanwhile.
- **Today's per-channel clip is dropped**, not kept as a third option.

## The maths — `color::gamut` (no GUI, no pipeline)

- `RenderingIntent { Perceptual, RelativeColorimetric }` — `ALL`, `label`, serde.
- `GamutMap::for_space(space) -> &'static GamutMap`, built once per space (`OnceLock`). It holds the
  **target boundary**: the largest Oklab chroma the space holds at each (lightness, hue), on a grid
  (lightness × hue, bilinear lookup, found by bisection at build time), and the **ProPhoto boundary**
  on the same grid — where the source ends.
- `map(intent, working_rgb) -> working_rgb`: lightness and hue fixed, chroma moved.
  - **Relative colorimetric:** a pixel already in the target gamut is returned **bit-identical**;
    outside, chroma is cut to the boundary.
  - **Perceptual:** chroma up to `KNEE = 0.8` of the boundary is unchanged; above it a smooth knee
    (continuous value and slope at the knee, monotone) maps ProPhoto's boundary exactly onto the
    target's. Chroma beyond ProPhoto's boundary maps to the target boundary.
  - Lightness outside `[0, 1]` goes to black/white (chroma 0).
  - **ProPhoto target: the identity** for both intents.
- The existing per-channel clamp in `encode` stays as the float-residue safety net.

⚠ This "relative colorimetric" is a **hue-preserving** clip, not ICC's per-channel clip for matrix
profiles. That is deliberate; it is what the plan's "without hue shift" asks for.

## The pipeline

- `OutputTransform::new(space, intent)`: map → matrix → encode. `RenderSpec` gains `intent`.
- `GpuOutputTransformStage`: the same function in WGSL, the two tables through the per-pixel `Part`
  table mechanism and the Oklab prelude, so it still fuses. Parity for every space × intent.
- `proof_texture` maps into the proof space with the canvas intent; the gamut **warning is
  unchanged** — it marks what lies outside *before* the mapping.

## Where the intent comes from

- **Canvas:** `Settings.canvas_intent`, switched from the **View menu** beside Soft proof (a quick
  A/B). Thumbnails follow the canvas. It enters the render request so a change re-renders; the
  prefix caches are untouched (the intent is tail-only).
- **Export:** `ExportOptions.intent`, a dropdown beside Colour space in the Export dialog, disabled
  for ProPhoto; stored in presets, an old preset loads the default.

## Tests

- Table: every stored boundary colour is in gamut and 1% more chroma is out.
- Map: output in gamut for every space; lightness and hue preserved within a **measured** tolerance;
  relative is bit-identical in gamut; perceptual monotone and continuous at the knee; ProPhoto is the
  identity. Discriminating fixture: a colour in P3 but out of sRGB.
- **Done-when:** a saturated out-of-gamut red to sRGB keeps its Oklab hue under both intents — and
  the test first asserts that the old per-channel clip shifts it, so it can fail.
- GPU parity (every space × intent); preset and Settings round-trips; a menu test that every intent
  is reachable.
- Goldens regenerated for the chosen default; a new `gamut_perceptual` golden.

## Out of scope

Black-point compensation, CMYK/print profiles, user-supplied ICC profiles.
