# M9.12 — Import / ingest — design

**Done when** (Obsidian `03-plan-of-action.md`): photos can be copied from a card to a chosen folder
with a filename template, a metadata preset (copyright included) and a develop preset applied on
entry, plus a second copy to a backup location.

## Decisions taken in the brainstorm (the author's)

| Question | Answer |
|---|---|
| Scope | **The full import dialog** — source, destination, template, metadata, develop preset, backup, then open the result. |
| Destination layout | **Dated subfolders**: `Destination/YYYY/YYYY-MM-DD/<name>`. |
| Which files | **A grid with ticks, new only**: every photo ticked, already-imported ones greyed and unticked. |
| "Metadata preset" | **Remembered fields** (Copyright, Creator, Keywords) — no named preset library. |
| Architecture | **A: an `ingest` module group in the app lib** (no egui) + a modal and a flow in the bin. Declined: a new crate (would first move `filename_template` and presets out of the app lib) and extending the export worker (one worker, two jobs). |

## Lib — `crates/app/src/ingest/` (no egui)

### `ingest::source`
- `pub fn cards(roots: &[PathBuf]) -> Vec<Card>` — every direct child of each root that contains a
  `DCIM` directory (case-insensitive). `Card { name, root }`.
- `pub fn default_roots() -> Vec<PathBuf>` — macOS `/Volumes`; Linux `/media/$USER`,
  `/run/media/$USER`; Windows the drive letters `D:\`…`Z:\` that exist. Injected into `cards` so the
  tests run on a temp tree.
- `pub fn scan(dir: &Path) -> Vec<Candidate>` — recursive walk, `catalog::is_supported` files only,
  hidden files and `.Trashes`/`.Spotlight-V100` skipped, sorted by path.
  `Candidate { path, size, mtime, taken: Option<i64> }` (`taken` filled by the worker, below).

### `ingest::plan`
- `pub fn already_imported(c: &Candidate, known: &KnownSet) -> bool` — `KnownSet` built once from
  the catalog: the `(size, taken)` pairs of every photo, and `(file name, size)` for photos with no
  capture time. A candidate matches on `(size, taken)`; with no `taken`, on `(name, size)`.
- `pub fn day_dir(taken: Option<i64>, mtime: i64) -> PathBuf` — `YYYY/YYYY-MM-DD`, from the capture
  time, else the file's mtime.
- `pub fn destination(root, c, template, seq) -> PathBuf` — `root/day_dir/<rendered name>.<ext>`
  through `filename_template` with `NameFacts` from the candidate (stem, `seq`, `taken`, camera); the
  extension is kept exactly as it was on the card.
- Collision: `batch_export::destination::dest_named`'s `-N` rule, reused, so nothing is ever
  overwritten — including a file an earlier item of the same import just wrote.

### `ingest::copy`
- `pub fn copy_verified(src, dest) -> io::Result<()>` — create the parent, copy to
  `dest.partial-<pid>`, check the written size equals the source's, `rename` into place; on any error
  the partial is removed. The card is only ever read.

### `ingest::worker`
`ImportWorker::spawn(job)` — `batch_export::worker`'s shape: a `std::thread`, an mpsc channel of
`ImportEvent`, an `Arc<AtomicBool>` cancel. Two phases on one thread:

1. **Survey** (starts when the dialog opens a source): per candidate read the capture time
   (`raw_decode::read_capture` / `image_decode::read_capture`) and the embedded thumbnail
   (`raw_decode::extract_thumbnail` / `image_decode::thumbnail`), sending
   `ImportEvent::Surveyed { index, taken, camera, thumb }` as each lands.
2. **Copy** (on Import): per ticked candidate, `copy_verified` to the destination, then to the backup
   if one is set (a backup failure is reported for that file and does not stop the import), then
   `ImportEvent::Copied { index, dest, backup_error }` or `Failed { index, error }`; `Progress{done,
   total}`; `Finished(Summary)` with copied / skipped / failed counts.

The worker only touches the filesystem. **Catalog, XMP and edits are applied on the UI thread** from
`Copied` events, in `import_flow` — where the app's `Catalog` and `PresetStore` already live, so
  the worker needs neither.

### `ingest::options`
`ImportOptions { destination, backup: Option<PathBuf>, template, copyright, creator, keywords,
preset: Option<String> }`, serde, stored as `Settings.import` ("the options the last import actually
used" — `Settings.export`'s rule; no field-level serde defaults, per `settings.rs`).

## On entry (UI thread, `import_flow`)

For each `Copied { dest }`:
- **Catalog**: the destination folder is scanned into the catalog when the import finishes
  (`sources::scan_and_relink` for the destination root), then per photo:
  - Copyright / Creator → `Catalog::set_description`, **only the non-empty fields**, never erasing
    what a later edit set.
  - Keywords (comma-separated) → the existing keyword machinery, created if missing.
  - XMP written through `xmp_sync::write_for` (RAW only — `takes_sidecar`'s existing rule).
- **Develop preset**: `sync::apply([dest], preset.edits, preset.groups)` — the headless
  load → `merge_from` → save that Sync uses. `None` writes no sidecar.
- Then `open_folder_at(first imported day folder)`.

## UI (bin)

- **Entry points:** File → *Import…* (Ctrl/Cmd+Shift+I) and a button in the Library's empty state
  and top bar.
- **`modals/import.rs`** — the export dialog's "copy out, edit locals, apply on change" idiom. Left:
  source picker (detected cards first, then *Choose folder…*), the grid (thumbnail, ticked,
  already-imported greyed with a tooltip saying why), *Check all / Check none / Check new*, a count
  and total size. Right: Destination (folder picker), the template with its token help and a live
  preview of the first name and folder, Backup (checkbox + folder), Copyright / Creator / Keywords,
  Develop preset (combo from `PresetStore::list`, *None* first). *Import* is disabled with a stated
  reason when nothing is ticked, no destination is set, or the destination is inside the source.
- **Progress** in the same dialog after Import: a bar, the current file, *Cancel*; then the summary
  with a *Show* button that opens the folder.
- **`import_flow.rs`** — `start_import`, `pump_import` (each frame, like `pump_export`), `cancel`.

## Error handling

- Source vanishes mid-import (card pulled): each remaining file fails individually; the summary says
  how many; nothing partial is left under a real name.
- Destination not writable / disk full: that file fails with the OS error text; the import goes on
  (a full disk fails the rest the same way — each is reported).
- Destination inside the source, or the same as the backup: Import is disabled with the reason.

## Tests (all on temp trees the tests create; ⚠ counter-suffixed dirs, `immich_list_cache`'s pattern)

- `source`: a fake `Volumes/CARD/DCIM/100MSDCF/*.ARW` tree is a card, a `Volumes/Disk` without DCIM
  is not; `scan` skips hidden and unsupported files.
- `plan`: `(size, taken)` match; name fallback with no capture; `day_dir` from capture and from mtime;
  the destination through a template; a collision gets `-1` and so does a second one within the same
  import.
- `copy`: bytes identical after copy; a failing destination leaves no partial; the source is
  unchanged (mtime and bytes).
- `worker`: a two-file import with backup yields two copies in each place and the events in order;
  cancel stops before the second; a backup failure is reported without stopping.
- `import_flow`: copyright and creator reach the catalog for an imported photo and an empty field
  erases nothing; a develop preset reaches the sidecar; `None` writes none.
- Every fixture is constructed; the real check is an import from the author's card.

## Out of scope

Ejecting the card; converting to DNG on import; renaming by camera-specific counters; deleting from
the card after import (never — the card is read-only to Rustroom); named metadata presets.

## Addendum (2026-09-27, the author's request after first use): the folder layout is a choice

"Whether the import happens into a dated folder should be an option." The author chose **dated
layouts plus one folder**: `ImportOptions.layout: Layout` with
- `YearDay` — `YYYY/YYYY-MM-DD` (the default, unchanged),
- `YearMonthDay` — `YYYY/MM/DD`,
- `Day` — `YYYY-MM-DD`,
- `OneFolder` — the destination itself, or `ImportOptions.subfolder` inside it when non-empty.

`plan::day_dir` becomes `plan::folder(layout, subfolder, taken, mtime)`. The subfolder goes through
`safe_name::sanitize`, the one guard against a name escaping its directory, so `../x` or `a/b` stays a
single folder under the destination. The subfolder applies to `OneFolder` only.
