# M9.9 — Folder tree and move tracking

**Date:** 2026-09-27 · **Branch:** `m9.9-folder-tree` · **Status:** choices made in brainstorm

Plan done-when: *the Folders panel shows real nesting, and a file moved on disk between two known
folders keeps its edits, marks and catalog row instead of appearing as new.*

## Decisions (the author's)

- **Opening a folder scans its subfolders too**; the panel shows the real tree.
- **Clicking a folder shows it and everything beneath** (Lightroom's default).
- **Moves made outside Rustroom are recognised automatically**, reported in the status line. Moving
  photos from inside Rustroom is NOT in this milestone.

## Design

- **`catalog::scan_tree(dir)`**: `(folder, entries)` for `dir` and every subfolder holding images;
  hidden folders and symlinked folders skipped (a symlink can loop). Each folder is synced as today.
- **`Catalog::relink_moved(folder, entries, gone)`**, before a folder's new rows are added: for a
  file new to `folder`, a row in ANOTHER folder with the same file name, size and mtime whose old
  path `gone` reports missing is the same photo. Exactly one → every row keyed on that file moves
  (`photos` — all copies —, `photo_keywords`, `photo_capture`, `photo_description`,
  `photo_history`; collections follow the photo row). Zero or several → new, as today. Returns the
  `(from, to)` pairs. `gone` is the app's filesystem check; the catalog makes none.
- **The app** moves a left-behind `.RAF.json` and `.xmp` beside the photo — never over an existing
  one — and says "Recognised N moved photos".
- **The tree** — `folder_tree` (lib, pure): nodes from the folder paths, each under its nearest
  known ancestor, labelled by the path relative to it, with recursive counts; collapse state per
  session. Clicking re-scans and shows the node's whole subtree. Forget on a parent forgets its
  subtree as one undo step (a `Batch` of `CatalogDelete`s), after the existing confirmation. The
  Immich cache keeps its own row.

## Tests

`scan_tree` recursion and skips; relink keeps marks, keywords, copies, description and history, a
surviving original is a copy not a move, two candidates are refused; sidecars move and never
overwrite; `folder_tree` nesting and labels; the done-when end to end in a temp directory.
