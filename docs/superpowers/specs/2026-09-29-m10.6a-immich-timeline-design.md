# M10.6a — The Immich Timeline at the top of the Immich section

**Date:** 2026-09-29 · **Branch:** `m10.6a-immich-timeline` · **Status:** design approved in brainstorm

The author's to-do (vault `to dos.md`): *"For immich folder, move timeline to the top."*

## Today

`immich_panel::body` draws the album rows first, flat under the section header, then an
`egui::CollapsingHeader` "Timeline" holding the years (`date_rows::branch`) and their months. The
section header's count is the number of albums. The month list (`GET /timeline/buckets`) is asked for
only once the Timeline header is open. ⚠ That header is the only `egui::CollapsingHeader` left in the
Library rail; every other tree uses the rail's own branch row (`DESIGN.md` §7.6).

## Decision (the author's)

**Two peer rows**, Timeline first, Albums second, each a rail tree row with the disclosure triangle and
a count in the rail's column:

```
IMMICH
  ▾ Timeline               11,083
      ▸ 2025                4,210
      ▸ 2024                6,873
  ▾ Albums                     12
      Holidays 2024           872
      Wedding                 214
```

## Behaviour

- **Timeline** — count: the photos on the server, the sum of the month counts; **blank** until the
  month list is in hand. Open, it shows the years and months exactly as today.
- **Albums** — count: the number of albums; blank until the list is in hand. Open, it shows the album
  rows at tree depth 1, with their Download / Remove actions as today.
- The "Loading…" / "Loading albums…" lines, "Nothing on the server" / "No albums on the server" and the
  error line (with Retry, for albums) sit inside each open row, as today. "No server configured" is
  unchanged and replaces both rows.
- **The section header's count is empty**, as the Dates section's is — each row carries its own.
- **Open states.** The Timeline row uses the old header's persisted id
  (`ui.make_persistent_id("immich_timeline")`), so an open Timeline stays open; a new profile starts
  it **closed**. The Albums row is new and starts **open**, so after the update the albums sit where
  they were, one row lower.
- **Loading.** The month list is asked for as soon as the section is drawn open — no longer only once
  the Timeline is opened — so the closed Timeline row can show its count. The albums are asked for as
  today. `body` returns one `Action` per frame: the Timeline's request first, the albums' the next
  frame. Each is guarded by its own flag (`pending_buckets`, `pending_albums`), so neither can drop
  the other; the Timeline checks the **buckets** flag, not `is_listing()`, which is either.
- **Hover**, one sentence each: Timeline *"Shows the server's whole library by year and month"*;
  Albums *"Shows the server's albums"*.

## Placement

- **Lib:** `immich_source::photo_total(buckets: &[immich::Bucket]) -> u64` beside `group_buckets`.
- **Bin:** `date_rows::branch` keeps its signature for the Dates tree and the Immich years, and
  delegates to a new `date_rows::branch_with(ui, id, BranchSpec { name, count: Option<i64>, depth,
  default_open, hover })` — a struct, the project's answer to clippy's argument limit.
  `immich_panel::body` draws the two rows through it. `immich_panel::header_count` is **removed**; its
  one caller in `collections_panel` passes `""`, as the Dates section does.
- **Lib:** `ImmichWorker` gains `is_listing_albums()` and `is_listing_buckets()`, one per flag; each
  row's "Loading…" and its request read its own. `is_listing()` stays for any caller that means either.
- `immich_panel.rs` is 267 code lines; nothing else grows past the ~600 marker.

## Tests

- **`photo_total`:** the sum; zero for an empty list.
- **Rail harness** (`collections_panel` tests, which already seed `immich_albums` / `immich_buckets`):
  - the Timeline row is drawn **above** the Albums row (AccessKit centres);
  - on a fresh context, the album row is drawn with no click (Albums open) and no year row is
    (Timeline closed);
  - the Timeline row's painted count is the sum of the months, and nothing is painted for it before
    the months arrive;
  - with the months unknown and the Timeline closed, `body` asks for them (`Action::RefreshBuckets`);
  - an open state stored under the old id opens the new Timeline row;
  - the existing `every_count_in_the_rail_ends_at_one_x` still passes (it opens the Timeline by name)
    and now covers both new counts.
- **Sabotages:** the rows drawn in the old order; Albums defaulting closed; the Timeline's id changed;
  the month request moved back inside the open Timeline — each must turn a test red.
