# M10.6b — Every clickable control says what it does: hover coverage

**Date:** 2026-09-29 · **Branch:** `m10.6b-hover-table` · **Status:** design approved

Phase 10's M10.6b, recorded at the design language (2026-09-29): *"non-slider hovers are swept but not
tabled"*. Sliders take their sentence from `slider_help` and two coverage tests fail on a mute one;
every other control writes its sentence at the call site (~125 `on_hover_text`, 66 `hover:` fields),
and the only check is a **source** sweep for over-long literals — which cannot see a sentence built with
`format!`, passed in a tuple (the mask row's Disable hover is two sentences that way), or missing.

## Decisions (the author's)

- **Scope: every clickable control** — buttons, icon buttons, checkboxes, toggles, combos, segmented
  controls, list rows (tree rows included), sliders. **Exempt:** menu items (label and shortcut chip),
  text fields (their placeholder), section headers (they only open and close).
- **Approach: one helper and a coverage walk**, not a central table. The sentences stay at their call
  sites (a table would move ~190, many `format!`-built, and still could not know a control exists
  unless something draws it).

## Design

- **The helper** (`theme.rs`, bin): a `Hover` trait on `egui::Response` —
  `.hover(sentence)` sets the widget's **AccessKit description** to the sentence (a no-op when
  AccessKit is off) and shows it as the tooltip; `.hover_titled(title, sentence)` for the slider row's
  elided name (tooltip `title\nsentence`, description the sentence); and `theme::describe(&resp,
  sentence)` for a node whose tooltip lives elsewhere (a slider's rail, whose sentence is on its name).
  ⚠ Screen readers gain every sentence as the control's description.
- **Every non-test `.on_hover_text(` in `crates/app/src` becomes `.hover(`**; `.on_disabled_hover_text`
  stays egui's (a disabled reason, shown only while disabled).
- **The exemptions, made explicit in the tree:** a section header (`develop/panel/section.rs`, both
  sites) sets its AccessKit **expanded** state — correct for a screen reader, and what the walk exempts;
  the in-window menu bar's buttons (`menu_bar.rs`) set **`Role::MenuItem`**; text fields are
  `Role::TextInput`.
- **The walk** — a test-only bin module `hover_coverage.rs`. For each surface state, draw it, read the
  AccessKit nodes, keep the **clickable** ones (the `Click` action) that are not exempt, and fail —
  listing every offender with its surface and label — on a node with **no description** or one that is
  **not one short sentence** (the sweep's rule, now shared as `theme::sentence_fault`). Surface states:
  the Library rail with every section open and Immich configured; the top bar in both views; the
  in-window menu bar drawn directly (so its exemption is exercised on macOS, where the app never draws
  it, not only on the Linux runner); the status row; the Develop panel under Edit (sections and Advanced
  color open), Crop, Masks (one mask of each kind added and selected), Retouch (a patch placed), Presets,
  Snapshots; Settings on each tab; Export with its sections open; Info. A sample assertion (many
  clickable nodes found) comes first. **Not reachable by a harness, and said so in the test:** Compare,
  Survey, the canvas overlays, the Import dialog.
- **Guards:** a source sweep fails on `on_hover_text(` outside `theme.rs`; the literal sweep learns
  `.hover(`.
- **The fix pass:** every offender the first run lists gets one sentence in the house style (the
  Dates and Immich year rows among them); the Disable hover becomes one sentence.

## Tests and sabotages

The walk, the guard and the extended sweep. Sabotages, each red: the helper without the description;
one control's `.hover` removed; the Disable hover back to two sentences; a bare `on_hover_text` in a
bin module; a section header without its expanded state.
