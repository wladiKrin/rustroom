# M10.7a — Bit-reproducible exports

**Date:** 2026-09-30 · **Branch:** `m10.7a-reproducible-exports` · **Status:** design approved

Backlog *"Exports are not bit-reproducible across runs"* (found 2026-09-01 while validating M7.3): two
exports of the same photo with the same settings differ, so *"did this change move any pixel?"*
cannot be answered with `cmp`.

## What was measured before designing

- **One field is the whole cause.** Every exported ICC profile comes from `export::icc_for`, cached per
  colour space per process; lcms2 stamps the header's creation date (`dateTimeNumber`, bytes 24–35)
  with the time the profile is built — a probe read `2026-09-30 08:05:16`. Within a run, exports are
  identical; across runs, they differ there.
- The profile ID (bytes 84–99) is all zeros — lcms2 does not compute one — so nothing else depends on
  the date.
- DNG export embeds no ICC profile and writes no timestamp; the XMP packet's dates are the capture
  date; the PNG, TIFF and JPEG encoders write no time of their own.

## Decision

**Pin the date to a fixed, valid constant**, `export::ICC_CREATED = 2026-08-24 00:00:00` — the day
these profiles were first written into exports (colour management piece B). Not zeros: month 0 and
day 0 are not a valid ICC date and validators flag them, which is the risk the backlog entry asked to
check. Not the capture date: `icc_for` is shared per space and knows no photo, and a profile's creation
is not a photograph's.

## Design

`export::pin_created(icc: Vec<u8>) -> Vec<u8>` writes `ICC_CREATED` into bytes 24–35 (six big-endian
`u16`s) and returns anything shorter than an ICC header (128 bytes) untouched. All four cached
profiles in `icc_for` pass through it.

## Tests

- **Proven different first** (standing lesson (c)): a fresh `lcms2` profile's date is not the pinned
  one; then every `OutputSpace`'s `icc_for` carries exactly `ICC_CREATED`.
- **Only the date moves:** pinning a fresh profile changes some bytes, all of them inside 24–35; a short
  input comes back untouched.
- **End to end:** `every_format_embeds_an_srgb_profile` already asserts the exported JPEG, PNG and TIFF
  embed exactly `icc_for`'s bytes, so they carry the pinned date.
- **The consumer check:** `the_profile_agrees_with_our_own_maths` parses the pinned profile back through
  lcms2 and agrees with our own curves.
- **Sabotages:** a space that skips the pin; the wrong byte range.
