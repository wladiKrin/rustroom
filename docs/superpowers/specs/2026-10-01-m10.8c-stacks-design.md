# M10.8c — Stacks by hand, and stacking by capture time

**Date:** 2026-10-01 · **Branch:** `m10.8c-stacks` · **Status:** design approved

Phase 10's M10.8c: *"stack arbitrary photos by hand, and group by capture time rather than stem
(2026-09-25)"*. Today a stack is a view grouping of same-name files in one folder (or an Immich
server stack), driven by Settings → Appearance → Stacking.

## Decisions (the author's)

- **Right-click and the Photo menu**: Stack (⌘G), Unstack (⇧⌘G).
- **The top photo is the active one when stacking, changeable** with *Make top of stack* — Lightroom's
  model, remembered.
- **Capture time is a command that makes stacks** (Lightroom's Auto-Stack), not a live mode: the result
  is ordinary hand stacks, fixable one by one.

## Design

### The commands

- **Stack** (⌘G) on a selection of two or more **files** (a collapsed row brings every file of its
  stack; virtual copies are never stack members, as today). Per folder — a stack never spans folders.
  A file already in a hand stack brings that stack with it (merge). The active photo's file is the top,
  else the first.
- **Unstack** (⇧⌘G): every hand stack the selection touches comes apart. A name-stack is the setting's.
- **Make top of stack** on a member of a hand stack.
- **Stack by capture time ▸ 1 s · 2 s · 5 s · 10 s · 30 s · 1 min** on the selection, or the whole view
  with fewer than two selected: per folder, sorted by capture time, runs whose consecutive gaps are
  within the choice become hand stacks (top: the earliest). No capture time, no stack. A file it
  re-stacks leaves its old hand stack.
- After every command a hand stack left with **fewer than two** members dissolves.
- **One undo step each**: `ActionKind::StackChange` records every affected file's membership before
  and after; undo writes the befores, redo the afters.

### Showing them

`stack::group` takes the hand stacks too. The key is **a hand stack first** (`(folder, "hand:<id>")`),
then Immich's server stack, then the name — so the badge, collapse/expand, the grid, the filmstrip and
the selection are unchanged. Hand stacks show **whatever the name-stacking switch says** and whatever
formats it lets take part: they were made on purpose. A collapsed hand stack shows its top member.

### Storage

Schema v11: `photo_stacks (folder_id, file_name, stack_id, top, PRIMARY KEY (folder_id, file_name))`.
It joins `PER_FILE_TABLES`, so a move — Rustroom's or noticed — carries it, and the folder snapshot, so
undoing *Forget folder* brings it back. `Catalog::hand_stacks_in(folder)`, `set_hand_stack(photo,
Option<(id, top)>)`, `next_stack_id()`. The `Library` holds the open view's map, loaded with the view and
after every command.

### Placement

Catalog: `db/stacks.rs`, the schema, `moves.rs`, `restore.rs`. Lib: `stack.rs` (the key and `group`),
`stack_by_hand.rs` (stack, unstack, make-top, by-time, tidy — pure). Bin: `stack_ops.rs` (the commands,
the undo replay), `library_state` (the map), `menu`/`commands`/`cell_menu` wiring; `move_flow` shares the
key.

## Tests

- **Catalog:** membership round-trips; a move carries it; forget-then-undo restores it; v11 migrates.
- **Lib:** stacking per folder; the merge; unstack; make-top; capture runs at and over the gap, no-time
  files skipped, several stacks at once; tidy dissolves a stack of one; `group` collapses a hand stack
  to its top whatever the name switch says and keys it before the name.
- **App:** ⌘G through the menu stacks the selection as one undo step and the drawn grid shows one cell
  with the count; unstack; by-time on a folder; a hand stack survives reopening.
- **Sabotages, each red:** the hand key not first; the top ignored; tidy off; the merge off; undo not
  restoring; the stack table missing from `PER_FILE_TABLES`.
