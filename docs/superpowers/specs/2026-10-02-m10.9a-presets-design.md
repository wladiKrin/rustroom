# M10.9a — Develop presets: import/export, folders, rename

**Date:** 2026-10-02 · **Branch:** `m10.9a-presets` · **Status:** design approved

Phase 10's M10.9a: *"Develop presets: import/export, folders, rename (2026-08-25)"*. Today a user preset
is one JSON file in `<config>/rustroom/presets/`, listed flat under *Yours*, applied by a click and
deleted by its `×` into a 20-entry trash that Ctrl+Z restores. Nothing renames, groups, imports or
exports one.

## Decisions (the author's)

- **Rustroom's own JSON** in and out. Lightroom `.xmp` presets are their own later item.
- **One level of folders, like Lightroom's groups.**
- **The full right-click set:** Rename (also a double-click, the keywords' gesture), Update with current
  settings, Move to ▸, Export…, Show in Finder, Delete.

## Design

### On disk

- A top-level `*.json` is a preset with no folder; **each subdirectory is a folder** and its `*.json`
  its presets; an empty folder is an empty directory. Folder names go through `safe_name::folder_name`.
- **The file format does not change** — an exported preset is exactly the stored file, and the folder is
  never written inside it. `Preset` gains `folder: Option<String>`, `#[serde(skip)]`, filled by `list`.
- **A preset is its folder and its name**; names are unique within a folder (Lightroom's model).
  `Preset::key()` is the name, or `"folder/name"` — what Import's preset choice stores (a bare name, as
  saved before, still finds a top-level preset).
- **The trash remembers the folder**: an entry is `{"folder": …, "preset": …}`; an older plain-preset
  entry still reads, as no folder. Restore puts a preset back in its folder.

### The Presets tool

- *Yours*: the presets with no folder, then **each folder as a collapsible header** (`section::header`,
  its count trailing), its presets below. Built-in stays its own group.
- Beside *+ Save current…* a **⋯** menu: *Import presets…*, *New folder…*, *Show presets folder*.
- **Save current…** gains a **Folder** choice (none by default).
- **Right-click a preset**: *Rename* (also a double-click — the row becomes a field, Enter commits,
  Escape cancels), *Update with current settings* (the open photo's edits replace the preset's; its
  groups stay), *Move to ▸* (No folder, each folder, *New folder…*), *Export…*, *Show in Finder*,
  *Delete*.
- **Right-click a folder**: *Rename* (also a double-click), *Import presets here…*, *Export folder…*,
  *Delete folder…* — which asks first; its presets go to the trash.
- **Drag a preset** onto a folder's header, or onto *Yours* for no folder, to move it.
- The `×`'s hover says *"Deletes this preset"* (it said *"Deletes this mask"*).

### The rules

- **Never overwrite.** A rename or move onto a name the folder already has is refused and the status row
  says so; an import's taken name becomes *"Warm 2"*, *"Warm 3"*; an export never replaces a file (it
  takes `-1`, `-2`); a new or renamed folder never takes an existing folder's name.
- **Import** takes one or more `.json` files (the system picker): from ⋯ into no folder, from a folder's
  menu into it. A file that is not a preset is skipped and counted.
- **Export** writes `<name>.json` to a chosen folder; a folder exports as a directory of its presets.
- **One undo step each** — rename, move, update, import, a folder's creation, rename and deletion:
  `ActionKind::PresetEdit { before, after }`, each a snapshot of the touched presets and folders; undo
  removes `after` and writes `before`, redo the reverse. A single delete keeps its trash and
  `PresetDelete`.

### Placement

- **Lib** — `presets.rs` keeps `Preset`, the built-ins and `groups_summary`; the store moves to a new
  **`preset_store.rs`** (folders, rename, move, update, the folder-aware trash, `unique_name`, export
  naming). The old path stays re-exported so callers change little.
- **Bin** — **`preset_ops.rs`** (`impl RustroomApp`: the operations, the pickers, `PresetEdit`'s
  replay); `develop/panel/presets.rs` keeps the section; a new **`develop/panel/preset_rows.rs`** draws
  *Yours* — the folders, the rows, the menus, the double-click rename, the drag; `modals/presets.rs` —
  the Folder choice and `Modal::ConfirmDeletePresetFolder`; `mask_components::row` returns its
  `Response` and takes the `×`'s hover.

## Tests

- **Store:** list with folders; save/delete/restore in a folder; the trash remembers the folder and
  reads an old entry; rename and move refuse a taken name; `unique_name`; export never overwrites;
  folder create/rename/delete; `key` and Import's lookup.
- **App:** each operation is one undo step and redo; the drawn panel shows a folder and its preset;
  a preset's right-click offers the six entries; a double-click renames; a drag onto a folder moves;
  *Update* takes the open photo's edits and keeps the groups; Save into a folder.
- **Sabotages, each red:** overwrite on rename; the folder dropped from the trash; import overwriting;
  undo not restoring a move; the drag ignored; *Update* changing the groups.
