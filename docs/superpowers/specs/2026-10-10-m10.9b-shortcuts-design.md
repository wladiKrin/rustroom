# M10.9b — User-defined keyboard shortcuts

**Date:** 2026-10-10 · **Branch:** `m10.9b-shortcuts` · **Status:** design approved

Phase 10's M10.9b: *"User-defined keyboard shortcuts — the Settings bindings so far are closed enums by
design (`PanDrag`); this is the general version."* Today every shortcut is a default in the menu model
(`menu::model_with`), which the key handler (`shell::keys::pressed_command`), the macOS menu bar
(`native_menu`), the in-window menu bar (`menu_bar`) and Help → Keyboard shortcuts all read.

## Decisions (the author's)

- **Every menu command** can be given a shortcut, the ones without one today included. Culling and
  navigation keys stay as they are.
- **Settings → Keyboard**, a new tab; Help → Keyboard shortcuts stays the read-only reference.
- **A conflict is taken over**: the command you are setting gets the keys, the other loses its shortcut,
  and the row says which.

## Design

### The model (lib)

- `menu::Shortcut` gains **`alt`** (⌥), and every letter, digit, punctuation key and **F1–F12** become
  usable. F-keys are encoded as `char`s in Apple's own range (U+F704 = F1 …), which keeps `Shortcut`
  `Copy` and every `match` on `key` unchanged; `key_name` spells them "F1"… Label order is macOS's,
  `⌥⇧⌘S`; elsewhere `Ctrl+Alt+Shift+S`. `Shortcut` becomes `Serialize`/`Deserialize` (`alt` defaults).
- **`shortcuts.rs`** (new, lib): `Settings::shortcuts: Vec<Rebinding { command: String, shortcut:
  Option<Shortcut> }>` stores **only what was changed**; `command` is the command's stable key
  (`command_key(c)`, its `Debug` form — `SelectTool(Crop)`, `StackByTime(Some(5))`). An entry naming
  no command is ignored, never an error. `menu::model_for(recent, overrides)` is the bound model, the
  **one** every reader uses; `shortcut_of(command, overrides)` reads it.
- `assign(overrides, command, shortcut) -> Option<Command>` takes the chord over (whoever held it, by
  default or override, gets `None`) and returns that command; `reset(overrides, command)`,
  `reset_all`.
- `refusal(shortcut) -> Option<&'static str>` — the reason a chord cannot be chosen: a culling key
  (0–9, P, X, U; bare or with ⇧), ⌘A and ⌘X (select all, cut), macOS's ⌘Q ⌘H ⌘M ⌘W, and the fixed
  chords below. **Fixed rows**: Undo ⌘Z, Redo ⇧⌘Z, Copy settings ⌘C, Paste settings ⌘V — the system's
  edit keys, which the window turns into copy and paste before a key arrives. Navigation keys (arrows,
  Enter, Esc, Delete, Space) are never recorded.
- The `Y` → Compare alias applies only while no bound shortcut uses `Y`.

### The tab (bin, `modals/settings_keyboard.rs`)

- A **search** field; the commands grouped by menu, a submenu item as "Stack by capture time ▸ 5 s";
  each row the label and its **shortcut button** (the chord or "—"). Fixed rows are dark, their hover
  says why.
- **Click the button, press the keys**: Esc cancels, Delete or Backspace clears to none, a refused chord
  says why under the row, a taken one says *"Taken from Stack"*. A changed row has **↺** (its default);
  **Reset all** at the foot.
- In the Settings **draft**, applied on Apply like every other tab; the native menu is rebuilt then.
- ⚠ Esc while recording is taken before the dialog reads it (`dialog` closes on Esc *before* the body
  draws). ⚠ **While recording, the macOS menu's accelerators are off** — a native accelerator is
  consumed before the window sees the key, so ⌘O could not otherwise be recorded; they come back when
  recording ends.

### Everything that shows a chord follows it

- `pressed_command`, `menu_bar`, `native_menu` (its full key mapping, F-keys and ⌥ included; its
  Settings… item reads the binding), Help → Keyboard shortcuts.
- **Hover text** naming a chord (*"Zooms to 100 %… (⌘1)"*, ~10 sites) reads it from the binding and
  drops the parentheses when the command has none; a source sweep keeps a literal chord out of hover
  text.

### Placement

Lib: `menu.rs` (Shortcut, the bound model), `shortcuts.rs` (overrides, refusal, assign). Bin:
`modals/settings_keyboard.rs` (the tab — `settings.rs` is ~865 lines and gets only the draft field and
the tab entry), `shell/keys.rs` (the full egui key map, both directions), `native_menu.rs`, the hover
sites. `Settings::shortcuts` with the exhaustive compat fixture.

## Tests

- **Lib:** an override replaces the default and a `None` removes it; `assign` takes over and returns the
  loser; refused chords; an unknown key ignored; every command's key unique and round-trips; labels
  with ⌥ and F-keys; Settings round-trip.
- **App:** a rebound chord fires its new command and the old chord no longer fires; the alias yields to a
  bound `Y`; the native accelerator map covers every recordable key.
- **Drawn tab:** click a shortcut, press ⌥⌘S → set; a taken chord moves and the note names the loser; a
  refused chord says why; Esc cancels without closing Settings; ↺ and Reset all; Apply persists.
- **Sweep:** no hover text carries a literal chord.
- **Sabotages, each red:** override ignored by the key handler; take-over off; refusal off; Esc closing
  the dialog; the alias winning over a bound `Y`; a hover with a literal chord.

## As built (2026-10-10)

- The per-row reset is a **Reset** button, not ↺ — a glyph not in the bundled fonts' cmap draws as a box
  here, and a word costs nothing.
- The `Y` alias needs no guard of its own: it is consulted only when no bound shortcut matched, so a user's
  own `Y` wins by construction.
