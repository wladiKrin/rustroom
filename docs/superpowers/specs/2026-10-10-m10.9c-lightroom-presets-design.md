# M10.9c — Import Lightroom presets

**Date:** 2026-10-10 · **Branch:** `m10.9c-lightroom-presets` · **Status:** design approved

Phase 10's M10.9c: *"Import Lightroom / Camera Raw `.xmp` develop presets (split from M10.9a by the
author): map each `crs:` setting that has a Rustroom counterpart; the look will not match Lightroom
exactly, since the processing differs."*

## Decisions (the author's)

- **All three formats**: `.xmp` (Lightroom Classic 7.3+, Lightroom, Camera Raw), `.lrtemplate` (the older
  Lightroom Classic format) and **`.zip` packs**, read without unzipping.
- **Each preset lands in a folder named after its own Lightroom group** when imported from ⋯; from a
  folder's *Import presets here…*, all go into that folder.
- **Real files for the tests**, downloaded (below).

## Design

### A new crate, `lr-preset` (no GUI)

Beside `xmp`; depends on `edit-model`, `color`, `quick-xml`, `flate2` (already in the build).

- **`Value`/`Settings`**: a preset's raw settings, `BTreeMap<String, Value>` with `Value::{Num, Text,
  Bool, List}` — one shape both readers produce.
- **`xmp.rs`** — a `.xmp` preset: the `crs:` attributes of its `rdf:Description`, the `crs:Name` and
  `crs:Group` alternatives, and the curve sequences (`crs:ToneCurvePV2012`, `…Red/Green/Blue`, each
  `"x, y"`). A `crs:Look` is recorded as present.
- **`lrtemplate.rs`** — a reader for the Lua table these files are: `key = value`, `["key"] = value`,
  strings (with escapes), numbers, `true`/`false`, nested tables, trailing commas, `--` comments. Name from
  `title` (else `internalName`); settings from `value.settings`. No group (Lightroom kept it in the folder).
- **`zip.rs`** — the central directory and local headers, **stored** and **deflate** entries (`flate2`);
  encrypted, zip64 or other methods are counted, not read. Yields `(path, bytes)`; the readers above take
  each `.xmp`/`.lrtemplate`, and a preset with no group of its own takes the **folder it is in** inside the
  pack (the last folder; a lone top folder from the archive's own name is skipped when it holds folders).
- **`map.rs`** — `Settings` → `Mapped { edits: Edits, groups: EditGroups, left_out: Vec<&'static str> }`.
  - **Groups**: an edit group is carried exactly when the file sets one of its settings — Lightroom
    writes every setting of a group it includes, zeros too.
  - **Same name, same range**: Exposure2012, Contrast2012, Highlights2012, Shadows2012, Whites2012,
    Blacks2012, Texture, Clarity2012, Dehaze, Vibrance, Saturation, HSL (`Hue/Saturation/Luminance
    Adjustment` × Red Orange Yellow Green Aqua Blue Purple Magenta), noise reduction
    (LuminanceSmoothing, LuminanceNoiseReductionDetail, ColorNoiseReduction,
    ColorNoiseReductionSmoothness), the post-crop vignette (Amount, Midpoint, Roundness, Feather),
    sharpening detail and masking.
  - **Converted**: tone curves 0–255 → 0–1; parametric regions and splits (percent → 0–1); colour grading
    (`ColorGrade{Shadow,Midtone,Highlight,Global}{Hue,Sat,Lum}`, Blending, Balance) with Lightroom's
    hue-wheel angle turned into Rustroom's Oklab hue through the colour it names; the older split toning
    onto grading's shadows and highlights and balance; white balance — `Temperature` as Kelvin, `Tint`
    ×100/150, "As Shot" as none; `ConvertToGrayscale` as saturation −100; `Sharpness` capped at 100,
    `SharpenRadius` as is; `LensProfileEnable` on/off.
  - **Left out and named** — only when it would change something: grain (until M10.11b), masks, crop,
    the profile and a creative Look, Auto white balance, a relative (JPEG) white balance, the black &
    white mix, and settings of the pre-2012 process.
- `pub fn read(bytes, file_name) -> Result<Vec<Imported>>` over all three; `Imported { name, group:
  Option<String>, mapped }`.

### In the app

- **Import presets…** (⋯ and a folder's menu) takes `.json`, `.xmp`, `.lrtemplate` and `.zip`.
- From ⋯ a Lightroom preset goes into its group's folder (made if needed, `safe_name::folder_name`);
  from a folder's menu, into that folder. A taken name is numbered. **One undo step**, the made folders in
  it.
- Status: *"Imported 24 presets into 3 folders · left out: grain in 5, the profile in 24 · 1 file was not
  a preset"*.

### Placement

Crate `lr-preset` (`lib.rs`, `value.rs`, `xmp.rs`, `lrtemplate.rs`, `zip.rs`, `map.rs`); the app's
`preset_ops::import_presets` dispatches by extension. ⚠ Nothing in the app crate parses a Lightroom file.

## Test files — real, and where they come from

- **`.xmp`** — presets from **Questtion/Lightroom-Presets** (MIT, the author's own, written by Camera Raw
  17.5), committed with the licence and an attribution note.
- **`.zip`** — GitHub's archive of that repository (MIT): a real zip with folders inside.
- **`.lrtemplate`** — `fixtures/minimal.lrtemplate` from **yuzukumo/LRtemplate2XMPPresets** (GPL-3.0, as
  Rustroom), written by a third party; **and** a local check against Lightroom-written files from
  **xsynaptic/synaptic-lightroom-presets** — no licence file, so **not committed**: an `#[ignore]`d test reads
  them from a path given in `LR_PRESET_SAMPLES`, run once and its result recorded in the journal.
- ⚠ Every fixture says where it came from; none is written by hand here.

## Tests

- **Readers**: the real `.xmp` gives its name, group and the settings it carries; the `.lrtemplate` its
  title and settings (nested curve table); the zip lists its presets with the folder each is in; a broken
  file is an error, never a panic.
- **Map**: on the real files — groups carried exactly, values converted (a known exposure, a curve point, a
  colour-grading hue through Oklab); what is left out named only when non-neutral.
- **App**: importing the real `.xmp` and the real zip — presets in their group's folders, one undo step;
  a junk file counted.
- **Sabotages, each red**: the group from the zip folder ignored; a curve not scaled; the hue not
  converted; a zero grain reported; a broken file panicking.
