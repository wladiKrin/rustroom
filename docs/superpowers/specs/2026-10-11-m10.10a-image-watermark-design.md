# M10.10a — An image watermark

**Date:** 2026-10-11 · **Branch:** `m10.10a-image-watermark` · **Status:** design approved

Phase 10's M10.10a: *"An image watermark (a PNG with alpha) beside the text one (P-26, 2026-09-28)."*
`export::watermark` already draws a text mark — a corner, a size as a share of the long edge, an opacity —
on the display-encoded buffer after output sharpening and before the encode; its own doc names the image
mark as the contained follow-up.

## Decisions (the author's)

- **One or the other**: a Text · Image choice sharing the corner and the opacity.
- **A copy** of the chosen file is kept by Rustroom, so moving or deleting the original changes nothing.
- **Width as a share of the long edge**, 2–50 %, like the text mark's size.

## Design

### The settings (`export::watermark::Watermark`)

- `kind: WatermarkKind { Text, Image }` — **appended**, default Text, so every saved options file and
  export preset reads as before.
- `image: String` — the stored copy's **file name** (empty = none); never an absolute path, so a preset
  carries no machine's layout.
- `image_width: u8`, 2..=50, default 15. `corner` and `opacity` are shared; the text keeps `size`.
- `is_active`: Text as before; Image when a file is named and the opacity is above 0.

### Choosing the image

- Export → Watermark: a **Text · Image** segmented choice. Image shows *Choose image…* (PNG, JPEG, TIFF,
  WebP), the chosen file's name, and a **Width** slider.
- Choosing **copies** the file into `<config>/rustroom/watermarks/` (`watermark_store`, lib): a name already
  there takes `-1`, `-2` — a different logo with the same name never replaces another.
- The section's summary: *"Image · logo.png"*, *"Text · © Me"*, or *"off"*.
- ⚠ `modals/export.rs` is ~796 lines of code: the watermark body moves to **`modals/export_watermark.rs`**.

### Drawing it (export crate, no GUI)

- `Logo::decode(bytes, space)` — decoded **once per export run** on the worker thread (`resolve_looks`'s
  rule), its colours turned from sRGB into the export's space (`srgb_to_linear` → `OutputSpace::from_srgb`
  → `encode`) because the buffer it lands on is already encoded in that space; stored premultiplied.
- Per photo: resized (Lanczos3, premultiplied — no dark fringe) to `image_width` % of the long edge, in the
  corner at the text's margin, composited `dst·(1 − a·op) + rgb·op`. **No drop shadow.** Too big to fit →
  skipped, as the text is.
- `apply(image, mark, logo: Option<&Logo>)`: Text draws as before; Image draws the logo when there is one.
- **A stored copy that is missing or unreadable**: the export still runs and its report says *"the
  watermark image could not be read"* — never a silent export without it (`ExportReport::notes`).

### Placement

Export crate: `watermark.rs` (the settings, `Logo`, compositing). Lib: `watermark_store.rs` (copy in,
unique names), `export_summary`. Bin: `modals/export_watermark.rs` (the body, moved and extended);
`batch_export::worker` (`watermarks_dir`, `resolve_logo`, the note); `export_one` takes the logo;
`export_flow` passes the dir and shows the note; `RustroomApp::watermark_dir`.

## Tests

- **Export crate:** a PNG's transparent hole leaves the photo untouched; opacity scales the blend; width
  follows the long edge; a P3 export moves the logo's red by the sRGB→P3 matrix; a logo that does not fit is
  skipped; a broken file is an error, never a panic; old settings without `kind` read as Text.
- **Lib:** a copy lands in the folder; a second file of the same name gets `-1`.
- **App:** an export with an image watermark changes its corner and nothing else; a missing copy gives the
  report's note; the dialog's switch and summary.
- **Sabotages, each red:** the alpha ignored; the colour not converted; the copy overwriting; the note
  dropped; the logo loaded but not drawn.

Test images are generated by the tests or written by the `image` crate — a watermark is our own artefact,
not a third party's format.
