# M10.10b — Export sizing in cm/in with a PPI, and a file-size target

**Date:** 2026-10-11 · **Branch:** `m10.10b-export-sizing` · **Status:** design approved

Phase 10's M10.10b: *"Export sizing in cm/in with a PPI, and a file-size target (P-26, 2026-09-28)."*
Today the Size section offers one thing — *Fit within a long edge*, in pixels — and ⚠ it shrinks the
**uncropped** decode before the pipeline, so a photo cropped to half its width comes out at about half
the long edge asked for.

## Decisions (the author's)

- **Lightroom's set of size modes**: Width & height, Dimensions, Long edge, Short edge, Megapixels,
  Percentage — lengths in px, cm or in, with a resolution in PPI.
- **A Don't enlarge tick**, on by default; off, a photo is scaled up to reach the size.
- **Too few pixels with Don't enlarge on: the PPI is lowered** so the file still opens at the asked
  physical size, and the status names how many photos fell below the asked PPI.
- **A file-size limit lowers the JPEG quality to a floor of 40, then the pixels**, until the file fits; the
  status says how many were made smaller.

## Design

### The size applies to the final, cropped picture

Before rendering, the photo's final size at full resolution is **predicted** — the prefix steps' own
`output_dims` folded over the decode's size (`pipeline::prefix_output_dims`), no pixels touched. The size
rule turns that into a target in pixels; then:

- **Smaller than the photo** — the linear decode is shrunk (today's path, the right factor now) to the
  smallest size whose predicted output is at least the target, and the render is trimmed to the exact
  target (at most a pixel or two at the edge, where crop rounding lands).
- **Larger, Don't enlarge on** — rendered at full size; the PPI written is lowered (length units only).
- **Larger, Don't enlarge off** — rendered at full size, then enlarged to the target **in linear light**:
  the output encoding undone (`OutputSpace::decode`), Lanczos3, encoded again. ⚠ After the render rather
  than before it: `RenderScale` is capped at 1, and output sharpening then follows the resize, as it
  exists to.

### The settings (`export::sizing`, no GUI)

- `OutputSize { fit: FitMode, unit: LengthUnit, long_edge, short_edge, width, height, megapixels,
  percent, ppi: u16, dont_enlarge: bool }` — each mode keeps its own number, so switching back loses
  nothing; lengths are stored in `unit`, and changing the unit converts them through the PPI.
- `FitMode`: Original · Width & height (W wide, H high) · Dimensions (fits the box either way round) ·
  Long edge · Short edge · Megapixels · Percentage. `LengthUnit`: px · cm · in.
- Defaults: Original, px, long 2048, short 1536, 1920 × 1080, 12 MP, 50 %, **300 PPI**, Don't enlarge on.
- `ExportOptions::size` replaces `max_edge`; ⚠ an options file or preset with `"max_edge": 2048` reads as
  Long edge 2048 px, and `null` as Original (`#[serde(alias = "max_edge")]` and a reader taking either the
  old number or the new map).
- `ExportOptions::limit: FileSizeLimit { on, kb }` — default off, 500 KB; ⚠ **KB is 1000 bytes**, the
  stricter reading, so a file meets a limit whichever a website meant.

### The PPI in the file (`export::density`)

- **JPEG** — the JFIF density (`JpegEncoder::set_pixel_density`), whole pixels per inch.
- **PNG** — a `pHYs` chunk after `IHDR`, pixels per metre.
- **TIFF** — the encoder already writes XResolution/YResolution (1/1) and ResolutionUnit (none); they are
  patched **in place** to the PPI and inches, so no byte moves.
- **DNG** — left alone (not a print format).
- A new `export::encode(image, format, quality, space, ppi) -> Vec<u8>` for the raster formats; `save`
  is that plus a write, and its callers are unchanged. `metadata::with_xmp(bytes, format, meta)` is
  `embed`'s in-memory half.

### The file-size limit (`export::size_limit`)

- JPEG only. The encoder searches the quality from 100 down to 40 in memory, the XMP included in what is
  measured, and keeps the highest that fits.
- Still too big at 40 → the picture is resized smaller **in linear light** from the render *before*
  output sharpening and the watermark (both then redone), by the square root of the overshoot with a
  margin, and searched again; the PPI is kept. Below 16 px, or after 8 rounds, the photo fails with a
  reason.

### The report

`export_one` returns `Written { below_ppi, shrunk }`; the run turns them into notes after the counts:
*"Exported 12, 2 photos below 300 PPI, 1 photo made smaller to fit 500 KB"*.

### The dialog

- **Size** (its body moves to `modals/export_size.rs`; `modals/export.rs` is 787 lines of code):
  *Resize to fit* (the modes), the value boxes with the unit menu, *Resolution … PPI*, *Don't enlarge*, and
  a line giving the size in the other measure — *= 3543 × 2362 px* for cm/in, *= 17.3 cm at 300 PPI* for
  px. ⚠ Not the first photo's own result, as first proposed: its pixel size is unknown until it is decoded.
- **File**: *Limit file size* with a KB box, JPEG only; while it is on, the quality slider gives way.
- Summaries: *30 × 20 cm, 300 PPI* · *2048 px long edge* · *12 MP* · *50 %* · *original*; the File line
  gains *≤ 500 KB*.

### Placement

`pipeline::prefix_output_dims`; `core_image::ImageBuf::downscaled_dims` (the one formula `downscale_to`
and the prediction share). Export crate: `sizing.rs`, `density.rs`, `size_limit.rs`, `encode` in `lib.rs`,
`with_xmp` in `metadata.rs`. App lib: `batch_export/sizing.rs` (the decode size, the trim, the enlarge),
`export_one` and the report's notes, `export_summary`. Bin: `modals/export_size.rs`, the File section's
limit.

## Tests

- **Sizing rules** — each mode on a landscape and a portrait; 30 × 20 cm at 300 PPI → 3543 × 2362;
  Dimensions fits a portrait either way round, Width & height does not; Don't enlarge clamps and lowers the
  PPI (70 cm on 6240 px → 226 PPI) only for length units; unit switching round-trips; the old `max_edge`
  reads.
- **Writing** — 300 PPI read back from the JPEG (JFIF), PNG (`pHYs`) and TIFF (IFD0) bytes, each file
  still decoding; a 200 KB limit lands at or under it with the next quality over it; an impossible one
  reports its size at the floor; resizing in linear light averages light, not code values.
- **Render** — a half-cropped photo at long edge 100 exports at exactly 100 (today 50); cm sizes give
  exact pixels; enlarging reaches the target; Don't enlarge keeps the pixels and flags the PPI.
- **Run** — a limited export's files are all within the limit; the notes for lowered PPI and shrinking.
- **Dialog** — the modes' fields, the unit menu converting, the limit hiding the quality slider.
- **Sabotages, each red** — the prediction ignoring the crop; the trim off; the PPI not written per format;
  the limit not counting the XMP; resizing in code values; Don't enlarge ignored; the old `max_edge`
  dropped.
