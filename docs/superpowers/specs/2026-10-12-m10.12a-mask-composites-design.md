# M10.12a — The flat composite, made usable (nesting parked)

**Date:** 2026-10-12 · **Branch:** `m10.12a-mask-composites` · **Status:** design approved

Phase 10's M10.12a was *"Nested composites — `radial ∩ (brush ∪ gradient)`"*. The brainstorm measured
what the flat composite can already express, and the author re-scoped the item on that evidence.

## What was measured

A mask is a base shape plus refinements folded **top to bottom** with the product algebra
(`MaskOp::combine`), each shape carrying its own Invert, and since 2026-09-29 any row may be dragged
anywhere as long as the top row adds. A brute-force search over every order, every op and every Invert
setting (scratch script, 40 random coverage samples, 1e-9 tolerance) for nine nested expressions:

| Expression | Flat composite today |
|---|---|
| `R ∩ (B ∪ G)` — the item's own example | ✅ `B`, Add `G`, Intersect `R` — exact, partial coverage included, because Intersect is a product |
| `A ∪ (B ∩ C)`, `A − (B ∪ C)`, `A ∩ (B − C)` | ✅ by ordering the rows |
| `A − (B ∩ C)`, `A − (B − C)` | ⚠ only by inverting every shape (De Morgan) — reachable, undiscoverable |
| `(A ∪ B) ∩ (C ∪ D)`, `(A ∩ B) ∪ (C ∩ D)`, `(A − B) ∪ (C − D)` | ❌ unreachable — two compound operands at one op |

The real gap is the last row: **two separately refined areas sharing one adjustment**, which two masks
already do. Lightroom is flat too, as far as found (one Adobe community description: Intersect is a
subtract of the inverted shape, folded onto the whole mask — not verified).

What *does* block the reachable cases in practice, checked in the code: **a row's op is fixed at
creation** — nothing in the panel or `mask_order` assigns `Refinement::op` — so building `B, +G, ∩R`
from a mask that started as the radial means deleting and redrawing it (for a brush, losing the
strokes). And there is **no Duplicate**, the workaround for the ❌ row.

## Decisions (the author's)

- **Build three small things:** change a row's op in place; Duplicate a mask (and Duplicate and invert);
  an **Invert for the whole mask**.
- **Park nesting** in `docs/BACKLOG.md` with the table above. If it is ever built, to **any depth** — one
  level would only be a cap to lift later.
- **The whole-mask Invert is a checkbox drawn for composites only** (or when already on). A one-shape mask
  keeps only its shape's own Invert, so no two controls ever do the same thing.

## Design

### The flag (`edit_model::MaskedAdjustment::invert`)

`pub invert: bool`, `#[serde(default, skip_serializing_if = "std::ops::Not::not")]` — `disabled`'s rule:
a mask that is not inverted writes the bytes it always did, so every sidecar on disk, every preset and
`the_fingerprint_is_stable_across_calls_and_pinned` are untouched, and an old build reading a new
sidecar simply ignores it.

**Meaning:** the mask's coverage is `1 − fold(base, refinements)`, applied **after** the last
refinement and before the adjustments blend. It inverts the composite, not any one shape — each shape's
own `invert` is unchanged and still applies to that shape before it folds. ⚠ Named `invert` like the
shapes' own; its doc comment says which one it is (the AI mask's `threshold` doc already disambiguates
`refine` the same way).

Every struct literal of `MaskedAdjustment` without `..` gains `invert: false` (the compiler lists them).

### The picture — three folds, three traps

The rows are combined in **three** places, and each must apply the flag:

1. **CPU** — `pipeline::stages::mask_coverage::Composite` gains `invert: bool`; `Composite::at` returns
   `1 − a` when set.
2. **GPU** — `gpu_pipeline::mask_wgsl::coverage_entry` gains the flag and emits `a = 1.0 - a;` after the
   last fold; `GpuMaskStage` carries it. The shader text differs, so the pipeline cache keys itself.
3. **The Show-mask tint** — `develop/canvas/mask_tint.rs`'s plane applies `1 − a`.

**(a) The inert-base short-circuit.** `Composite::base_inert_is_enough` lets an unpainted base skip the
whole mask, because Subtract and Intersect preserve zero. **Inverting does not** — an inverted mask whose
fold is zero covers *everything*. It must answer `false` when the flag is set. ⚠ The failure is silent:
the render is the unmasked photograph, the M7.1c hazard exactly.

**(b) The tint's cache and its fast path.** `TintCache` matches on `c.mask == m.mask && c.refine ==
m.refine` — the flag must join the key, or ticking Invert mask leaves the old tint on screen. And the
**lone-brush fast path** (`m.refine.is_empty()` and a brush → `rasterize_in`, bbox-bounded) ignores
everything but the brush: under the flag it rasterises **a clone of the brush with its own `invert`
flipped** — exact, since for one shape the two inverts are the same coverage, and it keeps the bbox and
the `outside` surround an inverted brush already uses, so the commonest tint costs what it always did.

**(c) The prefix's two shape projections.** Masked noise reduction and dehaze (`capture_projection`) and
masked defringe (`defringe_projection`) each copy the mask's **shape** into a `MaskedAdjustment` that is
both what the prefix step is built from and its cache key. Both must carry `m.invert`, or toggling it
changes what the masked capture corrections cover while the cached checkpoint stays valid — a stale
picture at native zoom. Both are struct literals without `..`, so the compiler forces the line;
what it cannot force is `m.invert` rather than `false`, which a test pins.

What the flag does **not** touch: the brush coverage cache (per-component maps, keyed on the brush —
the invert applies after the fold) and the GPU's per-component uploads (same reason).

### The panel

**Logic — a new lib module `crates/app/src/mask_actions.rs`, no egui** (the `mask_order` pattern):

- `set_op(m, j, op) -> bool` — row `j`'s op; `false` (no edit) for `j == 0` (the base has no op: it is
  the Add everything folds onto), an out-of-range `j`, or the op it already has.
- `duplicate(masks, shown, selected, i, invert) -> bool` — a copy of mask `i` inserted at `i + 1`,
  `shown` kept index-aligned with its new entry **on** (what the panel does for a mask it adds itself),
  `selected` set to the copy. With `invert`, the copy's whole-mask inversion is flipped by
  `flip_whole_invert`. A copy keeps everything, `disabled` included.
- `whole_invert_drawn(m) -> bool` — `!m.refine.is_empty() || m.invert`: the checkbox shows for a
  composite, and for a mask left with one shape while its flag is still on, so a live flag is never
  hidden.
- `flip_whole_invert(m)` — flips `m.invert` where the checkbox is drawn, the shape's own `invert_mut()`
  otherwise. On a one-shape mask the two are the same coverage, so this is exact either way, and it is
  what "Duplicate and invert" means wherever it is used.

**Gestures — the bin:**

- **A component row's right-click menu** (`mask_components::rows`): *Add*, *Subtract*, *Intersect* as
  radio items, the current op selected (DESIGN §7.13). Not offered on the base row. One
  `Edited::discrete` when `set_op` returns true.
- **A mask row's right-click menu** (`masks::list`): *Duplicate*, *Duplicate and invert*. One
  `Edited::discrete`; the copy's first row selected (`selected_component = 0`), `active_mask_handle`
  cleared.
- **"Invert mask"** — a checkbox under the component rows, when `whole_invert_drawn`. Hover: *"Inverts the
  whole mask so it covers what its shapes leave out"*. One edit.

The precedent is the presets' and snapshots' row menus (`preset_rows.rs`, `snapshots.rs`), read from
`RowOut::response`. Menu items are exempt from the hover sweep (DESIGN §8); the checkbox is not.

⚠ `develop/panel/masks.rs` is 1,122 lines with its tests (~560 before them) and
`mask_components.rs` 761 (~540) — both under the 1,000-line ceiling; re-measured with
`code_and_doc_lines` before adding, and reported.

## Tests

- **edit-model** — the flag round-trips; absent from the JSON when false; a sidecar without it reads
  `false`; the fingerprint test unchanged.
- **pipeline**
  - `Composite::at` with the flag is exactly `1 −` the same composite without it, over a ramp.
  - The inert-base trap: an unpainted-brush base, no Add refinement, flag on → covers everything.
    Sabotage: drop the flag clause from `base_inert_is_enough`; the test must fail.
  - Both prefix projections carry the flag: the key differs when only `invert` differs, for a masked NR
    and for a masked defringe. Sabotage: `invert: false` in one projection.
  - One golden: an inverted composite (`goldens` stay byte-identical otherwise), with the guard that it
    differs from the same composite uninverted.
- **gpu-pipeline** — `every_fold_renders_the_same_picture` (or a sibling) gains an inverted composite;
  sabotage: the shader skips the flip.
- **app, lib** — `mask_actions`: `set_op` refuses the base, out of range and the same op; `duplicate`
  inserts below, keeps eyes aligned, selects the copy, keeps `disabled`; `flip_whole_invert` picks the
  shape on a one-shape mask and the flag on a composite; `whole_invert_drawn` both ways.
- **app, tint** — an inverted composite's tint is the inverse at a probe point; toggling the flag
  re-tints (the cache trap); a lone brush with the flag on tints its outside.
- **app, panel** (the egui harness) — the component row's menu changes the op as one edit and is absent
  on the base row; Duplicate and Duplicate and invert through the mask row's menu; the checkbox drawn only
  per `whole_invert_drawn` and wired to the flag. `hover_coverage` and the hover sweep stay green.
