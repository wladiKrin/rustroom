# M10.19c — Mark several folders, forget them from a right-click menu

**Date:** 2026-10-12 · **Branch:** `m10.19c-folder-marks` · **Status:** design approved

Found in use, 2026-10-12: another app's thumbnail cache (`~/Pictures/LightCraft Library/thumbs/00…ff`)
was scanned in with `Pictures` — 180 folders, each its own row with no parent row, so removing them
took one × and one confirmation **per folder**. (They were removed from the author's catalog the same
day through `Catalog::forget_folder`, a backup taken first.) The author asked for a way to mark several
folders at once and remove them all from a right-click menu. Phase 10's *found in use* group, built
now at his request.

## Decisions (the author's)

- **"Delete" means Forget from the catalog** — what a row's × does today: catalog rows only, files on
  disk untouched, undoable. Never the files themselves.
- **Marks are for actions only.** The grid is unchanged: a plain click opens one folder, as now.
  Lightroom's union-of-folders view was offered and not chosen.

## Design

### Marks (`crates/app/src/folder_marks.rs`, lib, no egui)

A set of folder **paths** plus an anchor — keyed by path, not by row index, because rows move whenever
a parent collapses or a folder is added. The gestures are the Dates section's own
(`smart_sources::click_period`): ⌘ toggles, ⇧ extends a range anchored on the last non-⇧ click.

- `click(path)` — the marks become `{path}`; the anchor moves there.
- `toggle(path)` — ⌘-click: add or remove; the anchor moves there.
- `extend_to(path, order)` — ⇧-click: every folder from the anchor to `path` inclusive, in `order`, the
  rail's visible order (`folder_tree::build`'s output). The anchor stays. With no anchor, as a click.
- `follow(open)` — called once per frame with the folder the Library shows (`None` for anything else):
  **when that changes, the marks reset to it** (`{open}`, or empty). So opening a folder by a plain click
  marks exactly it, opening All Photos or a collection clears the marks, and a mark can never outlive
  the context it was made in. ⌘/⇧-clicks never open anything, so they do not reset.
- `retain(existing)` — drops marks for folders that no longer exist (after a forget, a relink).
- `targets(row)` — what a right-click on `row` acts on: **every mark** when `row` is marked and more
  than one is, else `[row]` alone. A right-click on an unmarked row never acts on the marks.
- `roots(paths)` — the paths with any path beneath another removed: forgetting a parent already takes
  its subtree, so a marked child under a marked parent is not counted or forgotten twice.

### The rail (`folder_rows.rs`)

- A row is tinted (`RowSpec::selected`) when it is marked **or** open — the one accent, DESIGN §2.
- A click reads the modifiers: ⌘ → `toggle`, ⇧ → `extend_to`, plain → `Out::Open` (and `follow` marks
  it next frame). A click on the disclosure triangle stays a toggle of the tree, as now.
- **The right-click menu** (`RowOut::response.context_menu`, the presets' and snapshots' precedent):
  one item, **"Forget folder"** — or **"Forget N folders"** when `targets(row)` has more than one —
  giving `Out::Forget(paths)`. The × gives `Out::Forget(vec![path])`, so there is one path, not two.
- The marks live beside `folders_collapsed` on the app (`folder_marks`), view state like it.

### Forgetting (`sources.rs`, `modals`)

- `forget_folders(ctx, paths)` replaces `forget_folder(ctx, id, path)`: the subtree ids of every root in
  `roots(paths)`, deduplicated, each forgotten, **one undo step** (`ActionKind::Batch`, as today for a
  parent and its children), and the Library closed if it showed any of them — the existing
  "what is on screen" handling, applied per root. The marks are cleared.
- The confirmation dialog generalises: `Modal::ConfirmForgetFolders { paths, folders, photos }`.
  One folder reads as today (*"Forget folder?"*, its path, its photo count); several read
  *"Forget N folders?"* with the folder and photo totals and the same *files are untouched* sentence.
- ⚠ **A stale comment, corrected:** `confirm_forget_folder`'s doc says forgetting has neither a trash
  nor an undo; `sources.rs`' `forgetting_a_parent_forgets_its_subtree_as_one_undo_step` proves the undo.
  The dialog stays (a large forget is still worth a sentence first); the comment states the real reason.

## Tests

- **`folder_marks`** — click, toggle, a ⇧ range in visible order and its anchor staying put, ⇧ with no
  anchor, `follow` resetting only on a change of the open folder, `retain`, `targets` for a marked row
  among several / a marked row alone / an unmarked row, `roots` dropping a nested path.
- **The rail** (the egui harness, `folder_rows`) — ⌘-click marks without opening; ⇧-click marks a range;
  the right-click menu reads "Forget 2 folders" on a marked row and "Forget folder" on an unmarked one;
  choosing it gives `Out::Forget` with exactly those paths.
- **Forgetting** — two marked folders (one nested under the other's sibling) forget in one step and one
  undo brings every one back; a nested mark is not forgotten twice; the dialog's totals.
- The hover sweep and `hover_coverage` stay green (menu items are exempt; nothing new needs a hover).

## Out of scope

A union view of several folders; marking from the keyboard (⌘A, Esc); forgetting anything other than
folders this way; deleting files on disk.
