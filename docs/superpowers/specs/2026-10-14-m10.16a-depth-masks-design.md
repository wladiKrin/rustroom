# M10.16a — Depth masks: an estimated depth map and the Depth range mask — design

**Date:** 2026-10-14 · **Branch:** `m10.16a-depth-masks` · **Status:** design approved in the
brainstorm, spec awaiting the author's review

Phase 10's M10.16a: *"Depth masks (2026-08-26). L"* — the AI tools, where *"the `ai-mask` crate's
`tract` runtime and model registry are the shared half"*.

**Done when:** any photo's background (or foreground) can be masked by distance without a stroke —
the band set by sliders or by dragging over the photo — and the estimated depth can be seen; an AI
component (Subject, Selection, Depth) covers in a mask's Noise reduction, Dehaze and Defringe; the
model's licence permits redistribution alongside a GPL-3.0 program.

## Why the depth is estimated

Lightroom's Depth Range mask exists only for photos that **carry** a depth map (iPhone portrait-mode
HEIC). Rustroom cannot read HEIC (M10.19a), and the author's cameras record none — so the depth is
estimated from the picture by a monocular depth network. It is **relative**: an order of nearer and
farther, not metres.

## §1 The edit model

- **`Mask::Depth(DepthRange)`**, **appended** to `Mask` (externally tagged — every sidecar on disk
  still loads; `docs/PARALLEL-WORK.md` rule 3).
- ⚠ **Not another `AiPrompt`.** An `AiMask` carries a Refine `threshold`, which means nothing for
  depth; a separate variant keeps "a depth prompt with a threshold" unrepresentable.
- **`DepthRange { near, far, feather, invert }`**, in `edit-model/src/mask_ranges.rs` beside
  `LuminanceRange`:
  - `near`, `far` — 0..=100, the edges of the fully covered band, **0 the nearest point in the photo,
    100 the farthest**. Sorted rather than trusted, as the luminance range's are.
  - `feather` — 0..=100, the luminance range's smoothstep idiom and scale.
  - `invert` — as every shape.
  - **One band function.** `LuminanceRange::coverage`'s band is lifted into a private
    `mask_ranges::band(x, low, high, feather)` that both call — bit-identical for the luminance range
    (its goldens and its GPU twin's parity guard it).
  - `DepthRange::coverage(position)` takes the map's value, 0..=1, scaled to the band's 0..=100.
- **Default: the far half** — `near 50, far 100, feather 50`, hand-written (`RadialGradient::default`'s
  reason: a derived default gives a partial sidecar a zero-width band). A visibly-a-mask start aimed at
  the commonest use, the background; Invert is one click to the foreground.
- `label()` → **"Depth"**; `invert_mut` → its flag; `analytic_coverage` → `None` (a raster).
- A new predicate **`Mask::reads_a_map()`** — `Ai` and `Depth` — replaces every
  `matches!(k, Mask::Ai(_))` asked as "does this component wait for a map".
- It rides the `masks` group; `merge_from`'s destructure and the three exhaustive fixtures gain it.
- **No pixels in the sidecar.** The map lives in the AI cache.

## §2 The depth map

### The model and the runtime
- `ModelId::DepthAnythingV2Small` → the dynamic ONNX above, licence "Apache-2.0 (Depth Anything V2
  Small, code and weights)", licence URL `https://github.com/DepthAnything/Depth-Anything-V2`.
  ⚠ The SHA-256 is **measured from the downloaded file** and copied verbatim, never typed — the
  registry's own rule.
- ⚠ `ModelId::ALL` is a hand-written list — the shape *"a guard that enumerates a list stops guarding
  the moment the list grows"*. An exhaustive `match` in a test forces every variant into it.
- `ai_mask::depth` (a new module): `Depth::load(path)` and `Depth::run(&RgbImage) -> ProbMap`, through
  `tract`. ⚠ `tract` needs concrete input facts, so a plan is built per input size and kept (the SAM
  decoder's precedent); the spike measures what a build costs.
- Downloaded on first use through the existing dialog, which lists the one file, its size and licence.

### What the network sees
- The decode, **upright** (`Orientation::rotate`; the M9.13 sideways-mask trap), sRGB 8-bit and
  exposure-normalised — `ai_worker::model_input`, which gains a long-side parameter — with a film
  negative shown as its positive (M10.11a). ImageNet mean/std, NCHW, **both sides multiples of 14**,
  the aspect kept.

### From the network's answer to the stored map
1. **Normalise** (`ai-mask`, pure): the output is relative **disparity** (near is large). Between robust
   percentiles of the photo's own disparities it becomes a **position, 0 nearest … 1 farthest**,
   clamped — so a stray pixel cannot claim the whole scale.
2. **The scale** — linear in disparity, or equalised (each step of the slider an equal share of the
   photo's pixels) — is the author's choice from the spike's renders (§5). Linear disparity crowds all
   distant things into the last few percent; equalised spreads them.
3. **Snap** (the app — `ai-mask` keeps no `pipeline` dependency): `pipeline::spatial::guided_filter`,
   guided by the photo's luminance, pulls the network's soft depth edges onto the photo's edges —
   exactly what Dehaze does to its transmission map. When the spike picks a stored size above the
   inference size, the snap is a guided **upsampling** to it.
4. **Store** a `ProbMap` (0..=255) in **decode space** at most 2048 px long (its size from the spike):
   valid through every crop, rotation and lens change; only the decode — or the negative —
   invalidates it. Rotated back from upright before it is stored.

### The cache
- `ai_cache::key(photo, ModelId::DepthAnythingV2Small, <query "depth:v1">, negative)`. The version in
  the query string is the **recipe's** — bumped when the scale, the snap or the size changes, so a
  changed recipe recomputes instead of reading a stale map.
- In the app, the map store's key widens from `AiPrompt` to **`ai_coverage::MapQuery { Prompt(AiPrompt),
  Depth }`**; `prompts(edits)` becomes `queries(edits)`, `model_for` takes a query.
- ⚠⚠ **The Subject and Click keys stay byte-identical** — pinned as literal digests by a test — so every
  map already on disk stays valid.

## §3 Coverage and rendering

- **`ai_coverage::to_frame` takes a value→coverage function and the outside value** in place of an
  `&AiMask`: Subject/Selection pass their Refine smoothstep, Depth passes `DepthRange::coverage`.
- **One helper, `ai_coverage::component_coverage(component, maps, lens, dm, clip)`**, is what all three
  sites call — the preview's `render_engine::BrushCache`, export's `batch_export::render`, and the
  Show-mask tint (`mask_tint`). Today each has its own `Mask::Ai` match; one helper means a fourth kind
  cannot reach one site and miss another.
- **The pipeline:** `MaskStage::source_for` maps `Mask::Depth` to `CoverageSource::Raster`, the GPU
  twin to its existing `Component::Prebuilt`. The band is applied on the CPU when the 8-bit coverage is
  built — **no new WGSL, no GPU twin**.
- **The six sites of the CLAUDE.md warning:** the CPU fold (`Composite::at`) and the GPU fold
  (`coverage_entry`) see only a raster; `capture_projection` and `defringe_projection` clone the mask,
  so the band is in their keys; `TintCache::same_shape`'s exhaustive destructure forces its choice.
- **A missing depth map covers nothing**, inverted too — `Composite::waits_for_a_map`, as for Subject.
- Depth follows Subject everywhere maps are read: the Develop preview, export, and rendered previews
  (an export job).
- **Cost:** a Near/Far drag rebuilds that component's coverage on the existing ≤1024 grid (a few ms);
  with a masked Dehaze it also re-runs that one prefix step, as a brush-masked Dehaze does today.
  Measured through `RUSTROOM_DEBUG_RENDER`, never a probe.

### The prefix fix — AI components in a mask's NR, Dehaze and Defringe
- **Today** (`pipeline/src/prefix.rs`, the masked-capture step): the step is built with no prebuilt
  coverage, so — by reading — an AI component there covers nothing. **The plan proves it with a test
  that fails on today's code before changing anything.**
- `build_prefix_steps` gains an **AI-raster input**, injected the way `lens` and `airlight` are: per
  mask and component, a source the stage resolves **at its own frame size when it runs** — the shape a
  brush already has there ("rasterise it yourself when handed none"), so no frame size is predicted.
- ⚠⚠ **The step's key carries each map's identity.** Without it, a map arriving after the checkpoint was
  cached leaves a stale picture at native zoom — the failure `capture_projection`'s own comment names.
- The masked-capture step and the defringe step both take it; export passes the same input; region
  renders (`region.rs`) the same.

## §4 The UI

- **Adding one:** the Masks add menu gains **Depth range** (`MaskKind::Depth`, an AI kind), hover
  *"Adds a mask that selects by distance from the camera"*. First use opens the existing download
  dialog (one file, 99.1 MB, Apache-2.0, its destination; Download / Cancel; a progress bar).
- **While computing:** the row reads **"Estimating depth…"**; the canvas stays live.
- **Controls:** **Near**, **Far**, **Feather** — `Edited::slider` with each field's default, so a
  double-click resets — and **Invert**, as every shape; a **Show depth map** toggle. Hover texts one
  sentence, no full stop (`every_hover_is_one_short_sentence`).
- **The picker** (lib `depth_tool`, plain types — the `crop_tool`/`mask_tool` pattern; the gesture in
  `mask_overlay` beside the Select click):
  - with a Depth component selected, a **plain left-drag** on the photo draws a thin rectangle and the
    band follows the depths inside it **live** — their 5th–95th percentile, so a stray pixel cannot
    stretch it; release is **one undo step**;
  - a **click** sets a narrow band around the depth under the pointer;
  - **no new Settings binding**: it is the component's own primary action, as painting is a brush's and
    aiming is Select's; no pan binding claims a plain left-drag (Space+drag still pans);
  - until the map arrives it does nothing, and its hover says so.
- **Show depth map** (lib `depth_view`, no egui — M10.16d's Lens Blur reuses it; bin
  `develop/canvas/depth_overlay`):
  - the map in greyscale over the photo, **near white**, placed through the geometry chain the tint
    uses, so it lines up through crop and rotation;
  - the mask's own eye-tint still draws over it — the band seen against the depths;
  - **view state, never `Edits`**; it stays on across photos until turned off, and draws while a Depth
    component is selected. Its texture is cached on the map's identity, the geometry and the frame size.
- Everything follows `docs/DESIGN.md` (its §12 checklist): no literal font size or `Color32` outside
  `theme.rs` — the greyscale pixels are data, drawn as an image.

## §5 Task 1 — the spike (the M9.13 pattern)

Spike code outside the workspace; results into this spec and the journal. On the author's M2, release
builds, on three of his photos: **a landscape with real depth, a portrait, an interior**.

1. **Does `tract` run the dynamic graph?** If not, the static 518² file; if neither — **stop and return
   to the author** rather than improvise a runtime.
2. **Load (plan build) and run time at long sides 518 / 770 / 1036**, and peak memory.
3. **Edges**: with and without the snap; stored at the inference size vs guided-upsampled to 2048 —
   magnified crops at a person's outline and a tree line.
4. **The scale**: linear disparity vs equalised, rendered side by side.

**2's default by rule:** the largest size under ~3 s a photo. **3 and 4 are the author's choices from
the crops** — photographic judgements. The chosen size, snap and scale are written here and fixed in
`depth:v1`.

## §6 Tests

Every key test is **sabotaged once**; an inert sabotage is recorded as inert, never counted.

- **`edit-model`:** `Mask::Depth` round-trips; a sidecar without it loads; the masks group; the three
  fixtures; depth and luminance share **one** band function (sabotage: let them diverge);
  `reads_a_map()` is true for exactly `Ai` and `Depth`.
- **`ai-mask`:** the new `ModelId` pinned and licensed (the existing sweep), and `ALL` complete by an
  exhaustive match; normalisation on synthetic planes — near → 0, monotone, an outlier held out by the
  percentiles; a **portrait** input comes back right side up and right way round.
- **App:** the snap narrows a soft synthetic edge onto the guide's edge (edge width measured before and
  after); **the Subject and Click keys pinned as literal digests**; the depth key moves with the recipe
  version and an active negative; `component_coverage` gives Subject today's answer and Depth its band;
  the picker's band from a rectangle (percentiles, the click's narrow band, clamping, near ≤ far);
  `depth_view` draws near as white.
- **The prefix fix:** first, a test that **fails on today's code** — a Subject-masked Dehaze changes
  nothing; then it covers, a missing map covers nothing, an inverted composite waits, and the checkpoint
  is not reused when the map changes (sabotage: drop the identity from the key).
- **Goldens:** two new references — a synthetic depth ramp with a band and an exposure offset; a Dehaze
  masked by an injected AI map. The GPU parity fixture gains a Depth component.
- **The real model:** an `#[ignore]` test in the `real_isnet_finds_a_subject` shape — on a landscape,
  the bottom rows read nearer than the top.
- **By use:** the GUI launched after the big steps, with what to look at; the milestone closes when the
  author has seen it.
