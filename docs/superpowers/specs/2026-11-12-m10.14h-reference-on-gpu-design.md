# M10.14h — the reference photo on the GPU

**Status:** the author asked for every parked item, one by one ("just start" for the series). The decisions below
are mine.

## Why

A range mask, colour mask or gating brush that carries a scene offset (Exposure, WB, Contrast or the tone regions)
selects on the **reference photo**: the globally edited photo before any mask (M10.12b2). Today
`SceneOffsetsStage` computes that reference and its coverage on the CPU. The GPU twins of that stage and of the
mask's look stage both decline, so the tail splits around two CPU stages.

Measured on 2026-11-12 with `bench_mask_reference`, an X-T4 RAF on an RTX 3060 Ti, warm GPU path:

| Rung | Same mask, no offset | Range + Exposure (reference) |
|---|---|---|
| 1600 | 2.25 ms | 26.69 ms |
| 3200 | 12.1 ms | 106.6 ms |

**Success:** the reference case stays on the GPU, roughly within 2× of the no-offset case, and renders the same
picture as the CPU path. The parity tests are the gate.

## Design

1. **`GpuSceneOffsetsStage` computes the reference.** It holds GPU twins of the reference's stages, built through
   `REPLACEABLE` from the names the CPU stage reports (`SceneOffsetsStage::reference_names`). Its encode:
   1. copies the input into a reference image (a copy kernel);
   2. runs those twins on the reference image, in the same pass;
   3. computes each reading mask's coverage from the reference into a plane per mask (a coverage kernel built
      from the same `mask_wgsl::chain`);
   4. runs the offsets kernel on the input. A reading mask's coverage comes from its plane; every other mask's is
      computed in the shader as today.
2. **A GPU coverage slot.** A `GpuCoverageSlot` holds the plane buffer and is filled at encode. The mask's look
   twin (`GpuMaskStage`) built for a mask that `takes_reference_coverage` binds that buffer as its `cov` plane and
   skips its own coverage dispatch: it seeds, runs its sub-stages and blends by the plane. The two twins find each
   other in the accelerator's walk by the CPU `CoverageSlot`'s identity (`PipelineStage::reference_slot`).
3. **All or nothing.** The reference twin is built only when every stage from the offsets stage to the last mask
   consuming its slot gets a GPU twin, so they sit in one chain and one submission. Otherwise everything falls back
   to today's CPU path. A mask twin never reads a GPU slot that nothing filled, and a CPU mask never reads a CPU
   slot that a GPU offsets stage left empty.
4. **The CPU fallback stays exact.** `SceneOffsetsStage::duplicate` works with a reference: the reference is
   rebuilt from a stored builder, and the copy keeps the same slots. The mask twin's CPU twin keeps its slot. A
   chain that fails on the GPU therefore renders today's CPU answer.

## Tests (each sabotaged once)

- GPU against CPU parity for a range mask with Exposure, a range with Exposure and Saturation (the look twin fed by
  the slot), and a colour range with Temp. Each fails on a non-finite value first and asserts that the render
  differs from the one without the mask.
- The walk builds the reference twin and the slot-fed mask twin: the tail's stage names show one chain.
- It declines as a whole when the consuming mask cannot be twinned.
- `duplicate` keeps the reference and the slots.
- Measured afterwards with `bench_mask_reference` and recorded.

## Not changing

The CPU path, gating brushes' deposit rules (a gating brush still needs its prebuilt map, as today), and prefix
stages.
