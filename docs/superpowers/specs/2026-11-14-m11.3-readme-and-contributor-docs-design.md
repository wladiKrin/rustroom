## Intent

The repository goes **public as soon as all of Phase 11 is done**. The GitHub page is the first thing
anyone sees, and today's `README.md` (103 lines) is stale — it lists import, AI masks, DNG export and
persistent history as "not there yet", and points readers at `CLAUDE.md` for status. M11.3 rewrites
it **as a product page for photographers** and adds the contributor docs beside it.

## The README — agreed with the author

**Who reads it:** photographers, mostly — Lightroom users and people tired of paying for it.
Developers second: their material sits at the bottom and in `CONTRIBUTING.md`.

**What a reader should take away within a minute** (the author's words: *"professional grade,
feature-rich (feature-complete), open source, tested"*, plus Immich, *"something that's important to me"*):

- **Professional grade** — a serious RAW editor on Lightroom Classic's model: scene-referred linear
  colour, camera profiles (DCP, checked against Adobe's DNG SDK), a GPU pipeline.
- **Feature-rich** — a short, scannable rundown in photographers' words, grouped (Library, Develop,
  masks incl. AI subject/depth, retouch incl. AI removal, HDR and panorama merge, tethering, map,
  people, print, export, publish services). Grouped lists or a compact table, never a wall of prose.
- **Open source** — the licence (GPL-3.0-or-later), no subscription, no account.
- **Tested** — stated plainly with numbers: ~4,700 automated tests, golden-image tests pinning the
  rendering, CI. ⚠ Re-count at writing time, never requote (`cargo test --workspace` totals).
- **Immich gets its own section, high on the page**: browse a self-hosted library, edit, upload
  exports back, send stars/favourites, publish albums, keys in the OS keychain — and plainly what
  Rustroom never does to your server (never deletes an asset; writes only from Send marks, export's
  upload and Publish — see CLAUDE.md's Immich invariants).

**Assume for the README** (the author, 2026-11-14): **Windows works and `v0.1` is released** — write
it as of the public launch. No "Linux first / Windows coming" hedging, no "build from source only".

**Also in it — all seven accepted by the author:**

1. **A hero image at the very top** — Develop on a strong photo with the panel open; ideally a short
   GIF (a slider drag or a mask) below it.
2. **"Your photos stay yours"** — no account, no cloud, no telemetry; every AI feature (subject masks,
   removal, denoise, people) runs locally; originals never changed. Use the start page's sentence
   verbatim where it fits: *"Your files are never changed, edits are kept separately beside them."*
3. **Coming from Lightroom** — Lightroom presets import (`lr-preset`), the familiar model (virtual
   copies, snapshots, history, the module split); and honestly what does not come across. ⚠ Verify
   before writing: as far as known Rustroom does **not** read Lightroom catalogs.
4. **Download & requirements** — links to the Releases page per OS, OS versions, the GPU
   requirement, camera support through libraw (verify the model count against the libraw version
   bundled by `rsraw` before quoting a number).
5. **Badges** — CI, licence, latest release.
6. **Credits** — the libraries and the AI models. ⚠ Some model licences REQUIRE attribution; list each
   model with its licence (IS-Net, BiRefNet_lite, MobileSAM, Depth Anything V2 Small (Apache-2.0),
   LaMa, YOLOX-m, YuNet, SFace, FFDNet, DRUNet — check each against where the app downloads it from).
7. **Where next** — report a bug, ask a question, contribute (→ `CONTRIBUTING.md`).

**Deliberately left out** (my proposal, not objected to): a feature-by-feature comparison table
against darktable / RawTherapee — it invites arguments and goes stale. One line positioning it
("Lightroom Classic's model, open source") instead.

## The screenshots — agreed with the author

The agent **takes them itself, on the Mac** (the author's call), and the author picks the final ones.
Proposed set (the author said "sounds good"):

1. **Hero:** Develop on a strong photo, panel open.
2. **Library:** the grid with the rail, a few stars and labels.
3. **Masks:** an AI Subject mask with its overlay shown.
4. **Immich:** a server album or the timeline.
5. **Map or People**, and one HDR or panorama result if there is room.
6. **A short GIF** of a slider drag, built from a burst of captures.

Files go to `docs/images/` (PNG, and the GIF), referenced from the README by relative path.

**⚠⚠ The author's constraint, verbatim in spirit: none of his own albums may be visible in any
screenshot.** The agent **may create its own temporary albums / collections / keywords / publish
services etc. to show the features, and must revert every change afterwards.** Concretely:

- **Before anything:** back up Rustroom's whole config directory on the Mac —
  `~/Library/Application Support/rustroom/` (`catalog.db`, `settings.json`, `thumbs/`, previews, looks).
  Rustroom has **no** switch for a separate profile (checked 2026-11-14: no config-dir env var;
  `dirs::config_dir()` everywhere), so a backup-and-restore is the revert. Restore it at the end and
  say so. The Immich keys live in the OS keychain, untouched by the backup — do not read them.
- **Sidecars:** edits are written beside the photos (`.json` sidecars, `stem.xmp`). Any photo the
  screenshots edit, rate or keyword: back up its sidecars first (or work on copies of the photos in a
  scratch folder) and restore afterwards.
- **Immich:** the rail lists every server album, so a shot of the Immich section would show his albums.
  Ask the author how to handle that before taking it (options: crop to a temporary album's contents,
  collapse the list, a separate demo account on the server). Anything created ON THE SERVER (an album
  for the shot, Send marks) must be undone: albums Rustroom created are removable through a publish
  service's `−` / the Immich web UI; ⛔ Rustroom never deletes an asset — do not add a way to.
- **Never visible either:** folder paths with the username, the rail's own folder list beyond the
  demo folder, people's real names (see the open questions).
- **Window size:** `RUSTROOM_DEBUG_WINDOW=1440x875` opens the window at that inner size, top left —
  use one fixed size for every shot. Capture with `screencapture -l <window-id>` (or `-R x,y,w,h`).
  Driving the GUI from a script needs Accessibility permission for the terminal (`osascript` /
  `cliclick`); the author approves that on the Mac. Run with the PKG_CONFIG_PATH line from CLAUDE.md,
  `--release`.
