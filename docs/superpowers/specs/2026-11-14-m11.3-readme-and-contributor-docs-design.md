## Intent

The repository goes **public as soon as all of Phase 11 is done**. The GitHub page is the first thing
anyone sees, and today's `README.md` (103 lines) is stale: it lists import, AI masks, DNG export and
persistent history as "not there yet", and sends readers to `CLAUDE.md` for status. M11.3 rewrites it
**as a product page for photographers** and adds the documents a contributor needs beside it. It also
prepares the repository's own text for being public: `CLAUDE.md`, written to an AI assistant and
holding the author's private working notes, is split, and the Immich server's address leaves the tree.

## Goals, non-goals, anti-goals

**Goals**
- A photographer landing on the GitHub page understands within a minute that Rustroom is
  *"professional grade, feature-rich (feature-complete), open source, tested"* (author), that it
  works with Immich (*"something that's important to me"*, author), and how to get it.
- A contributor — **a photographer who either programs or has an AI assistant make the change**
  (author) — can build Rustroom, find where a change goes, make it, and show it working.
- Nothing private is published by M11.3's files: no server address, no email, no home path, none of
  the author's albums, no people.

**Non-goals**
- Going public itself: the history rewrite, turning on Discussions, filing the starter issues — the
  last step of Phase 11 (see *Going public*). Packaging and the first release are M11.2 / M11.4's.
- A comparison table against darktable / RawTherapee (my call, not objected to: it invites arguments
  and goes stale; one positioning line instead).
- Fixing product defects found while writing — each goes to `docs/BACKLOG.md`, not into this branch.

**Anti-goals** (these would make M11.3 a failure even if every file existed)
- A screenshot showing one of the author's albums, folder names outside the demo folder, a path with
  the username, a person, or the server's address.
- The author's real catalog, settings or Immich library left changed after the screenshot session.
- A README claim nobody checked (a count requoted, a feature listed that does not work, a model
  licence guessed).

## Constraints

- **Never push; no `Co-Authored-By` trailer; branch `m11.3-docs`** (author, standing).
- **The README is written as of the public launch** (author, 2026-11-14): Windows works and `v0.1`
  is released. No "Linux first", no "build from source only", no "coming soon".
- **Numbers are measured at writing time, never requoted** — the test count from the gate run
  (`cargo test --workspace` totals), the camera count from the libraw version `rsraw` bundles.
- **Docs for photographers use photographers' words.** Developer material goes to the bottom of the
  README and into `CONTRIBUTING.md` / `ARCHITECTURE.md`.

## Part 3 — `ARCHITECTURE.md`

**A map for a photographer who programs, in photographers' terms** (my call). Starting point: the
backlog entry (`grep -n 'Contributor-facing documentation (recorded' docs/BACKLOG.md`) and
`CLAUDE.md`'s *Core architecture*.

1. **The big idea** — non-destructive: an edit is a list of settings replayed on the original;
   sidecar JSON beside the photo vs the SQLite catalog (what lives where, and why — locations and
   names in the catalog only).
2. **The picture's journey** — decode → the prefix (lens, NR, dehaze, spots, geometry — one resample)
   → the tail (white balance, exposure, tone, colour, masks, effects, sharpening, output). Why
   geometry ends the prefix, why NR is early and sharpening late. Render scale and regions (why a
   drag is fast). A diagram (Mermaid, which GitHub renders).
3. **Linear light and the working space** — one paragraph, plainly.
4. **The GPU** — CPU stages are the reference; every tail stage has a GPU twin; the parity tests.
5. **AI features** — the models run locally, downloaded on first use; maps live in decode space.
6. **The crates** — all 20 (`ls crates/` at writing time), one line each, grouped (decoding, editing,
   output, library, the app); the rule that only the app's bin modules use egui.
7. **Recipes** — "I want to add…": **a slider** (the `Edits` field with its serde attributes, its
   `EditGroups` group, `merge_from`, the three exhaustive fixtures, the stage, its GPU twin and
   `REPLACEABLE` row, the panel), **a pipeline stage**, **a mask kind** (the six coverage places),
   **a file format**. Each recipe names the tests that will fail until every step is done.

## Part 4 — `CONTRIBUTING.md` and the GitHub templates

**`CONTRIBUTING.md` is about showing a change works** (author's framing of the contributor):

1. **Before you start** — say what you want in **Discussions** (ideas) or an issue (bugs); check
   `docs/BACKLOG.md` for things already declined with numbers.
2. **Build and run** — exact commands per OS, no setup script (my call): macOS (Homebrew packages +
   the `PKG_CONFIG_PATH` line), Linux (Debian/Ubuntu `apt` and Arch `pacman` — libraw, LittleCMS,
   libheif + its HEVC plugin, libgphoto2), Windows (whatever M11.2 establishes; a marked gap until
   then). Always `--release` for real use.
3. **Working with an AI assistant** — point it at `AGENTS.md`; ask it for evidence (a test that fails
   without the change, a screenshot), not a summary; the sabotage habit in one paragraph.
4. **The checks** — fmt, clippy in its own target directory, `cargo test --workspace` filtered by
   test name, never by package; goldens (run, and how to regenerate one deliberately); the 1,000-line
   ceiling; `docs/DESIGN.md` for anything visible.
5. **Sending it** — small PRs; a screenshot or before/after for anything visible; contributions under
   the project's licence, GPL-3.0-or-later, no CLA (my call).

**Templates** (my call):
- `.github/ISSUE_TEMPLATE/bug_report.yml` — a form: Rustroom version, OS, camera / file type, what you
  did, what you saw, what you expected, a screenshot.
- `.github/ISSUE_TEMPLATE/config.yml` — blank issues off; links to Discussions for questions and ideas.
- `.github/DISCUSSION_TEMPLATE/ideas.yml` — the feature wish: what you would like, how Lightroom does
  it if it does, an example photo. (Takes effect once Discussions is on — M11.4.)
- **Questions go to GitHub Discussions, bugs to issues** (author, 2026-11-16).

## Part 5 — the README

**Who reads it:** photographers, mostly — Lightroom users and people tired of paying for it.
Developers second, at the bottom and in the two documents above. (author)

**Order on the page** (my call, from the agreed content):

1. Title and one positioning line — *Lightroom Classic's model, open source, no subscription, no
   account*.
2. **Badges** — CI, licence, latest release.
3. **Hero image**, then the **GIF** below it.
4. The one-minute pitch — **professional grade** (scene-referred linear colour, camera profiles checked
   against Adobe's DNG SDK, colour learned from your camera, a GPU pipeline), **feature-rich**, **open
   source** (GPL-3.0-or-later), **tested** (the measured test count, the golden-image tests, CI).
5. **Your photos stay yours** — no account, no cloud, no telemetry; every AI feature runs on your
   machine; originals never changed. Use the start page's sentence where it fits: *"Your files are
   never changed, edits are kept separately beside them."*
6. **Immich** — its own section, high: browse a self-hosted library and its timeline, edit, upload
   exports back, send stars and favourites, publish albums, keys in the OS keychain — and plainly
   what Rustroom never does to your server (never deletes a photo; writes only from Send marks,
   export's upload and Publish).
7. **Features**, grouped and scannable (grouped lists or a compact table, never a wall of prose):
   Library · Develop · Masks (incl. AI subject, depth) · Retouch (incl. AI removal, dust, people) ·
   HDR and panorama merge · Tethering · Map · People · Print · Export · Publish.
8. **Coming from Lightroom** — presets import; the familiar model (virtual copies, snapshots, history,
   Library/Develop); honestly what does not come across. ⚠ Verified 2026-11-16: no code reads a
   Lightroom catalog (`.lrcat`) — say so.
9. **Download and requirements** — the Releases page per OS, OS versions, the GPU requirement, camera
   support through libraw (the count measured against the bundled version). ⚠ **What a release IS is
   not decided anywhere yet** (checked 2026-11-16: no release workflow, no installer config; the vault's
   M11.2 says only "installers exist"; macOS signing is the self-signed dev identity). M11.3 does
   **not** decide packaging (my call): the section is written as of launch, without hedging, but the
   file per OS, the minimum OS versions, whether the system libraries come bundled, and signing are
   **marked spots** (`<!-- fill at v0.1: … -->`) that the going-public checklist fills.
10. **Credits** — the libraries (libraw, LittleCMS, lensfun and its database, libheif + libde265,
    libgphoto2, egui/wgpu, tract, OpenStreetMap — the map already credits "© OpenStreetMap
    contributors") and **every AI model with its licence, read from `ai_mask::registry`** (its
    `licence` / `licence_url` fields), including what it says plainly: IS-Net's weights carry no
    explicit licence; FFDNet's and DRUNet's training data is research-only.
11. **Where next** — ask in Discussions, report a bug, contribute (→ `CONTRIBUTING.md`).
12. Licence.

The current README's developer sections (build, CLI, workspace table) move into `CONTRIBUTING.md` and
`ARCHITECTURE.md`.
