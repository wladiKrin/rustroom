## Where piece 3 stands

Packaging is split by machine (the author, 2026-11-17): **3a ✅ on Windows** — the icon, the Windows installer and the
release workflow; **3b on the Mac** — the `.app` and `.dmg`; **3c here** — an AppImage. Flathub, like signing and the
other stores, stays piece 4. Read `grep -n 'piece 3a' docs/JOURNAL.md` first.

## What 3a settled, to reuse

- **The icon:** `packaging/icons/rustroom.svg` and its committed PNGs (`png/rustroom-256.png` and 512 for the desktop
  entry's `hicolor` icon). The window shows it already on X11 (`rustroom_app::app_icon`); Wayland takes the icon from
  the desktop file, matched by the app id — check what winit sets.
- **One script per package, which the release workflow only calls:** add `packaging/linux/build.sh` (like
  `packaging/windows/build.ps1`) and a `linux` job in `.github/workflows/release.yml`, its artifact added to the
  `release` job's `needs`.
- **Licences:** `cargo about generate --manifest-path crates/app/Cargo.toml packaging/about.hbs` (`about.toml` already
  lists the Linux target) plus each bundled native library's own text, as `build.ps1` gathers them.

## What Linux needs (known, not yet tried)

- ⚠ **Build on an old glibc, not on Arch:** an AppImage runs only where the glibc is at least the one it was built
  against — so the release builds it on `ubuntu-22.04` (CI, or a container locally), and Arch is where it is tried.
- **The bundle** (`linuxdeploy` + `appimagetool`, or by hand): LittleCMS, libheif with its **plugin folder** — Ubuntu
  ships the HEVC decoder as the separate `libheif-plugin-libde265`, found through `LIBHEIF_PLUGIN_PATH` — and
  libgphoto2 with its **camlibs and iolibs** (`CAMLIBS`, `IOLIBS`), all set by the AppImage's `AppRun`.
- ⚠ **Never bundle the GPU stack** — `libvulkan`, `libGL`, Mesa: wgpu must use the system's drivers.
- **A desktop file** (name, icon, categories `Graphics;Photography;`), and AppStream metadata if Flathub is near.
- **Tethering needs USB permission** (libgphoto2's udev rules), which an AppImage cannot install — say so to the user.
- **The keys:** the Secret Service through `keyring`'s pure-Rust backend, unchanged — needs a running keyring.
- **Decisions for the brainstorm:** x86_64 only or also aarch64, the app id, whether the AppImage updates itself.
