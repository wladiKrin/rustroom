# M11.4 `v0.1` — piece 3a: the icon, the Windows installer and the release workflow (design)

> **Draft, decisions taken with the author 2026-11-17** on his Windows machine. Piece 3 (packaging) is split by
> machine, the author's choice: **3a here** — the icon, the Windows installer, the release workflow with its Windows
> job; **3b on the Mac** — the `.app` and a `.dmg`; **3c on Arch** — an AppImage. Each adds its job to the workflow and
> is tried on its own system before it merges. 3a writes the briefs for 3b and 3c. Signing, notarisation and the
> stores stay piece 4.

## Why

`v0.1` is a download people install the way their system expects. Today Rustroom exists only as `cargo run`.

## What 3a found (2026-11-17, measured)

- **The binary needs no files beside it:** the fonts are `include_bytes!`, the lens database is the `lensfun` crate's
  bundled one, the AI models download on first use; every `CARGO_MANIFEST_DIR` outside a test is in a test.
- **The release exe's imports** (`dumpbin /dependents`): Windows' own DLLs plus Microsoft's C++ runtime
  (`MSVCP140`, `VCRUNTIME140`, `VCRUNTIME140_1`, the `api-ms-win-crt-*` set) — **no third-party DLL**. The exe carries
  **no resources at all**: no icon, no version information. No icon exists in the repository.
- **Every C dependency is built through `cc`** (LibRaw, LittleCMS, SQLite, `ring`) — none through CMake — so a static
  C runtime reaches all of them; libheif is vcpkg's, which has a static-runtime triplet.
- **The app takes no path on its command line**, so file associations would open nothing.

## What

1. **The icon.** Three SVG concepts in the design language's accent (`docs/DESIGN.md` §4.2), shown side by side at
   16, 32, 48 and 256 px and as a Dock tile; **the author picks or redirects** — never the builder. From the chosen
   SVG: `rustroom.ico` (16–256), `rustroom.icns` source PNGs (for 3b), 256 and 512 px PNGs (for 3c), all committed
   under `packaging/icons/`, with the SVG as the one master.
2. **The icon in the window** — the title bar, the taskbar and Alt-Tab, through eframe's viewport icon, on every
   system (macOS's Dock uses the bundle's `.icns`, 3b).
3. **The exe's own resources** (Windows): the icon and version information (product "Rustroom", the crate's version,
   the licence) through the app's existing build script, only when the target is Windows.
4. **The C++ runtime linked in** — `+crt-static` for `x86_64-pc-windows-msvc` in `.cargo/config.toml`, libheif from
   vcpkg's `x64-windows-static`: one self-contained exe for development and release alike, so the installer never runs
   Microsoft's redistributable (which would need an admin prompt). `CONTRIBUTING.md`'s triplet changes with it.
5. **The installer: per user, Inno Setup** (the author's choice) — `Rustroom-<version>-windows-x64-setup.exe`,
   installing into `%LOCALAPPDATA%\Programs\Rustroom` with **no admin prompt**, a Start-menu entry, an optional desktop
   shortcut (off by default), an uninstaller in Settings → Apps. ONE `AppId`, fixed forever (upgrades find the old
   install by it). **Uninstalling never touches the catalog, previews or settings** (`%LOCALAPPDATA%\rustroom`,
   `%APPDATA%\rustroom`). The licence is shown as information, not a click-to-accept (GPL needs no acceptance).
6. **The licences that travel with the binary:** `LICENSE` (GPL-3.0-or-later) and a third-party list — every Rust
   crate's licence (generated by `cargo-about`, as MIT and Apache-2.0 require for a binary) and the native libraries'
   and fonts' (LibRaw, libheif, libde265, LittleCMS, Inter, Phosphor) — installed beside the exe. 3b and 3c reuse it.
7. **The release workflow** (`.github/workflows/release.yml`): on a `v*` tag, build the installer on `windows-latest`
   and open a **draft** GitHub release with it and a `SHA256SUMS`; the author publishes. ⚠ The tag must equal the
   app's version (`v0.1.0` = `0.1.0`), or the workflow fails before building. A manual run (`workflow_dispatch`)
   builds the same artifacts without a release, to try the workflow without tagging. 3b and 3c add their jobs.
8. **Docs:** the README's Windows download row (the file, "Windows 10 or 11, 64-bit"); `CONTRIBUTING.md` (the static
   triplet; building the installer locally); the briefs for 3b and 3c; the journal and backlog.

## Known costs

- Unsigned: SmartScreen says "Windows protected your PC" (More info → Run anyway) until piece 4 signs it.
- The static triplet is one more vcpkg build of libheif (~1.5 min) on every Windows machine and CI run.
- The release workflow cannot run here: its first real run is the author's push of a tag (or a manual run).
- The `AppId` is permanent: a mistake there orphans every earlier install.
