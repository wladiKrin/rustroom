# M11.4 `v0.1` — piece 2: Windows (design)

> **Draft, decisions taken with the author 2026-11-17** on his Windows machine (Windows 11, i5-13400F, RTX 3060 Ti,
> 16 GB). Piece 2 of four: (1) ✅ the version in About and more RAW formats, (2) Windows, (3) packaging, (4) signing
> and stores. From the brief `2026-11-17-v0.1-windows-brief.md`.

## Why

Nothing had been built or run on Windows. The goal of this piece: Rustroom builds, passes the gate and runs on Windows,
the author tries it, and a CI job keeps it building (the Linux build was once broken for four weeks unseen).

## What the first build found (2026-11-17, measured)

- **Toolchain:** Rust stable (1.100) through rustup, Visual Studio 2022 Build Tools (C++ workload, Windows 11 SDK),
  LLVM 23 (libclang, for `rsraw-sys`'s bindgen), CMake, and vcpkg in classic mode.
- ⚠ **`rsraw-sys` 0.1.1 refuses MSVC on purpose** — its build script is `panic!("MSVC is not supported")`. LibRaw
  itself compiles with MSVC: removing the panic and passing `-pthread` only to non-MSVC compilers is the whole fix,
  tried through `cargo --config patch…` with nothing in the repo. Bindgen then also emits the CRT's `memcmp`,
  `memcpy`, `memmove`, `memset` and `strlen`, which rustc warns about.
- **libheif comes from vcpkg on MSVC, unconditionally** — `libheif-sys` ignores pkg-config and `embedded-libheif`
  there. `libheif[core,libde265]:x64-windows-static-md`: the decoder only (the port's default adds x265, a GPL-2 HEVC
  *encoder* Rustroom never uses), static with the dynamic CRT, the triplet the `vcpkg` crate picks by default — no
  DLL to ship. 1.3 min to build.
- **LittleCMS needs nothing:** `lcms2-sys` compiles its bundled copy when pkg-config finds none.
- **libgphoto2** has no Windows build here; with the camera feature off, everything else compiles: debug workspace
  green, the release app in 6 min 10 s at `-j 4`, and it starts.
- ⚠ **On this machine, not in the code:** no page file, so the commit limit is the 15.8 GB of RAM and a 16-job build
  failed with `link.exe` out of memory (LNK1102) and allocation crashes — builds here run `-j 4` until the author
  turns one on. Git for Windows' `core.autocrlf=true` checked 1,297 files out as CRLF (none is committed so).

## What

1. **`rsraw-sys` vendored** at `vendor/rsraw-sys` (0.1.1 as published, LibRaw included, 1.9 MB) through
   `[patch.crates-io]`, with the smallest patch that builds on MSVC: no panic, `-pthread` only off MSVC, the five CRT
   functions blocklisted in bindgen. Identical behaviour on macOS and Linux. A `README` there says what changed and
   why; an upstream PR is the author's to open, and retires the copy when released.
2. **Tethering on Windows: shown, says unavailable.** `tether`'s `gphoto2` dependency becomes `cfg(not(windows))`
   and its code `all(feature = "gphoto2", not(windows))`, so a plain `cargo run --release -p app` builds on Windows
   with no feature flags. File → Tethered capture… stays; on Windows it says tethering is not available on Windows.
3. **Big data in Local AppData on Windows.** The catalog, thumbnails and previews move from `%APPDATA%` (Roaming) to
   `%LOCALAPPDATA%\rustroom` through ONE function (macOS and Linux keep `config_dir()`, unchanged); the AI models
   from `data_dir()` to `data_local_dir()` (the same folder on macOS and Linux). Settings, presets, export presets,
   looks, learned camera looks and watermarks stay in Roaming; the caches are in Local already (`cache_dir()`). No
   migration — there is no Windows user yet.
4. **No console window.** The app is a GUI program on Windows (`windows_subsystem = "windows"`), and attaches to the
   console of the terminal it was started from, so `cargo run` still shows the `RUSTROOM_DEBUG_*` output.
5. **Platform words.** "Show in Finder" (two places) reads "Show in Explorer" on Windows and "Show in file manager"
   on Linux, decided in `reveal.rs`; a sweep of the UI text for other Mac-only words.
6. **Names Windows refuses.** Where a typed name becomes a file or folder (`safe_name::folder_name` for the import's
   subfolder; batch rename and export names), `< > " | ? *`, a trailing dot or space and the device names (`CON`,
   `NUL`, `COM1`…) are made safe too.
7. **Line endings:** a `.gitattributes` with `* text=auto eol=lf`, so every Windows checkout is the Mac's byte for
   byte; this checkout renormalised.
8. **The gate green on Windows** — `cargo fmt`, clippy (`CARGO_TARGET_DIR=target/clippy`), `cargo test --workspace`
   and the goldens, the GPU tests on the RTX 3060 Ti (the backend wgpu picks recorded). Each failure is fixed where
   it is wrong: in the test when it assumed Unix (a `/tmp` or `/Users/…` literal, a file still open at a `TempDir`'s
   drop), in the code when Windows shows a real bug — and the report says which.
9. **CI: a `windows-latest` job, clippy (all targets) and `cargo build`** — LLVM and vcpkg come with the runner image,
   libheif installed as above. Format stays on the Linux job; tests stay local on Windows.
10. **Docs:** `CONTRIBUTING.md`'s Windows steps from what worked, `AGENTS.md`'s rules where they changed (the vendored
    crate, the cfg-gated tethering), the journal, `docs/BACKLOG.md` (M11.2) and the README's platform line.

## Known costs

- The repo carries LibRaw's source (1.9 MB); a new `rsraw-sys` release is taken by hand, diffed against `vendor/`.
- A Windows contributor installs about 8 GB of tools (Build Tools, LLVM, vcpkg) — the usual price on Windows.
- Windows does not colour-manage the window: the preview is shown as sRGB, as on Linux today.
- Printing to a printer is CUPS: on Windows Print saves a PDF only, as the README already says.
- The Immich keys in Windows Credential Manager (`keyring`'s default backend) are checked by use, not by a test —
  `SettingsStore::new(path)`, every test's, never reaches the store.
